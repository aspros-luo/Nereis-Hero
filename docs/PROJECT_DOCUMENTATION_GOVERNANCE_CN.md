# 项目文档治理与任务启动合同

> 状态：生效中
> 适用分支：`feature/story-map-progression`
> 目的：避免设计、对话上下文、源码和验收记录之间发生漂移。

## 1. 权威层级

发生冲突时，不以“离源码最近”或“文件最近修改”为唯一判断依据，按以下顺序裁定：

1. 用户明确确认的最新设计决策与长期硬约束。
2. 本文件与 `DEVELOPMENT_WORKING_CHARTER_CN_EN.md` 中的工程约束。
3. 区域当前设计基线 / 决策记录：记录已批准的目标行为、路线、入口、出口和明确废止的方案。
4. 实现状态与验收合同：记录源码实际行为、尚缺事项和验证步骤；不能自行改变设计目标。
5. 开发日志、旧草案和历史审计：提供历史原因，不自动代表当前目标。

源码是“当前实现是什么”的证据，不是“设计应该是什么”的裁定依据。Canva 是视觉/空间设计依据，但必须将其空间关系转成明确的实现合同；不能把 Canva 中尚未决定的门槛或跨区端点擅自当作已批准事实。

## 2. 每次任务开始前的必读流程

每个新任务、切换区域或恢复中断工作时，先完成并记录：

- [ ] 确认目标分支与最新提交；不得把工作写入 `main` 或擅自新建分支。
- [ ] 读取本合同、开发协作条约和项目状态/索引。
- [ ] 读取当前区域的权威设计基线、最新 Canva 设计及相关验收合同。
- [ ] 读取相关场景、脚本、资源、拓扑数据和验证器。
- [ ] 检查文档之间、文档与源码之间的冲突。
- [ ] 输出简短的“设计目标 / 当前实现 / 差异 / 风险 / 本次范围”记录，再开始修改。

不要求每次机械地读完整个仓库所有文档；要求先读全局规则，再读与任务相关的完整来源，并用索引/引用审计找出冲突。不能因上下文中似乎记得某项决策而跳过仓库核对。

## 3. 每次修改后的同步义务

任何影响项目行为或决策的代码、场景、配置、资源、拓扑数据变更，都必须在同一任务中同步更新相关文档：

- 设计变更：更新当前设计基线，说明变更原因、影响范围及未改变的合同。
- 实现变更：更新实现记录，准确说明改了哪些文件、行为与限制。
- 新增约束：更新本合同或开发协作条约，并链接到受影响的区域合同。
- 验收变化：更新验收清单和状态，分别记录静态检查、脚本执行、Godot 实机测试；未运行不得标成通过。
- 退役文件：更新索引/引用，并说明替代文件和退役原因。

如果实现与文档同步无法在本次完成，应停止继续扩张功能，先补齐文档；不得把文档同步留成“以后再做”的无期限事项。

## 4. 旧文档与仓库清理

- 先盘点、再判断、最后删除；禁止只凭文件名、年龄或“搜索不到直接引用”认定文件无用。
- 对每个候选文件检查静态引用、`res://` 路径、`preload/load`、`.tscn/.tres` 依赖、动态路径、自动加载、验证器、README/文档链接及存档兼容风险。
- 有价值但过期的方案优先标记为 `SUPERSEDED` 并链接到替代文件；只有在历史信息已迁移且无有效依赖时才删除。
- 不为减少文件数而删除独立验收证据、有效的设计理由或仍被工具使用的脚本。
- 清理清单必须记录：路径、判定、证据、风险、处置结果和验证结果。无法证明安全的文件保留并标注待审。

## 5. 正反方评审与暂停条件

重要设计/架构变更必须记录：

1. 正方：预期收益及解决的问题。
2. 反方：维护成本、反例、兼容风险、玩法风险。
3. 裁定：采纳、修改后采纳、暂缓或拒绝。
4. 验收条件：能证实结果的可复现检查。

发现设计冲突、关键依据缺失、可能造成软锁/存档丢失/跨区合同破坏，或验证器与实际设计不一致时，暂停受影响的修改并报告证据。不要为迎合提议而略过风险；也不要因低风险细节反复要求用户确认已批准的事项。

## 7. A2 任务完成定义

每个房间分别记录设计、场景实现、连接、静态验证和实机验证。区域层面必须验证：

- A1 → R01 出生点与返回方向正确。
- R01 的地面主路、树冠上行路和钟墓下行路均可辨认且有实际碰撞路线。
- R01–R06 的房间连接有明确出口、目标房间、入口标记、落点、方向、单/双向语义及返回规则。
- C03/C04/H02 的跨区端点、解锁与持久状态未被内部房间重构破坏。
- 下坠路线有可读的着陆区和可用回程，除非设计明确规定为单向落差。
- 所有关键地形节点在 Godot 编辑器中可见可编辑。
- 验收报告明确区分静态检查与 Godot 4.6.1 实机验证。

## 8. Git 与交付约束

- 直接使用既有 `feature/story-map-progression` 分支；不修改 `main`，不新建分支。
- 不触发 GitHub Actions；不创建专门的测试提交。
- 每次交付报告：变更文件、设计裁定、验证命令/结果、未验证范围、下一步。
- 只在已核实实际文件和提交结果后声称已完成；不能把计划、Canva 文本或静态计数描述成运行时事实。
