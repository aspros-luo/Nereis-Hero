# A0 编辑器布局与交互距离审计

## 目的

A0 的固定场景目前主要由 `scripts/levels/escape_prologue.gd` 在运行时创建，因此原始 `scenes/escape_prologue.tscn` 只有根节点，Godot 2D 编辑器里看不到完整关卡。脚本已增加安全的编辑器预览和碰撞/交互范围参考线，编辑器预览不会创建 Hero、敌人、HUD，也不会修改 WorldState。

## 当前布局坐标（世界坐标）

| 对象 | 位置 / 尺寸 | 判定方式 |
| --- | --- | --- |
| 地面 | y=540；碰撞矩形高 40，中心 y=560 | 物理碰撞 |
| 手术台 | 碰撞中心 (280,500)，180×12 | 物理碰撞；美术由 SVG 绘制 |
| Hero 初始位置/检查点 | (420,540) | 胶囊半径 18、高 48 |
| 休整点 | (420,540) | 必须落地；横向距离 ≤90、高差 ≤32 |
| 绷带 | (460,492) | 距离 ≤100；没有物理碰撞体 |
| 手术托盘调查点 | (620,520) | 距离 ≤120；没有物理碰撞体 |
| 手术记录 | (740,450) | 距离 ≤100；没有物理碰撞体 |
| 出口交互区 | 中心 (2040,470)，110×140 | Area2D 物理触发区 |
| 维护平台 | 见 `SURGICAL_CATWALK_RECTS` | 物理碰撞 |

## 审计发现

1. **Hero 与休整点完全重合**：二者坐标都是 (420,540)。这不是物理碰撞冲突，但会造成角色和凳子美术重叠，且开场即满足休整点的横向/高度条件（落地后）。
2. **绷带不具备物理碰撞体**：拾取逻辑采用 100px 距离检测；当前坐标 (460,492) 位于地面上方 48px，需在编辑器预览中确认它是否确实摆在手术台或其他可见承托物上，而不是悬空。
3. **调查点和拾取物的距离检测范围会重叠**：交互焦点管理器会从当前可交互对象中选最近对象，并在 28px 平局范围内考虑优先级。范围重叠本身不等于输入冲突，但要检查角色站位是否会出现提示跳动或不易选中的情况。
4. **手术台物理碰撞与美术分离**：碰撞矩形是脚本创建的，手术台外观来自 SVG。二者并非同一可编辑节点，因此需要用预览参考线对照美术边缘。
5. **编辑器参考线只是可视化辅助，不是额外碰撞体**：青色矩形表示物理碰撞参考；黄色圆表示调查交互距离；绿色圆表示拾取距离；红色标记表示 Hero/初始检查点；橙色矩形表示出口 Area2D。

## 验收建议

- 在 Godot 2D 编辑器中打开 `scenes/escape_prologue.tscn`，确认背景和参考线可见。
- 检查 Hero 与休整点是否重叠、绷带是否悬空，以及调查点/物品提示范围是否易于区分。
- 运行游戏后验证同一布局；编辑器参考线不应在运行画面中显示。
- 本次只提交编辑器预览与审计说明；尚未声称完成 Godot 实机运行验证。正式将固定几何迁移为可独立选择的场景节点，仍可作为后续维护性改造。
