## 1. 源码审计结论

### A0 室内：教会手术所

- 场景由 `scenes/escape_prologue.tscn` 挂接 `scripts/levels/escape_prologue.gd`，主要几何、角色、闸门、拾取物和出口由脚本动态生成。
- 已接入原创 `assets/art/backdrops/surgery_ward_backdrop.svg` 与 `surgery_floor_strip.svg`，但 `_draw()` 仍叠加大量矩形、线段和纯色块；部分大块遮挡/简化形状与背景插画的绘制感不一致。
- 手术台、托盘、架子、闸门等仍以程序化几何表现。它们的位置与碰撞由不同函数维护，视觉替换必须以“仅替换绘制，不改物理坐标”为第一约束。
- 地面有独立碰撞体和维护高路碰撞体；背景素材不得承载碰撞或被误认为可站立平台。

### A0 洞外：山路与悬崖

- `scripts/levels/prologue_exterior.gd` 的背景原先完全由多边形和线条绘制，缺少与室内统一的绘制感素材。
- 已新增原创 `assets/art/backdrops/prologue_cliff_backdrop.svg`，并接入背景绘制。保留现有洞口、道路边线、河谷波纹、崖边碎石和执行者逻辑。
- 本次只替换天空/山脊的底层背景；`CLIFF_X`、`FLOOR_Y`、地面碰撞、执行者生成点、必败计时和救援转场不应因美术调整而改变。

### 共用资源现状

- `assets/art/backdrops/` 已有教会、手术室、村庄、森林、废墟、异象和地面条带 SVG。
- `assets/backgrounds/` 已有灰烬之路底图与远景雾、中景修道院、前景荆棘层；`scripts/core/world.gd` 已有视差绘制案例可供参考。
- `assets/characters/hero/` 当前仅发现资源说明文件；主角正式分件贴图/逐帧动画仍未形成完整资源包。现有骨骼/程序化角色应继续作为可运行回退。
- 外部素材候选清单不等于已下载或已获授权；不得把像素风角色直接混入当前手绘风格，也不得直接打包商业游戏拆包素材。

## 2. 分阶段实施顺序

### Phase A0-Art-1：场景底图（当前阶段）

- [x] 为 A0 洞外增加项目原创绘制感背景，并接入现有脚本。
- [x] 保持碰撞、出生点、门锁、遭遇与存档逻辑不变。
- [ ] 在 Godot 4.6.1 实机确认 SVG 导入、缩放、图层顺序、相机边界和前景可读性。
- [ ] 对比室内背景，调整两处场景的暗部/冷光/锈红比例，避免洞外比室内更抢眼。

### Phase A0-Art-2：室内道具去几何占位

- 优先替换手术台、托盘、悬挂灯具、玻璃实验舱前景细节、损坏栏杆和两道安全闸门的视觉层。
- 先建立独立视觉节点或绘制资源映射，再替换 `_draw()` 中的临时矩形；不移动对应交互节点、碰撞体和触发区域。
- 门锁的开/关状态继续由当前战斗进度控制；美术只响应状态，不参与解锁判定。
- 物品名称/描述不新增“线索”等分类标签。

### Phase A0-Art-3：洞外前景与坠崖提示

- 增加可重复使用的岩壁/碎石/草根/侵蚀石板视觉素材，前景与背景分层。
- 悬崖边缘需要明显但不夸张的轮廓；不得用视觉遮挡隐藏实际落差或碰撞边界。
- 救援演出、落水反馈属于后续表现工作，不在本轮为了美术而改变流程。

### Phase A0-Art-4：模块化地面与 TileSet

- 先定义地面顶边、直线段、内外角、断裂边、墙侧面、平台边缘、遮挡前景的模块规格。
- 将视觉 TileSet 与碰撞 TileSet 分离；平台碰撞形状以既有灰盒合同为准，素材接入后再逐段验证。
- 不在本轮一次性把全地图 A0–A13 全部迁移到新 TileSet。

### Phase A0-Art-5：分件骨骼角色与敌人

- 主角优先：头部/发型、躯干、上臂/前臂、手、腿、鞋、剑；统一脚底基线、骨骼枢轴和武器握持点。
- 实验守卫和教会执行者分别建立独立视觉资源，不共享导致轮廓同质化的整套角色图。
- 先验证待机、移动、攻击、受击、死亡，再替换正式场景；碰撞胶囊与攻击判定仍由既有逻辑控制。

## 3. 素材接入规则

1. 新素材先进入可审查的资源路径；记录来源 URL、作者、许可、署名要求、修改内容和使用场景。
2. 授权不明时只作视觉参考，不进入可分发构建。
3. SVG/PNG 必须在 1280×720 实际游玩缩放下检查，确认不会压住主角、敌人攻击前摇、拾取物和门交互提示。
4. 背景、装饰前景、角色、碰撞与交互区域分离；任何视觉节点都不得暗中创建或改变碰撞。
5. 保留旧绘制/灰盒回退，直到新素材在 Godot 中运行验收。
6. 不用新增 UI 标签直接告知玩家某物品是线索；叙事依靠物件本身和描述呈现。
7. 不以静态源码检查替代 Godot 运行验收；不声称尚未运行的 SVG 导入和画面表现已通过。
