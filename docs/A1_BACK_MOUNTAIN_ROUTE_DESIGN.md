# A1 后山攀登路线设计（提案）

> 状态：设计提案，尚未进入场景实现。  
> 分支：development  
> 目标：把 A0 坠崖事件、二段跳、金正的救命之恩、火焰抗性斗篷、隐藏神职人员遭遇和山顶飞龙整合成一条有回报、有分支且不制造主线软锁的探索路线。

## 1. 设计结论

采用「二段跳负责垂直探索，火焰抗性斗篷负责火焰路线，既有神识/共鸣感知能力负责发现隐藏封印」的分工。

暂不引入抓钩。抓钩不仅是一个移动动作，还会带来锚点布置、空中状态、动画、碰撞与失败恢复等系统成本；如果后续没有大量可复用的抓钩玩法，不值得为一条后山路线单独建立系统。

## 2. 地图结构：多峰环山，而非单线爬塔

参考《黑暗之魂 II》前往龙祭坛的空间感，但不照搬它的路线形态：本作有二段跳，因此地形既要保留山体尺度、悬空感和危险的交通连接，也要让跳跃成为路线选择的一部分。整体建议采用「多座山峰 + 吊桥 + 环山栈道 + 少量垂直踏板」的组合。玩家总体向上，但路线可以横向绕行、跨峰、回环，再逐步汇向龙峰。

### 建议的区域骨架

1. **山脚林线**：从 A1 后山入口进入，先通过有承托的山路和短平台认识地形。鹰类与杀人蜂在较宽的落脚区出现，避免一开始就用强击退把玩家打下悬崖。
2. **第一道断谷与吊桥**：以长吊桥连接两座山体。桥面本身不应只是平地走廊：可安排破损段、桥下可见的深谷，以及敌人从侧面或下方接近的预警。桥梁提供紧张感，但不要把连续高难跳跃和空中敌人同时塞进同一个狭窄屏幕。
3. **环山旧道**：沿山体外缘绕行，使用短平台、岩架、废弃瞭望台和局部洞穴形成路线节奏。环道应让玩家看见先前经过的桥、下层山路或远处龙峰，建立清晰的空间记忆，而不是靠重复背景制造长度。
4. **第二座山峰与高位踏板**：这里才逐步提高二段跳的使用频率。用少量高低错落的踏板连接环道与上层岩架；每次关键跳跃都应有清楚的起跳面、落脚面和失败后的可恢复路线。二段跳用于缩短绕路或取得高位捷径，不应成为整张地图唯一的通行手段。
5. **上层火山岩与分岔**：约四分之三高度设置通往隐藏神职人员支线的侧路。主路继续向龙峰延伸，隐藏支线则通过火焰路与封印门进入独立遭遇区域。
6. **龙峰**：以较开阔、可读的战斗场地承接飞龙 Boss。建议让玩家在抵达前短暂看见龙影、听见远处咆哮或观察喷火照亮山壁，先建立期待，再进入战斗。

### 拓扑原则

- **主路可读**：即使玩家不擅长精确跳跃，也能沿吊桥、环山路和较宽平台持续推进；二段跳提供优势与探索，不是每一步都强制使用的门槛。
- **有意义的回环**：至少考虑一处从高位开启、能回到较低山路或检查点附近的捷径。它必须真正缩短回程，不能只是视觉上像捷径。
- **跨峰有辨识度**：每座山峰应有不同轮廓或地标；用吊桥、栈道、垂直岩壁区分路线，不要让玩家迷失在重复的平台堆里。
- **坠落风险公平**：关键跳跃前应有视觉提示和可辨认的落脚点；高风险落差用于选择与紧张感，而不是隐藏碰撞或不可见的即死坑。
- **敌人与移动分层**：强击退飞行敌人不放在必须完成高精度跳跃的狭窄桥段；精英敌人应有稳定战斗空间。
- **地图规模先克制**：先做能形成完整闭环体验的多峰骨架，不为营造宏大感无止境延长路线。空间感来自视线、地标和路线关系，不单靠地图长度。

山顶连接哪个 A 主线区域仍为开放决策，不在本提案中擅自指定。

## 3. 火焰斗篷：获取与效果

### 获取叙事

斗篷来自独立地图中的金正救援事件：主角救下金正的性命后，金正主动赠予斗篷。该地图的地点、任务细节和事件顺序暂不定义，避免与尚未确定的其他地图设计冲突。

### 功能边界

- 斗篷是一个有明确叙事来源的关键道具，不额外建立装备栏或耐久系统。
- 按现有物品/世界状态架构实现被动效果；只有在确认现有系统无法承载时，才新增最小范围的状态逻辑。
- 对火焰伤害进行减免，不提供免疫，不免除灼烧区域的危险。
- **平衡初值建议：火焰伤害降低 40%**，这只是首轮原型参数，必须通过实战测试再决定。
- 飞龙喷火仍需闪避或寻找安全窗口；斗篷的作用是降低失误成本，不是让玩家站着吃火。
- 火焰路径应采用有节奏的伤害判定和可读的危险提示，不能用无预警的连续伤害把玩家瞬间磨死。

## 4. 隐藏神职人员分支：第二条件提案

### 建议方案：斗篷通过火路，神识/共鸣感知发现封印

把隐藏分支做成一条可选的高风险支线，而不是主线通行门：

1. 在后山约四分之三高度，主攀登路线旁出现一条被火焰封住的狭窄侧路。
2. 没有火焰抗性斗篷时，火路风险过高，玩家应能识别并暂时放弃；不能让它成为通往山顶的唯一道路。
3. 获得斗篷后，玩家可以穿越火路，抵达看似普通的岩壁/旧祭坛。
4. **第二个条件建议使用项目已有的神识/共鸣感知能力（resonance_sight）**：玩家必须先解锁该能力，再主动开启感知，才能辨认岩壁上的隐藏封印并与其交互，揭开通往神职人员遭遇的入口。现有世界状态会在场景切换时关闭感知，因此隐藏门的开启结果必须持久化，不能只依赖感知开启状态。
5. 若玩家尚未获得该能力，给出环境线索即可，不应显示直白的“缺少某物”任务清单；玩家可以先离开，继续登顶，日后再回来。
6. 隐藏门开启后应保持持久状态，具体使用现有世界状态标记，不另造平行的解锁系统。

### 为什么推荐它

- 两个条件各司其职：斗篷解决「能否承受火焰」，感知能力解决「能否发现隐藏封印」，避免同一道具既负责抗火又负责识别所有秘密。
- 复用现有能力，控制开发成本，不需要抓钩、专用钥匙或新的解谜系统。
- 隐藏分支是可选内容，不会让主线因为玩家尚未取得某个能力而软锁。
- 与游戏强调环境叙事、隐藏路线和不把所有信息直接写在 UI 上的方向一致。

### 需要保留的风险与验证

- 代码审查已确认项目存在数据驱动的 resonance_sight 解锁记录，也存在独立的临时感知开启状态；场景切换会关闭感知。仍必须核实该能力在玩家可到达后山时是否已可获得，以及它是否会与现有隐藏目标规则冲突。如果获取时间过晚或用途已被其他机制占满，就不应强行使用它；替代方案是一个在既有探索中获得的祭司印记/遗物，但不应为了本门额外制造一整条收集任务。
- 不能把「未获得感知能力」设计成看起来像 bug 的完全无反馈墙面。应通过风声、焦黑符号、重复的教会纹样等环境线索提示这里存在异常，但不直接暴露入口。
- 这是一项设计提案，不代表仓库中已经存在对应场景或逻辑。

## 5. 敌人与战斗节奏

- 鹰类、杀人蜂：负责空中骚扰，攻击前摇必须清晰，避免玩家在窄平台上被连续击退坠崖。
- 狮鹫类：建议作为中后段的精英威胁，不要在同一屏里同时安排多个强击退飞行敌人。
- 飞龙：峰顶 Boss。火焰攻击要有可识别的蓄力、覆盖范围和躲避窗口；斗篷减伤不替代攻击机制。
- 神职人员 Boss：隐藏支线的独立遭遇。可检查现有 high_priest.gd 是否适合作为复用基础，但在确认人物身份与战斗设计前，不直接认定两者是同一 Boss，也不把已有 Boss 脚本强行绑定到此门。

## 6. 关键流程与失败情况

- 未获得斗篷：可以继续攀登并挑战飞龙；火焰侧路暂不可安全通过。
- 有斗篷、无感知能力：可以穿越火路，发现环境异常，但暂时无法揭开封印；主线仍可继续。
- 有斗篷、有感知能力：可以揭开隐藏门并挑战神职人员。
- 飞龙战失败：按现有检查点/死亡恢复系统返回，不新增专用复活机制。
- 隐藏 Boss 战失败：不得把玩家送回火路另一侧的危险触发区；重生点和门口触发范围需单独审计。

## 7. 实施前验收清单

- [ ] 查清 A0 坠崖点与后山入口的空间/叙事呼应，不把二者误做成同一场景的简单反向出口。
- [ ] 核实二段跳的获取时点和后山最高必要跳跃距离，不能假设所有玩家进入时都已有二段跳。
- [ ] 核实 resonance_sight 的实际解锁条件、现有用途与状态持久化方式。
- [ ] 核实库存道具的效果接入点，避免新增独立装备系统。
- [ ] 设计火路的进入、退出、重生落点与伤害判定边界。
- [ ] 确认隐藏门开启后可持久复用，死亡/离场不会意外重锁。
- [ ] 为飞龙与神职人员遭遇分别设置战斗空间，不在狭窄攀登平台上直接复用 Boss 战斗场地。
- [ ] 山顶通往哪个 A 主线区域：待地图整体拓扑审计后决定。
- [ ] 完成场景后执行连接拓扑、出生点/门触发区、死亡恢复和完整可达路线测试；未实际运行的测试不得标记为通过。

## 8. 当前不做的事

- 不引入抓钩系统。
- 不提前指定金正救援地图的地理位置和剧情细节。
- 不把神职人员隐藏门设为通往飞龙或后续主线的唯一道路。
- 不把斗篷设计成火焰免疫。
- 不在尚未审计现有能力和库存系统前，新增平行的钥匙、装备栏或任务标记体系。
