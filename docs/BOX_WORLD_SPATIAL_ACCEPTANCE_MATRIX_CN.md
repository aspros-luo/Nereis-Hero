## 3. 所有地图通用的验收合同

每条连接都必须分别检查以下层次，不得互相替代：

1. **拓扑层**：连接 ID、源区域、目标区域、开启条件、方向与回程定义一致。
2. **场景层**：实体门、碰撞形状、平台高度、出生点与拓扑锚点一致。
3. **交互层**：门在正确位置显示交互；角色站在错误高度或错误一侧时不能误触。
4. **状态层**：解锁状态跨场景持久化；死亡、读档和重复进入不会错误重置。
5. **体验层**：主路可辨识；可选路线有风险、奖励、捷径或叙事价值；不为了制造箱庭而堆砌无意义碰撞墙。
6. **实机层**：用 Godot 4.6.x 实际移动、跳跃、交互、切图、死亡与回程验证。静态脚本通过不能标记为实机通过。

## 4. 灵视隐藏区域状态分离

H01–H08 必须分别核对以下状态，不能用单个布尔值代替所有阶段：

- 未发现
- 已感知异常
- 入口已显现 / 已开启
- 已进入
- 奖励或环境证据已取得
- 已解锁的回程 / 捷径状态

尤其要检查：从主地图和隐藏地图的不同入口进入时，状态是否一致；离开后是否仍可返回；是否存在一次性奖励重复领取；入口与普通门是否抢占 E 交互。

H09 仍是临时候选区，不计入正式地图验收，也不能成为任何结局的硬性前置。

## 5. 与 Nereis Lullaby 的共享世界观同步

两个项目共享世界事实，但玩法、视角与信息揭露节奏独立。每次剧情改动都要标记事实状态：

### 已确认方向
- 蜜忒的纯真与情感是真实的；她并不以人类的自觉方式理解自己与外神的关系。
- 教会、王国信仰体系、古神遗留力量与外神影响是不同层次，不能压扁成简单的善恶阵营。
- 村民有独立生活、关系和动机；参与异常不代表每个人都知道仪式真相。
- Hero 视角与蜜忒视角可以掌握不同信息；玩家知道的事不自动等于角色知道。
- 两个游戏不必复述同一场景，但不能互相矛盾。

### 提案 / 待解决
- 仪式中心位于村庄、森林或两者之间的具体结构。
- 村民集体成为邪教徒并保护蜜忒的事件是否发生、何时发生、属于何种结局。
- Hero 与蜜忒的后续命运、跨游戏因果链、复国军是否腐化。
- H09 的遗物、实验体与剧情关联。
- 三个结局的最终触发条件和完整因果链，凡未经用户明确认可的内容都不得当作最终设定。
