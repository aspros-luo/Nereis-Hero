# 地图优先开发路线与完成标准（中文）

> 本文是《蜜忒之歌-英雄》当前开发顺序的执行基准。优先完成地图空间、探索节奏与环境叙事；非阻断性 Bug 集中登记，地图内容达到验收节点后再统一回归。
>
> **地图类型的最高原则：** [箱庭式互联世界地图设计原则](./INTERCONNECTED_BOX_WORLD_DESIGN_CN.md)。M1–M5 是开发施工阶段，不是玩家必须按顺序通关的线性章节。

## 一、开发裁定

**当前策略：地图与剧情优先，基础阻断问题例外。**

- 立即修复：启动失败、主角无法移动、主线地图无法进入、关键出口无法离开、进度无法保存导致地图无法继续。
- 暂缓集中处理：不影响当前内容制作的 UI 小瑕疵、非主线路径碰撞边缘问题、表现层问题。记录复现步骤，不在每个小问题上中断地图制作。
- 不把“场景文件存在 / 静态连接成立”当成地图完成。地图完成必须包含可辨认的空间、可走通的路径、探索动机、区域叙事与入口 / 出口闭环。

## 二、地图完成的定义

每个主要区域至少要具备：

1. **空间结构**：能看出入口、主路线、垂直层次或地形变化、支路和回程关系；不能只是一条没有空间记忆点的长走廊。
2. **地标识别**：至少一个能从远处识别、在回访时帮助定位的主地标。
3. **探索节奏**：安全观察段、移动 / 跳跃挑战、可选支路或捷径中的至少两种；难度与角色当前能力匹配。
4. **环境叙事**：至少两处不依赖长对话的故事信息，例如被搬走的器具、错误年代的建筑、尸体摆放、教会封存痕迹、与其他区域呼应的声音或符号。
5. **路线闭环**：入口、出口、返回路径、远端捷径和检查点位置有明确目的；不能让隐藏区提前跳过主线关键事件。
6. **可选内容**：重要异常来源、隐藏入口、奖励或可调查物有明确位置与触发理由。
7. **验收记录**：静态检查与 Godot 实机走图分别记录；未实测的内容不得标为通过。

以上是“可玩灰盒完成”标准，不要求此阶段就完成最终美术、全部动画或最终敌人平衡。

## 三、地图制作顺序

### M1 — 箱庭网络的首个可玩切片（当前优先）

先把 `A0 → A1 → A2 → A3 → A5 → A6 → A7 → A8 → A9 → A10 → A12` 作为一条可靠的主线验收路径打通，但**这不是玩家唯一或强制的通关顺序**。玩家抵达 A1 后，应逐渐能选择多个方向探索、记住暂时封闭的路线，并在获得能力 / 道具 / 机关状态 / 鸣响后回访。

第一优先切片是 A1、A2、A3、A4：验证至少两个可选择的探索方向、一条真正缩短回程的回环、一个从另一侧开启的捷径，以及一处鸣响揭示旧地图新路线的内容。A0 现增加不绕过守卫锁的手术维护高路；A1 具有地面聚落、村庄屋顶高路、炉火休整点和 A1→A3 旧排水替代方向；A2–A12 每区增加一处区域休整点，H01–H08 保持无免费休整点的风险定位。之后再按区域批次扩展 A5–A8 与 A9–A12。A3、A4、A8、A9 作为高连接度枢纽，必须有可记忆的分层 / 分岔，不应只依靠门口标签区分路线。

### A1 水闸回程出生点避开相邻 POI

- A4 水闸回村原本将主角放在 x=1900，距复国军营 POI x=1990 只有 90px；村庄 POI 的交互半径为 110px，因此刚切图就会显示不相关的 E 交互。
- 出生点改为 x=1850，距酒馆 x=1730 为 120px、距复国军营 x=1990 为 140px，并远离村庄井门。验证器增加了对应契约，防止交互提示再次在回程落点自动出现。

### 连接审计修正：C05 路线标记只在真实经过 A3 时记录

- 发现 A4 的 `_ready()` 无论从哪条支路进入都会记录 `reached_A4_via_A3`，可能让玩家从监牢或王墓进入旧水库后，错误获得 H01 远侧井门。
- 已移除 A4 场景加载时的无条件记录。现在只有 A3 的下水道门实际触发切图时才记录 C05 路线；A4 的 H01 远侧门仍要求该持久标记。
- 静态验证器新增检查，防止以后在 A4 初始化时再次伪造路线进度。
- 验证器现逐一检查 H01–H08 的双向出口与远侧开门条件，尤其防止隐藏地图的回程捷径在对应主地图门尚未开启时提前生效。

### 连接审计修正：C24 城区侧也遵守村庄防卫门槛

- 发现 A1 侧的旧排水通道要求完成村庄防卫，但 A3 侧的「返回村庄」门此前始终生成，导致拓扑数据与实体出口的开放条件不一致。
- 现在 A3 侧回程门也只有在 `village_defense_survived` 已记录后才生成；正常流程不变，同时堵住旧存档、调试出生或未来入口调整造成的提前绕行。
- 静态验证器已增加 C24 双端门槛检查。Godot 实机切图与碰撞仍需运行时验证。

### 本轮连接审计修正：C10 钟塔落差不再依赖 H05

- 审计发现 A6 的 C10「钟塔落差」出口被 WorldState.is_hidden_path_opened("H05") 包在条件分支内。这让一个应从修道院开启的实体捷径，意外依赖玩家是否发现可选隐藏区 H05。
- 已将 C10 出口改为独立生成：首次互动记录 opened_bell_tower_drop 并开门，后续互动可返回 A3；A3 的反向门仍由同一标记控制。H05 继续保留自身鸣响条件，不再作为 C10 的前置。
- 静态验证器新增针对 A6 出口块的契约检查，防止未来再次把 C10 嵌入 H05 条件。
- 同时将 A3 内 H05 回程门从 x=1830 移至 x=1950，与 C10 的 x=1710 门拉开距离；即使两条路线都已开启，也避免两个 E 交互区域挤在一起。
- A4 的 H01 远侧井门从 x=2495 移至 x=2510，与 C06 水闸门 x=2350 的交互触发范围拉开间隔；回到 A4 时仍沿用原出生点，不会落在水闸门内。
- A9 的 H03 旧服务门从 x=1020 移至 x=1250，避开 x=900 的 C18 内城回程门，并与休整点和 R07 调查点保留空间；从 H03 回程时出生点改为 x=1600，避免落在入口触发区内。
- 同时将 C16 旧升降机返回 A9 的出生点从 x=1450 调整到 x=1600，避免主角落地即进入 R07 调查点 105px 的交互范围。
- C04 从战场返回 A2 时，出生点由 x=1950 移至 x=1750，与 A2 的 x=1880 回程门拉开 130px，避免刚进图就再次触发捷径门。
- 这是代码与验证规则已更新；当前环境仍无法启动 Godot，因此场景切换、门交互与回程距离尚未实机验收。

### M2 — 中层区域空间扩展、隐藏区域与捷径

当前灰盒已为 A0 增加手术维护高路、A1 增加村庄屋顶线；A2–A12 保留地面主路并各有区域专属的上层 / 支路结构；H01–H08 也各有独立的内部路线和一处不免费增加属性的环境证据。A5、A7、A10、A12 另补入官方战史、囚犯转移、双重封印圣物与国王未寄出的信。下一步不再单纯堆平台，而是回到箱庭核心：逐条对照 C01–C24 检查门、反向开锁、出生侧和回程是否与拓扑一致，优先修正真正缺失的远端捷径 / 连接闭环，再补全区域检查点与环境奖励。所有新增内容在 Godot 实机验收前仍是代码已写入、待用户验收。

依次完成 H01–H08、C15 / C19 与所有远端捷径：

- 先完成显现线索、入口、区域内部探索和安全返回。
- 再完成远端出口；远端出口必须等玩家从主线抵达对侧后才能打开。
- H06 / H08 的证据链、H07 的外神共鸣条件与 H08 的结局出口保持现有设计，不为方便测试而削弱正式条件。
- F5 Debug 仅用于验证路线；正式条件仍需在内容完成后单独验收。

### M3 — 环境叙事与区域身份

每区围绕一个核心问题安排视觉信息，不用大量解释性对白替代探索：

| 区域 | 玩家应逐步感受到的核心问题 |
|---|---|
| A2 雾林与钟墓 | 为什么钟声先于钟锤，旧朝圣路又在等待谁？ |
| A3 废弃城区 | 第三条街是被遗忘，还是被刻意从现实中删除？ |
| A4 下水道与水库 | 教会的排水设施为什么建在更古老的石殿里？ |
| A5 旧战场 | 王国的信仰胜利留下了什么被官方史书抹去的代价？ |
| A6 修道院与钟塔 | 修道院是在守护信仰，还是在执行一项长期实验？ |
| A7 监牢与维护竖井 | 哪些囚犯被登记为罪人，哪些只是研究材料？ |
| A8 旧王墓 | 王室姓名被抹去，是为了掩盖什么继承事实？ |
| A9 王城外环 | 城市表面秩序与被废弃的居民生活为何同时存在？ |
| A10 大圣堂 | 教会如何把古神力量伪装成正统信仰？ |
| A11 深层研究区 | 教会究竟发现了什么，又误认了什么？ |
| A12 王室内城 | 国王是腐败的共谋者、失控的统治者，还是明知真相却拒绝倒下的人？ |
| H01–H08 | 每个隐藏区揭示一条主世界无法直接提供的反常证据，而不是重复战斗。 |

### M4 — 遭遇与奖励布置

地图路线稳定后，再根据视线、空间宽度、垂直落差与回程距离放置敌人、精英遭遇、Boss、升级材料与剧情奖励。避免把敌人平均撒在整条路上；每次遭遇都应利用该区域独有的地形或叙事。

Boss 与三种结局继续遵守既有剧情：凡人之墓、永恒乐园、烈火天罚。此阶段不擅自改写结局条件。

### M5 — 全图验收

先逐区，再按全图顺序：

1. 从新游戏开始走通普通主线，不使用 Debug。
2. 检查 A4 支路、所有远端捷径与返回闭环。
3. 使用 F5 + V 逐个检查 H01–H08 的显现 / 开门 / 进入 / 返回；另用正式条件验证门槛。
4. 检查 C15 / C19、R08 事件顺序、H08 前置证据与可选结局出口。
5. 检查死亡回程、存档 / Continue、平台碰撞与交互焦点。
6. 汇总阻断问题与非阻断问题，再进入集中 Bug 修复。

## 四、当前真实状态

- A0–A12 与 H01–H08 已有不同程度的场景 / 灰盒代码接线；A13 仍是终局层抽象节点，不是独立可玩区域。
- 当前通用灰盒已有区域地标、平台和异常调查点，但**尚不能据此认定每区已达到空间内容完成标准**。接下来应优先扩展区域内部的分层、可选路线、环境叙事锚点与遭遇位置，而不是继续堆叠非阻断性修复。
- 本文只定义制作顺序与验收门槛；实际完成度必须由代码 / 场景审查和 Godot 实机结果共同更新。

## 五、验收节点由开发过程决定

不按固定日历日期宣布完成。满足以下条件才进入下一节点：

- **主线空间节点**：普通主线从 A0 连续走到 A12，区域之间的视觉身份与空间节奏明显不同。
- **隐藏地图节点**：H01–H08 均可进入、探索并返回；捷径不破坏主线顺序。
- **地图内容节点**：主线和隐藏区都有环境叙事锚点、探索奖励 / 异常证据与合理遭遇布局。
- **实机验收节点**：Godot 4.6.x 中完成无 Debug 的主线走图与 Debug 辅助的隐藏区回归，并记录未通过项。

地图内容节点之前，除阻断问题外，非关键 Bug 不应反复打断内容制作。
