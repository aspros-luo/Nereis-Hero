# Nereis-Hero 并行开发分支约定（中文）

> 本文是主角系统与剧情地图两条并行工作线的长期交接入口。新聊天应先读取本文，再读取目标分支的当前代码与相关文档；不得仅凭旧聊天摘要猜测代码状态。

## 1. 固定唤醒词

### 主角工作线
**唤醒词：Hero 分支唤醒**

- 仓库：aspros-luo/Nereis-Hero
- 工作分支：feature/hero-animation-system
- 集成基线：development
- 工作重点：主角骨骼、角色视觉、动画状态与动作表现、受击/硬直/力竭/坠落/死亡/起身、角色动作与现有战斗系统的安全接入。
- 入口文档：docs/PHASE_S1_2_2_STICKMAN_PROTOTYPE.md、docs/RENDERING_DRAW_AUDIT.md，以及相关正式角色控制器和场景。
- 核心约束：scripts/player/hero.gd 仍是正式玩法逻辑的权威来源。骨骼/视觉控制器只负责表现，不得私自复制或接管移动、碰撞、伤害、体力、无敌帧、武器判定等玩法规则。先审计现状，再小步修改；保留可回退路径，直到用户本地 Godot 验收通过。

### 剧情与地图工作线
**唤醒词：剧情地图分支唤醒**

- 仓库：aspros-luo/Nereis-Hero
- 工作分支：feature/story-map-progression
- 集成基线：development
- 工作重点：A0 手术所、关卡与地图拓扑、门和转场、出生点/死亡恢复、洞外骑士遭遇、追兵逼近、坠崖、蜜忒救援、村庄及后续路线。
- 核心约束：优先保证完整连通的实际游玩流程，不能只通过拓扑数据验证就宣称地图完成；检查真实场景、碰撞承托、触发区域、双向/单向门条件与恢复出生点。
- 剧情演出可以请求主角播放动作，但不得在剧情分支内复制一套主角骨骼/动画系统。若需要新增动作，先定义并与主角分支协商稳定接口；接口未就绪时可用现有动作或明确标注的临时占位方案推进。

## 2. 分支结构与操作规则

- development 是集成基线；两条工作线分别在自己的功能分支上推进。
- 禁止修改 main。
- 不创建测试提交；正常功能提交可以创建。
- 不要把主角动画系统与剧情/地图代码无差别地混在同一工作分支。
- 修改前必须读取目标分支最新代码和相关文档，并确认分支确实存在、当前文件内容与预期一致。
- GitHub API 修改现有文件时，先读取该目标分支上的文件并使用刚读取到的 blob SHA；按文件顺序逐个写入，避免并行覆盖同一文件。
- 合并前检查两条分支的共同接口与文件冲突。阶段性成果通过审查后再合并到 development，不自动合并、不直接覆盖另一条工作线。
- 若当前会话无法访问 GitHub 或无法确认写权限，必须明确报告，不可声称已读取或写入。

## 3. 主角与剧情之间的接口约定

主角分支负责主角动作的实现与命名；剧情地图分支负责演出时间轴、镜头、环境和流程。剧情控制器只通过公开接口驱动主角，不直接修改骨骼内部节点或重写角色玩法逻辑。

可考虑的演出动作语义包括：受击踉跄、力竭/跪地、回头、失足、坠落、死亡/倒地、起身。以上是接口需求方向，不表示这些动作或方法当前已经全部实现。新增接口前必须先审计正式 Hero 控制器、现有骨骼视觉控制器和场景结构，再确定具体方法、动作打断规则、演出结束后的控制权恢复方式。

演出系统需要明确：
1. 谁拥有角色移动控制权；
2. 动画能否被伤害、死亡或场景切换打断；
3. 演出结束时如何恢复输入和物理状态；
4. 失败、胜利两种剧情分支如何复用共同演出流程；
5. 镜头与角色移动如何配合，避免只对角色进行瞬间定位或无表现的直线平移。

## 4. 新聊天启动步骤

收到对应唤醒词后：
1. 先确认用户当前指定的仓库和分支，不把另一条工作线的分支当作目标。
2. 读取本文对应工作线的最新分支状态，并查阅入口文档、相关脚本、场景和最近提交。
3. 从实际代码中判断已实现、未实现、存在风险的内容；不能把旧对话中的计划误当作当前代码事实。
4. 给出简洁的当前状态与下一项具体工作，然后直接推进，不要只重复开发计划。
5. 需要本地 Godot 运行验收时，明确区分源码审查、静态检查与用户本地运行结果。GitHub 连接不能启动用户的本地 Godot，因此不得虚报运行测试通过。
6. 若用户指出的当前任务与旧摘要不一致，以目标分支当前代码和用户最新明确指令为准；有冲突时先说明再处理。

## 5. 当前已确认的架构方向

- 主角骨骼/动画完善与剧情地图推进是两条独立工作线。
- 剧情演出优先采用实机角色、动作时间轴、镜头与环境配合，而非默认制作独立预渲染 CG。
- 当前骨骼原型和正式角色视觉接入有各自的历史实现；不可假定独立的 stickman_hero.tscn 已经可以整体替代正式 Hero 控制器。
- A0 与洞外坠崖演出应重视节奏：战斗收束、受击/力竭、追兵逼近、角色反应、失足/坠落、救援转场应有可读的动作和停顿，而非过快完成或单纯平移。
- 用户负责本地 Godot 4.6.1 的实机验收；提交说明要列出变更、检查范围和仍需本地验证的事项。
