## 1. 审查结论

**宏观区域图静态连通，但完整游戏地图尚未通过 Godot 实机验证。**

静态遍历以 A0–A13 为 14 个主要区域节点，按当前连接表可从 A0 到达全部节点；规划连接共 24 条，未发现孤立区域。A2–A12 主路线灰盒以及 H01–H08 隐藏子区均已有程序化场景 / 入口代码接线。C15 / C19 分别从 A8 / A10 进入 A11，H08 终局出口也已接线。但碰撞、平台跳跃、交互焦点、存档恢复、死亡回程与场景切换尚未通过 Godot 实机验收。

## 2. 现有灵视系统与状态

- `WorldState.hero_resonance`：内部 0–100 鸣响值。
- `ancient_exposure` / `outer_exposure`：区分古神残留与外神影响的接触值。
- `resonance_sight_active` 与 `resonance_sight` 能力。
- `scripts/systems/resonance_hidden_target.gd`：根据鸣响、接触值及灵视激活状态显现隐藏目标。
- 当前灵视窗口约 4.5 秒，消耗 10 点体力，冷却 6 秒。
- `scripts/world/resonance_secret_gate.gd`：统一处理临时显现、E 开启、E 进入与永久开门存档。
- WorldState 已有发现 / 开启 / 进入三类持久状态；旧存档缺少新增字段时默认恢复为空集合。
- `scripts/world/resonance_source_clue.gd` 已支持来源 ID 已记录、但旧存档缺失能力解锁或最低鸣响 / 接触值时的修复交互。

## 3. 地图设计的四条硬规则

1. **显现不等于开启。** 灵视只是短暂揭示异常；玩家必须接近并调查，才能固定开启入口。
2. **入口开启必须永久保存。** 灵视结束、鸣响下降、死亡、切图与重新读档都不能关闭已开启的门。
3. **隐藏区出口不得破坏主线进程。** 通往后期区域的远端门可以保持锁闭，直到玩家从正常主线抵达对侧。
4. **鸣响让人看见更多，不保证理解真相。** 环境线索应先于入口存在；异常可以矛盾，但不能造成像碰撞错误一样的不可读性。

- **主路线与隐藏入口接线：已提交静态实现。** A2–A12、H01–H08，以及 C15 / C19 均有场景、门槛与继续游戏映射。
