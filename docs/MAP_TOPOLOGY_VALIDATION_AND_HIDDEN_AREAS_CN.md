# 地图拓扑验证与灵视隐藏区域（索引 / 汇总）

> 当前设计基准：development 分支  
> 本文保留为地图审查入口；详细区划、隐藏地图和 SVG 总图分别维护，避免多份文档的区域编号、门槛和名称互相冲突。

## 1. 审查结论

**宏观区域图静态连通，但完整游戏地图尚未通过 Godot 实机验证。**

静态遍历以 A0–A13 为 14 个主要区域节点，按当前连接表可从 A0 到达全部节点；规划连接共 23 条，未发现孤立区域。A2–A12 和 H01 / H07 已有程序化灰盒场景及初版代码接线，但碰撞、平台跳跃、交互焦点、存档恢复与场景切换尚未通过 Godot 实机验收。

## 2. 现有灵视系统与缺口

仓库已有以下实现基础：

- WorldState.hero_resonance：内部 0–100 鸣响值。
- ancient_exposure / outer_exposure：古神残留与外神影响的接触值。
- resonance_sight_active 和 resonance_sight 能力。
- scripts/systems/resonance_hidden_target.gd：可依鸣响、接触值及灵视激活状态显现隐藏目标。
- 当前灵视窗口约 4.5 秒，消耗 10 点体力，冷却 6 秒。

现有 `resonance_hidden_target.gd` 仍负责通用显现目标；新增的 `resonance_secret_gate.gd` 为 H01 提供 E 调查、永久开启记录、进入隐藏场景及存档恢复调用。WorldState 已有发现 / 开启 / 进入三类状态，旧存档缺少字段时默认为空集合。H01 / H07 与 A2–A12 已代码接线，但仍待 Godot 实机测试；H02–H06 / H08 尚未逐一实例化。

## 3. 地图设计的四条硬规则

1. **显现不等于开启。** 灵视只是短暂揭示异常；玩家必须接近并调查，才能固定开启入口。
2. **入口开启必须永久保存。** 灵视结束、鸣响下降、死亡、切图与重新读档都不能关闭已开启的门。
3. **隐藏区出口不得破坏主线进程。** 通往后期区域的远端门可以保持锁闭，直到玩家从正常主线抵达对侧。
4. **鸣响让人看见更多，不保证理解真相。** 环境线索应先于入口存在；异常可以矛盾，但不能造成像碰撞错误一样的不可读性。
