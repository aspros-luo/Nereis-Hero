## 3. 灵视 / 鸣响机制的源码审查

已检查的关键实现：

- `scripts/systems/resonance_hidden_target.gd` 有 `required_resonance`、`required_ancient_exposure`、`required_outer_exposure` 门槛，可显隐一个 `CanvasItem` 视觉节点并绘制异常标记。
- `scripts/core/world_state.gd` 用 `resonance_hidden_targets` 分组刷新目标，并保存鸣响值与古神 / 外神接触值。
- `scripts/player/hero.gd` 将 V 绑定为灵视输入。当前设计值为约 4.5 秒、消耗 10 体力、冷却约 6 秒；需要已经解锁 `resonance_sight`，开发调试覆盖除外。
- 场景切换和输入锁定会关闭当前灵视；进入新场景要重新扫描。
- 当前存档里有鸣响 / 接触值，但没有专门保存每个隐藏入口是否已开启的通用 ID 集合。

### 当前缺口

1. **显现不等于开门。** 现有组件显现视觉目标，没有通用的交互解锁、碰撞开关或进入隐藏区域逻辑。
2. **开启必须永久保存。** 灵视结束、死亡、换场景或读档不应让已经打开的门重新封闭。
3. **不能只看数值。** 深层地图应同时要求曾经发现过某些前置异常，避免玩家纯刷鸣响就打开所有入口。
4. **存档需兼容旧版本。** 新增隐藏地图状态要写入保存、读取与 reset；旧存档没有新字段时应默认为空集合。
5. **新地图需支持续玩。** 隐藏地图若使用独立场景，必须在恢复场景流程中登记它，或保存进入前地图与返回出口；不应读档时跳回村庄或序章。
6. **要核实鸣响增长来源。** 阈值使用的是实际内部值。落地每一区前需要确认正常剧情通过什么事件提升鸣响 / 接触值，以及玩家最早何时能达到门槛，不能假设数值自动增长。

## 4. 隐藏区域统一交互流程

```text
未察觉：异常以环境细节存在，不能直接看见完整入口
  → 使用 V 灵视，且达到该入口门槛
短暂显形：在当前灵视窗口内看见异常轮廓 / 纹理 / 声源
  → 靠近并按 E 与异常发生共鸣
永久开启：保存稳定 secret_id，门 / 通道 / 入口状态打开
  → 进入隐藏子区划；通过明确出口返回主地图
```

设计要求：

- 每个入口使用固定的 `secret_id`，不能用节点名称临时生成。
- 需要在异常显形时完成 E 交互；仅仅看见不算开门。
- 开门后不再要求玩家一直保持高鸣响或反复施展灵视。
- 成功开启时用声音、材质扭曲或短促视觉反馈；不出现“真结局地图已解锁”式的清单通知。
- 每个隐藏区域都有可理解的退出路线；鸣响下降、灵视结束或玩家死亡都不能让其困在内部。
- 隐藏入口可以提供捷径，但不能使玩家绕过尚未完成的主线进程门槛。
- 不新增主角移动技能；隐藏地图复用现有跳跃、冲刺、攀墙、钩爪和灵视。

### 后续需要的通用组件

建议增加一个薄层入口组件，例如 `scripts/world/resonance_secret_gate.gd`，复用现有灵视目标而不是重写整个状态系统。组件需要支持：`secret_id`、三类数值门槛、可选前置线索 ID、灵视期间的交互、开门视觉 / 碰撞变化、持久化 API、目标区域与返回出口，以及调试日志。

`WorldState` 需要提供类似 `is_secret_gate_unlocked(secret_id)` / `unlock_secret_gate(secret_id)` 的接口，将开门 ID 写入存档；实际命名可按代码风格调整。

## 5. 隐藏地图提案

门槛范围以内部 0–100 的隐藏数值为起点，**不是已测平衡值**。需要等真实鸣响增长曲线与灵视解锁时机确认后再校准。门槛顺序为“鸣响 / 古神接触 / 外神接触”。

| ID / 区域 | 前置地图的特异地方 | 起始门槛 | 内容与连接 |
|---|---|---|---|
| H01 **A2 无名祷坑** | 钟墓一块碑的阴影方向与钟声来源矛盾；灵视时石缝显现向下的轮廓 | 18 / 2 / 0 | 微型区，约 3–5 个房间节点。找到旧钟舌和不完整证词；从墓园进入、由地下钟室或墓园下层返回。可复用现有村庄墓园原型 |
| H02 **A3 被抹去的市街** | 旧礼拜堂壁画少了一条街道，透视结构却暗示门框仍在 | 28 / 3 / 0 | 小型区，约 3–5 个节点。住宅被搬空、门牌被刮除、征用痕迹互相矛盾；从礼拜堂进入、出口回旧市场，不得越过 A5 主线门 |
| H03 **A4 逆流水库** | 静水倒影里的台阶与实体方向相反；灵视时显出闸门手柄 | 32 / 5 / 0 | 中小型区，约 4–6 个节点。倒流水位与旧石层；进入并回到旧水库。可以看到王墓外廊，但不能提前通入王墓主区域 |
| H04 **A6 无声钟室** | 钟塔阴影里出现没有钟声的窗口；灵视时显现窗框与攀爬点 | 38 / 6 / 0 | 中型支区，约 4–6 个节点。垂直探索、旧钟机构与教会改造痕迹；由修道院一侧开启回城区高路，不可反向绕过 A5 进入 A6 |
| H05 **A8 王名抹除廊** | 王墓铭文中的空白并非磨损；灵视能看出被磨掉的字形 | 45 / 10 / 0，且记录至少 2 个不同前置异常 ID | 中型支区，约 4–7 个节点。王室名字、被替换的棺椁标记与矛盾年代证据；另一端回王室地下道，不一次讲完王国历史 |
| H06 **A9 镜街：雨幕背后** | 积水中的街区与现实不一致；高外神接触后能看到反射里的门 | 52 / 0 / 8 | 小型异象区，约 2–4 个节点。昔日街道残影、移动地标与可选挑战；入口和出口都留在 A9，不能借它越过 A10 |
| H07 **A11 胎宫 / 原初空腔** | 深层研究墙面像在呼吸；不同时刻的灵视呈现不同轮廓 | 65 / 15 / 18，且记录至少 3 个不同前置异常 / 共鸣来源 | 大型隐藏区，约 6–10 个节点。教会研究之前的古老结构与互不完全吻合的起源证据；有独立返回路线，丰富终局理解，但不单独决定结局 |

### 内容规模

- H01、H02：短探索，让玩家早期学会“旧地图还有第二层”的语言。
- H03、H04、H05：中型秘密区，分别强调空间反转、垂直路线和历史证据。
- H06：视觉 / 认知异象，不扩大成第二座完整城市。
- H07：大型隐藏地图，承担深层探索和终局认知。
- 普通主线可以完全错过所有隐藏地图。真结局的证据继续分散于不同地点，不强制玩家打卡 H01–H07 全部区域。

## 6. 修订后的进程门槛

### A4 → A8：王墓外廊

早期可看见、听见，但不可直接进入 A8 主体。深层入口由 A7 王室竖井或正式主线状态开放，避免绕过 A5–A7。

### A3 → A9：旧升降井

早期可从 A3 看到或听到升降井运作，但无法从 A3 提前进入 A9。玩家第一次从 A8 抵达 A9 后，从内侧解锁，之后成为双向捷径。

### A9 → A4：王城排水门

仅在玩家已抵达 A9 后，从 A9 内侧开启；这是返回地下网络的捷径，不是从 A4 早期闯入王城的入口。

### A6 → A3：钟塔捷径

只能由钟塔远侧开启。发现 H04 不能绕过 A5 主线；隐藏门入口与出口的进程锁需要分别验证。

以下项目**尚未执行 Godot 实测**，进入灰盒制作后逐一验收。

| 编号 | 测试步骤 | 通过标准 |

## 8. 下一阶段执行顺序

1. 盘点并保留现有 A0 / A1 场景；先制作 A2 的最小野外灰盒、A3 的主要环路、A4 的回水闸与村庄旧井出口。
2. 在真实灰盒中测试第一条环路的视线、跳跃距离、落差与失败回程。
3. 先实现一个通用入口组件，只验证 H01：低值不显形、高值灵视显形、E 开门、开门状态读档保留。
4. H01 通过后再制作 H02–H07，避免七套互不相干的开门逻辑。
5. 做 A5–A6 验证中层环路，再继续 A7–A12。
6. 记录正常流程里的鸣响 / 接触来源与达标时间，之后才能合理校准隐藏入口门槛。
7. 只有在 Godot 4.6.x 完成 MAP-01–MAP-14 的可玩测试后，才能把实际地图验证标记为通过。
