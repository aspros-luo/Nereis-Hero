## 1. A1 的设计定位

A1「边境村庄」不是一次性新手村、任务大厅或必须先打完一场战斗才能离开的剧情走廊。

它应是玩家反复返回的**生活与信息枢纽**，同时承担：

1. **生存缓冲**：主角在 A0 逃脱后获得一个暂时安全、能休息和整理物品的地方。
2. **人物关系**：玩家通过短暂交谈、共同生活、错过相遇和回访，认识蜜忒与村民；关系不显示为数值条。
3. **信息交叉口**：居民只分享自己有理由知道的局部信息，玩家把传闻、物品、环境和其他地图的证据拼在一起。
4. **世界路线分流**：北侧旧朝圣路通往 A2；旧排水通道通往 A3。路线开放条件必须与地图总账和事件因果一致。
5. **状态回响点**：玩家离开并从 A2–A13 或隐藏区返回后，人物位置、对话、物品、营地与环境应根据世界状态发生有原因的变化。
6. **低声量叙事**：以物品、装备、环境痕迹、行动后果和有限对话为主；不使用长篇旁白替玩家解释。

设计参照是 Dark Souls 的篝火据点 / Hollow Knight 的 Dirtmouth 式枢纽：安全感、人物记忆和路线意义随探索逐步改变，而不是持续派发任务。

## 2. 不可被实现覆盖的叙事原则

- NPC 首先是独立生活的人，其次才与玩家的路径发生交集。
- NPC 不应普遍主动发布任务；他们可谈论野兽、井水、征兵告示、外来者、物资和个人处境，但只知道自己能知道的部分。
- 主角保持沉默，不用内心独白替玩家总结真相。
- 蜜忒的早期善意、好奇、生活习惯与对主角的情感都是真实的；早期不主动揭示她与外神的联系，她本人也不以“阴谋策划者”自居。
- 玩家可以比主角更早推断异常；推断不等于角色本人知晓。
- NPC 的故事要跨区域发展。A1 是人物状态汇合点，不是每个人物故事的起点和终点。
- 错过人物相遇可以有情绪后果，但不得被做成明显的“恋爱任务失败提示”。
- 不把线索做成直接标明“这是结局线索”的标签。玩家首先应把它理解为物件、记录或生活痕迹。
- 不为了填满村庄而强行加入没有独立动机的 NPC、道具或支线。

## 3. A1 基础流程（设计目标，不等于当前实现）

### A1-0：初次抵达

- A0 结束后，主角在蜜忒家中醒来。
- 先用伤口包扎、换下的湿衣服、餐桌上的两个位置和屋外安静的村庄，表达“有人救了你”，不在开场讲完整背景。
- 玩家通过手动交互离开房间进入村庄；门口不能自动触发、反复传送或持续显示不可用的交互提示。
- 初次进入房间是一次性的叙事入口。以后从村庄回到 A1，必须根据真实连接落在对应门口，不可总被送回蜜忒房间。

### A1-1：自由观察与相识

- 玩家可以先看村庄、物品、建筑和 NPC，不要求先接受一条显式任务。
- 蜜忒的互动通过具体相处事实累积，而不是“好感度 +N”。
- 其他村民以自己的生活问题和有限信息回应主角。
- 初次探索应留下几个可疑但不互相解释的细节，例如旧钟与墓地、井水 / 老石构、征兵或军队痕迹、教会记录、酒馆里的歌声。每条信息都要有来源，不应全部来自一个全知 NPC。

### A1-2：周边威胁与路线开放（事件性质待裁定）

- 当前地图代码将“村庄防卫幸存”作为 A2 北门和 A3 旧排水通道的共同解锁条件。
- 该设计与 A1 作为自由探索枢纽存在张力：玩家目前触发北门交互就会进入自动攻击章节；A3 入口也被同一旗标锁住。
- **基线不直接删除村庄防卫，也不继续强化强制战斗。** 在事件性质被确定前，把它标记为“现有原型门槛、设计待裁定”。
- 待裁定后只能选择与整体叙事一致的一种因果结构：必经的村庄危机、可选/可延后的危机，或世界状态推进事件。无论哪一种，都必须明确玩家是否可以先探索、是否能返回、失败如何处理，以及 C02 / C24 的门槛是否需要同步调整。

### A1-3：离开、回访与后果

- A2、A3 及之后的区域应通过物品、人物经历、路线发现或事件后果反过来改变 A1。
- 同一个 NPC 不应仅根据全局的 `selected_route` 或 `humanity_state` 机械切换成另一段不相关的台词；应优先使用其自身经历、玩家实际发现的证据、时间 / 事件标记和关系事实。
- 回访变化可以很小：少了一件工具、营地的火灭了、NPC 不在原位、某人开始使用新说法、桌上多了一封未寄出的信。变化必须可追溯到事件因果。
- 蜜忒缺席可以作为关系断裂的安静后果，但具体触发时机与她是否离开村庄，须由统一人物状态设计决定，不能仅靠某次任意地点交互来判定。

## 4. 核心 NPC 基线台账

下表把“角色方向已确认”和“具体事件仍开放”分开。它不是完整对白稿。

| 人物 / 角色 | 已确认的人物核心 | A1 的职责 | 跨地图联系方向 | 当前审计判断 |
|---|---|---|---|---|
| 蜜忒 | 善良、活泼、好奇；喜欢烹饪、甜点、分享食物并养猫；早期不理解外神真相；与主角的感情真实 | 救助后的日常、共同生活、可错过的相遇与关系事实 | 食材与偏远区域、村民 / 外来者的关系、后期共鸣与玩家已发现的异常 | 已有交互与房间，但当前关系推进、缺席状态和剧情触发分散，需统一状态合同 |
| 金正 | 利益优先的机会主义者；会交易、帮助或伤害他人，不默认是隐藏好人 | 主动交易；Boss 材料换短刃的事件落点；商品与情报流 | 短刃的来历；交易信息可能流向教会，并间接关联复国军小兵之死 | 当前“旅行商人”是否就是金正尚未由代码证明；不得静默合并身份 |
| 朝圣骑士 | 真诚的理想主义者，持续前往王都朝圣，有个人承诺；可能迷路、休息、再出发 | **不应固定常驻 A1**；最多在其旅程合理经过时出现 | A2 首个森林 Boss 协助；在不同区域 / 隐藏区重逢；信仰逐步受现实冲击 | 当前 A1 脚本未见其独立旅程状态；应按地图事件设计，不作为普通村民生成 |
| 铁匠 | 有独立手艺、资源限制与生活，不是单纯装备菜单 | 修复、材料限制、村庄生活和战争需求的可见入口 | 金正的货物交易；复国军小兵偶尔帮忙打铁；后续服务受事件影响 | 当前 A1 生成逻辑未见完整铁匠人物与状态 |
| 老婆婆 | 有生活经验、传闻和有限记忆；不是全知讲解员 | 休息后给多个探索方向，信息来自她的生活经验 | 可能知道不同地区的旧事；与小兵有搬运日常；线索指向 A2–A13 而非单线任务 | 当前 A1 生成逻辑未见该核心人物 |
| 猎人候选 / 荒野居民 | 职业尚未冻结；对森林、野兽、食物和道路的知识来自实际经验且有盲区 | 提供野兽与荒野生计的局部观察 | A2 森林、食材、周边道路和后续生态变化 | 当前旧设计中的“老猎人”与最新人物弧线中的“猎人候选”需统一；不擅自冻结职业或身份 |
| 休息 / 指引 NPC | 身份、信仰和服务机制仍开放；不能只是篝火拟人化 | 服务随村庄逐渐接纳主角而开放 | 与村庄安全、休息含义、后续人物判断有关 | 当前有炉火休整点，但不能把功能节点直接视为已完成人物 |
| 复国军小兵 | 普通勤恳士兵；与蜜忒关系不错，喜欢甜点；帮铁匠和老婆婆做事，曾与朝圣骑士喝酒；不只是死亡工具 | 通过日常劳动、交往和营地痕迹建立存在感 | 金正 → 信息流向教会 → 小兵之死的因果链；尸体、装备、物品和不同人物反应分散呈现 | 当前只有复国军营地 POI 固定描述，尚不足以体现独立人物弧线 |
| 守门人 / 普通居民 | 具体个人动机尚未在核心人物文档冻结 | 可表达安全、道路、陌生人和村庄日常 | 随北门、征兵、外来者和区域事件变化 | 当前有守门人，但台词偏神秘暗示，缺少生活状态与信息来源约束 |
| 失忆的年轻人 | 目前只见于实现，核心人物文档尚未确认其与主线的准确关系 | 暂可作为待审角色，不默认其拥有主角过去的关键信息 | 需有独立生活、记忆边界和后续事件才能保留 | 当前台词直接识别主角 / 其身体异常，信息量可能超出人物来源 |
| 旅行商人 | 当前实现中的 NPC 名称；是否等于金正未确认 | 提供交易与旅行见闻 | 应与货物、路线、短刃和信息流相联系 | 先做身份核对，不在代码中直接把“旅行商人”改名为金正或反向合并 |

### 台账规则

每个准备进入实现的核心人物，至少要补齐以下字段：

- 独立生活与当前处境；
- 人物想要什么、害怕什么、有哪些限制；
- 初始状态与可观察行为；
- 主角未介入时的自然发展；
- 主角介入后可能改变的结果；
- 与哪些 A 区域 / H 区域 / 连接 / 物品发生因果联系；
- 事件发生后对人物、其他 NPC、地图或物品造成的可见后果；
- 错过条件与不可逆条件；
- NPC 知道什么、从何得知、明确不知道什么；
- 对话只呈现该状态下可知的信息。

## 5. A1 地点与信息职责

| 地点 | 已有 / 预期作用 | 设计要求 |
|---|---|---|
| 蜜忒的家 | 初次醒来、日常关系、休息与回访 | 与村庄门外形成清晰手动往返；不把初次开场变成永久重生点 |
| 酒馆 | 居民聚集、闲谈、歌声与外来消息 | 传闻应由说话者的经历支持；歌声是异常细节而非直接揭秘 |
| 教会 | 村庄与教会权力关系、记录与抹除痕迹 | 进入教会不能在没有清晰因果时自动判定蜜忒关系失败 |
| 墓地 / 旧钟 | 村庄记忆、钟声异常和旧故事 | 与 A2 钟墓及隐藏证据建立跨区域呼应，但不在 A1 一次解释完整 |
| 井水 / 旧石构 | 日常资源问题与更古老建筑的线索 | 与 H01 及 A4 的地理 / 结构关系一致；“井水有问题”需要具体证据和居民反应 |
| 复国军营地 | 战争、征兵 / 告示、营地人员的日常与分歧 | 不把阵营描述简化为统一立场；小兵必须有可见生活痕迹 |
| 北门 / 旧朝圣路 | A1 ↔ A2 主线连接 | 入口状态、事件条件、出生点、回程与提示必须和 C02 及拓扑一致 |
| 旧排水通道 | A1 ↔ A3 的低位替代路线 | 开放条件须与 C24 两端实体门一致；不应只在拓扑或单侧脚本中解锁 |
| 村庄炉火 / 休息点 | 休息、存档 / 恢复与状态推进的潜在锚点 | 功能节点与有独立生活的人物要分开设计 |

## 6. A1 → A13 的信息与人物交汇基线

此表记录“村庄可提供或承接什么”，不表示玩家应在 A1 得到完整答案。

| 区域 / 方向 | A1 可提供的初始信息 | 后续证据 / 回访变化方向 | 不应发生的事 |
|---|---|---|---|
| A0 教会手术所 | 主角的伤口、包扎、衣物与少量残留痕迹 | 手术记录、物品、身体异常逐步补全 | 村民一开始就解释实验机制 |
| A2 雾林 / 钟墓 / 旧朝圣路 | 野兽、道路风险、旧钟与朝圣路传闻 | 森林 Boss、朝圣骑士、钟墓环境与高路回响 | NPC 直接给出 Boss 全解或古神真相 |

| A4 下水道 / 水库 | 井水、旧石渠、村庄水源的局部问题 | 水闸、古老结构、H01 双入口状态 | 没有证据就宣布井水已被污染 |
| A5 旧战场 | 征兵、失踪、官方战史与营地争论 | 战旗、尸体朝向、战争记录矛盾 | 复国军被写成所有人都正确或全错 |
| A6 修道院 / 钟塔 | 村庄钟声习俗、旧钟维护传闻 | 钟声异常、维修记录与教会记录矛盾 | A1 直接解释隐藏钟室 |
| A7 监牢 / 维护竖井 | 失踪者、押送或囚犯传闻（来源必须合理） | 牢房记录、无编号维修通道与囚犯作为研究材料的证据 | 普通村民知道所有实验细节 |
| A8 旧王墓 | 家族名、墓地维护与被删名字的传闻（尚待具体设计） | 王室姓名、继承记录与抹除行为 | 直接告诉玩家完整王室阴谋 |
| A9 王城外环 | 旅行者、商人、流民与旧城消息 | 居民生活与官方秩序的矛盾 | 商人无理由全知 |
| A10 大圣堂 | 教会仪式、征税 / 物资 / 祷告等表面生活 | 假信仰力量与古神研究的环境证据 | 过早公开古神机制 |
| A11 深层研究区 | 只提供失踪者和教会旧事的碎片 | 实验档案、研究对象和研究者误判 | 让 A1 居民知道深层实验真相 |
| A12 王室内城 | 征兵、命令、王权与战争后果的传闻 | 国王的决策、未寄出的信和王国生存逻辑 | 把国王简单化为毫无动机的恶人 |
| A13 终局层 | A1 只留下人物、物品和关系上的回响 | 玩家把早期细节重新理解 | A1 提前解释终局或外神本体 |

## 7. 当前代码静态审计：实际存在的偏差

审计对象：`scripts/levels/village_hub.gd`、`scripts/levels/mite_house.gd`、`scripts/levels/village_defense_demo.gd` 与项目叙事文档。此处只陈述源码可见事实，不代表运行时行为已测试。

### 7.1 当前 NPC 与叙事基线错位

- A1 当前生成守门人、失忆年轻人、旅行商人和蜜忒；核心人物方向中的铁匠、老婆婆、复国军小兵没有以完整人物状态出现，猎人候选 / 老猎人的身份也未落入明确台账。
- “旅行商人”与“金正”之间没有被本基线确认的身份映射；短刃交易是人物弧线中的关键事件，但当前 A1 生成片段没有体现其材料交易合同。
- 守门人、年轻人和旅行商人的台词主要由 `selected_route` / `humanity_state` 选择，缺少其亲历事件与知识来源的状态模型。
- 年轻人直接说出主角曾跪在教会、身体里有东西离开等高价值信息；需要检查其身份、亲历来源和剧透节奏后再保留。
- 墓地、酒馆、复国军营地、教会、北门和排水道目前主要是固定描述 / POI；这不是完整的人物弧线，也尚未构成“线索—跨区调查—回访—人物反应”的闭环。

### 7.2 事件与路线耦合过紧

- 北门交互在未完成 `village_defense_survived` 时会直接进入 `village_defense_demo.tscn`；它不是单纯观察道路或选择是否出发。
- 北门 A2 和旧排水通道 A3 都受同一个 `village_defense_survived` 旗标控制。此结构目前可能把一场战斗同时变成 A2、A3 的共同门槛。
- 现有防卫章节自动开始攻击、要求连续击败两波敌人；应先确认它在新版叙事中是强制剧情、可选事件还是延迟发生的世界状态，之后再决定重构。
- A1 场景在 `_ready()` 中把通用 checkpoint 设在固定坐标；需要单独确认“初次抵达”“从北门回村”“从排水道回村”“从水闸 / 其他区域回村”和 Continue 恢复之间的出生侧合同，不能让叙事调整破坏已有地图连通性。
- 教会 POI 的交互会在玩家没有 `mite_stay_a_while` 时直接调用 `mark_mite_connection_missed()`。这把“进入教会”隐式变成关系断裂条件，因果过于武断；必须核对 canonical story 与人物状态设计，不能仅凭一次探索行为自动判定错过蜜忒。
- 蜜忒关系状态在村庄、房间和其他流程中分散处理。空椅子场景虽符合“缺席的情绪后果”方向，但缺席条件应由统一的人物状态机产生，而不是局部脚本各自推断。
- 场景载入后自动播放摇篮曲，会把村庄异常作为强制氛围提示；应检查是否与“初期普通生活优先、异常慢慢出现”的导演要求冲突。

### 7.3 文档之间存在的规范冲突

- `DEVELOPER_STORY_MEMORY.md` 的旧叙事段落把身体亲密、关系断裂与三结局叙事联系得很紧；较新的 `STORY.md` 和 `CORE_CHARACTER_ARCS_V1_CN.md` 明确写出：**身体亲密不是任何结局的必要门槛，结局由共鸣、真相锚点和探索记录决定**。
- 因此，A1 不应把某次蜜忒互动、进入教会、某个房间休息或某个关系标记直接用作结局条件。关系可以改变人物场景和情绪意义，但结局条件必须遵守当前明确的 ending evaluator 契约。
- `OPENING_STORY_MAP_INTEGRATION_V1_CN.md` 已指出 A0 可玩逃脱与新版失忆后村庄开局之间存在叙事衔接问题，并要求先裁定而非由代码替代决定。当前 A0→蜜忒房间流程已作为实现存在，但仍应与新版开局叙事共同复核。

## 8. 重建后的事件 / 状态架构

A1 后续实现应围绕可审计的事实状态，而不是堆叠 `if selected_route` 的对白分支。

建议每个事件至少有：

- **触发事实**：玩家做了什么、获得什么物品、从哪张地图返回、某人物是否亲历。
- **世界状态**：持久旗标或结构化事件状态，说明事件确实发生过。
- **人物反应**：NPC 只对自己知道或推断出的事实做出反应。
- **环境后果**：门、物品、营地、房间、尸体、工作痕迹或可调查对象变化。
- **可错过规则**：什么情况下自然错过；错过后出现什么可信后果。
- **回访规则**：同一事件重复访问是否变化、是否可逆、是否重复奖励。
- **地图契约**：相关连接 ID（如 C02 / C24）、进入侧、回程出生点和门槛必须一致。
- **验收证据**：静态合同、存档 / 读档测试、无 Debug 完整流程和 Godot 实机记录分别标明，不能混为一谈。

优先采用“人物生活状态 + 已发生事件 + 已发现证据”的组合。不要把所有状态塞进一个泛化任务列表，也不要引入可见好感度。

## 9. 重构前必须解决的设计问题（不在本次擅自裁定）

1. **村庄防卫的性质**：强制主线事件、可选事件还是有延迟的世界状态？C02 / C24 是否继续共同受它控制？
2. **金正与旅行商人**：是否同一人？如果是，何时以什么方式使用“金正”身份；如果不是，两个角色各自的独立生活是什么？
3. **猎人角色**：旧设计“老猎人”是否仍保留？与最新文档“猎人候选 / 荒野居民”是否合并？
4. **失忆年轻人**：是正式核心人物、临时占位 NPC，还是应从 A1 移除？他为何知道教会、主角身体和歌声的信息？
5. **蜜忒缺席的判定**：错过的是哪些真实相遇机会？什么事件让她离开 / 无法再见？不得用一次教会交互或单个硬编码标记替代完整因果。
6. **初期村庄气氛**：摇篮曲是否每次进入自动播放，还是仅在有依据的关系 / 证据 / 事件后出现？
7. **铁匠、老婆婆、小兵、休息 NPC 的首次登场顺序**：如何让他们先被玩家当作生活中的人，而非任务入口？
8. **A1 的日常线索如何与 A2–A13 的实际物品、环境叙事和人物事件逐项对齐**：需以地图总账与物品目录为准，不能凭空添加新收集 / 制作循环。

## 10. 推荐执行顺序

### P0 — 冻结基线
- 将本文件作为 A1 的设计审计基线。
- 核对上面 8 个设计问题与现有 canonical 文档；如有冲突，更新规范文档而非先改代码。
- 统一“已确认 / 暂定 / 开放”标记。

### P1 — 建立数据合同
- 建立核心人物状态表与事件表。
- 把蜜忒关系、村庄防卫、人物回访、物品证据与路线开放分开。
- 明确 C02 / C24 的门槛和两端场景一致性。
- 对每个 NPC 建立知识来源和可知范围。

### P2 — A1 场景重构
- 先重构 NPC 生成与状态选择，再重写对白。
- 把固定 POI 文案升级为由已发生事件 / 已发现证据驱动的有限状态内容。
- 保留已建立的安全出生点、门交互和地图回程合同；任何门槛变更须同步拓扑和验证器。
- 不先做大规模美术或增加无关道具。

### P3 — 全图联动
- 为每个核心 NPC 至少安排一个 A1 之外的真实事件或后果。
- 把 A1–A13 的线索来源、拾取物、环境证据和回访反应登记进世界内容总账。
- 隐藏证据继续保持碎片化，不提示“结局清单”。

### P4 — 验收
- 静态：脚本引用、事件状态、门槛与拓扑、出生侧 / 回程、对话状态覆盖。
- 存档：新档、旧档默认值、Continue、从各连接返回 A1。
- 实机：新游戏从 A0 走到 A1，手动出入蜜忒家，自由观察，触发 / 不触发防卫事件的候选流程，进入 A2 与 A3，再返回 A1 检查 NPC / POI 变化。
- 所有结果分别标注“源码审计”“静态脚本执行”“Godot 运行时”，不以其中一种代替另外两种。

## 11. 当前基线结论

**A1 的问题不是少写几句对白，而是人物弧线、世界事件、地图门槛和关系状态尚未共享同一份可审计设计合同。**

当前不应直接把旧猎人、老婆婆、铁匠等角色机械塞进场景，也不应先删除村庄防卫。正确顺序是先冻结角色身份、事件性质、知识边界和跨地图因果，再将其映射到代码。本文完成的是基线与差异清单；具体 NPC / 事件重构和 Godot 运行时验收属于后续阶段。
