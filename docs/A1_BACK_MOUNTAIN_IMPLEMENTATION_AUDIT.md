## 1. 分支状态与集成原则

- 地图工作分支为 `feature/story-map-progression`；主角动画骨骼工作分支为 `feature/hero-animation-system`。
- 两条分支与 `development` 已出现明显分歧，不应直接将整个分支合并来解决这次文档误提交。
- 地图设计文档、拓扑和地图验证合同在地图分支维护；动画骨骼实现留在动画分支。跨领域代码（如 Hero 移动、伤害链）需要按接口做定向集成，不应把整条分支混在一起。
- 这份审计只涉及地图分支代码，不替代后续将地图分支与 development 对齐时的完整 diff 审核。

## 2. 能力与隐藏路线

### 二段跳

- `scripts/player/hero.gd` 通过 `WorldState.is_ability_unlocked("double_jump")` 门控额外空中跳跃，角色仅允许一次额外空中跳跃。
- `scripts/core/world_state.gd` 注册了 `double_jump` 能力 ID，并提供带来源的持久化解锁记录。
- 本次针对地图分支进度合同的审阅没有确认二段跳的正式发放事件。实施 BM-40 前，应继续定位实际的 `unlock_ability("double_jump", ...)` 调用；若没有发放流程，应先与全局能力进度设计对齐，不能在后山临时发放来绕过主线设计。

### 灵视与隐藏路径

- `tools/world_map_topology.json` 的共鸣进度合同把 `resonance_sight` 的解锁安排在 A2 的 `anomaly_bell_retiming` 事件。
- `hero.gd` 会检查灵视是否解锁，并存在主动开启、持续时间与冷却管理。
- 地图分支存在 `scripts/world/resonance_secret_gate.gd`，可用于实现隐藏门条件；`WorldState` 提供持久化隐藏路径状态。正式配置前仍须对照该分支脚本参数与现有 H/C 门合同，不能直接复制其他分支的阈值。
- 后山隐藏封印可以继续以灵视作为候选条件，但必须确认后山访问顺序和灵视解锁顺序；若解锁太晚或造成支线设计不公平，应改用既有线索/印记，而不是新增平行收集系统。

## 3. 火焰斗篷与伤害链

- 地图分支的 `scripts/core/item_catalog.gd` 已有绷带、手术记录残页和烧黑的教会封条等条目，但未见火焰斗篷定义。
- `scripts/combat/hurtbox.gd` 的 `receive_hit(damage, source)` 将整数伤害传递给宿主的 `receive_damage(damage, source)`。
- 当前审阅未确认统一的伤害类型参数或火焰抗性接口。斗篷不能只作为一个普通库存条目添加；需要先追踪地图分支所有火焰/环境伤害来源，再决定最小向后兼容的类型标记与统一减伤入口。
- 40% 火焰减伤仍只是平衡初值提案，不是已实现效果。建议由统一受伤入口计算被动减伤，避免敌人和环境分别写斗篷判断。

## 5. 局部路线合同

```text
A1 安全侧 -> BM-00 山脚 -> BM-10 第一峰脚 -> BM-20 吊桥断谷
 -> BM-30 环山旧道 -> BM-40 二段跳硬门槛
    未解锁：安全退回；已解锁：回访继续
 -> BM-50 第二峰枢纽 -> BM-60 上层火路分岔
    主路：BM-70 龙峰前庭 -> BM-80 飞龙战场
    支线：火焰侧路 -> BM-H1 隐藏封印 -> BM-H2 可选神职人员遭遇
```

- BM-40 必须视觉可读、可抵达、可安全撤退，不能靠不可见空气墙或无承托落差表达能力门槛。
- 火焰支线不能成为抵达飞龙的必经主路；斗篷减伤而非免疫。
- 隐藏门开启状态应持久化；隐藏 Boss 的死亡恢复必须回到安全区域，不得把玩家送入火焰持续伤害区。
- BM-50 的山脊捷径必须真实缩短回程，并审计两端出生点、地面承托与门触发范围。
- 飞龙峰顶的外部连接、正式区域编号和金正救援地图均保持未决。
