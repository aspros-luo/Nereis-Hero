## 1. 已确认的代码事实

### 二段跳

- `scripts/player/hero.gd` 的移动逻辑只在 `debug_ability_override` 或 `WorldState.is_ability_unlocked("double_jump")` 为真时，才允许使用额外空中跳跃。
- 角色有一次额外空中跳跃额度（`MAX_EXTRA_AIR_JUMPS = 1`），因此 BM-40 可以成为真实的能力硬门槛，而不是纯叙事提示。
- `scripts/core/world_state.gd` 已注册 `double_jump` 能力 ID，并提供 `unlock_ability` 的持久化能力记录。
- 本次审阅的 `tools/world_map_topology.json` 能力/共鸣进度合同中没有找到明确的二段跳发放节点。当前不能安全假设玩家会在某个固定剧情节点取得它。实施 BM-40 前，必须继续定位所有 `unlock_ability("double_jump", ...)` 调用或确认当前根本没有正式发放路径；若没有，应先把发放节点纳入全局进度设计，而不是在后山临时赠送。

### 灵视与隐藏路径

- `tools/world_map_topology.json` 的 R01 将 `resonance_sight` 安排在 A2 的 `anomaly_bell_retiming` 事件：至少将共鸣提高到 12 并解锁灵视。
- `scripts/player/hero.gd` 中主动开启灵视需 10 点耐力，持续 4.5 秒，冷却 6 秒；未解锁时不能正常开启（调试覆盖除外）。
- `scripts/world/resonance_secret_gate.gd` 支持共鸣、古神接触度、外神接触度、来源 ID 和外神共鸣等可配置条件。入口必须在灵视激活且满足阈值时显现，之后按 E 开启。
- 开启状态通过 `WorldState.open_hidden_path(secret_id)` 写入 `opened_hidden_paths`，会持久化；场景切换关闭灵视不会把已开启的门重新锁上。
- 设计结论：灵视机制可复用，但隐藏支线门应使用独立 ID（例如未来分配的后山支线 ID），不得借用现有 H/C ID；第二条件须等到确认后山抵达进度与灵视发放顺序后再定。

### 火焰斗篷与伤害链

- `scripts/core/item_catalog.gd` 当前只定义 `church_bandage` 与 `surgery_record_fragment`；没有斗篷物品定义。
- `scripts/world/world_item_pickup.gd` 的拾取逻辑只负责登记目录物品、写入库存和显示描述，不负责应用被动属性。
- `scripts/combat/hurtbox.gd` 的 `receive_hit(damage, source)` 只把整数伤害交给宿主的 `receive_damage(damage, source)`。
- 目前审阅到的通用受击链没有伤害类型参数，也没有火焰抗性查询。故火焰斗篷无法通过单纯添加库存条目实现 40% 减伤。
- 实施建议：先让伤害源以向后兼容的方式标注类型（默认 physical/normal，火焰来源明确传入 fire），再由主角的统一受伤入口根据持有的斗篷被动减伤。不要在每一个火焰敌人脚本里各写一套斗篷判断；否则后续 Boss、环境火焰和持续伤害容易出现规则不一致。40% 仍只是待测参数。

### A1 入口布局风险

- `scripts/levels/village_hub.gd` 将村庄地面作为宽场景，Hero 摄像机右界为 x=2600。
- 右侧现有点位包括教堂（约 x=2180）、崖壁洞窟入口（约 x=2260，满足剧情条件后出现）、北门出生/出口侧（约 x=2310–2440）和村庄防卫后出现的复国军营地（约 x=1990）。
- 因此不能把后山入口未经布局审计就放到村庄最右端，否则可能与北门、教堂、崖壁洞窟和营地争夺同一屏幕空间或交互焦点。
- 当前 A1 总体区域仍是边境村庄；后山先作为局部子区域处理，不擅自新增正式 A 编号，也不擅自决定龙峰的外部主线连接。

## 2. 当前建议的局部路线合同

以下是路线关系，不是已存在的场景连接或坐标：

```text
A1 既有村庄安全侧
  -> BM-00 山脚入口
  -> BM-10 第一峰脚（空中敌人教学）
  -> BM-20 第一断谷（吊桥）
  -> BM-30 环山旧道
  -> BM-40 高位岩架 [二段跳硬门槛]
       未解锁：安全退回 BM-30 / 山脚 / A1，提示回访
       已解锁：继续攀登
  -> BM-50 第二峰交通枢纽
       -> 开启山脊捷径，回到 BM-10 或 BM-20 的安全侧
       -> BM-60 上层火路分岔
            -> BM-70 龙峰前庭 -> BM-80 飞龙战场
            -> 火焰侧路 -> BM-H1 隐藏封印 -> BM-H2 可选神职人员遭遇
```

### 路线公平性与状态合同

1. BM-40 必须是玩家能看见、能抵达、能安全离开的硬门槛。不要用不可见空气墙或让玩家跳入无承托深坑来解释“能力不足”。
2. 二段跳未解锁时，不能把 BM-50、龙峰或隐藏支线作为可绕过 BM-40 的平地旁路；否则硬门槛失去意义。玩家应返回其他区域获得能力。
3. 火焰支线不能成为通往 BM-80 的必经主路。斗篷降低火焰伤害但不免疫；无斗篷时必须能辨认危险并退出。
4. 隐藏封印只在支线内部使用灵视/线索条件。满足条件并按 E 开门后，开门结果持久化；隐藏 Boss 的失败恢复不得把玩家送进持续火焰伤害区。
5. BM-50 的捷径必须真正缩短回程，且两端落点有承托、不会把角色送进门触发区。此项需要灰盒场景才能验收。
6. 龙峰外部连接、后山正式区域编号、金正救援地图位置均保持未决，不从局部路线草案反推全局剧情。

## 3. 下一步实施顺序

1. 全仓库追踪二段跳发放调用及其真实触发条件；若缺失，先在全局进度设计中明确发放点。
2. 检查所有主角与环境的 `receive_damage` 实现及火焰伤害来源，定义最小兼容的伤害类型合同。
3. 根据村庄当前点位图确定后山入口位置，并复核交互焦点、门触发范围和北门路线。
4. 再把 BM 节点转成灰盒场景/连接，并为每个跨场景转移定义来源出口、目标出生侧、承托、死亡恢复和捷径持久状态。
5. 运行静态拓扑验证和 Godot headless/场景验收后，才能把相应项标为 PASS。
