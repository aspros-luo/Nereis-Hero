# 地图空间设计原则与下一阶段完善方案

> 本文是地图设计合同，不是引擎验收报告。  
> This is a map-design contract, not a runtime acceptance report.

## 1. 核心体验：先记住空间，再发现空间撒谎

地图不能只是连接场景的走廊。每个区域都应先以普通、可读的物理空间出现，再由灵视揭示同一空间里不符合现实的部分。

1. **第一遍可读**：玩家能凭路标、光源、建筑轮廓、敌人位置理解主路和回路，不需要灵视才能继续主线。
2. **第二遍异常**：灵视不应简单把整张地图涂成另一种颜色；它揭示被删掉的门、错误方向的回声、镜面里多出来的台阶或与建筑年代不符的石层。
3. **永久改变**：第一次 E 打开异常后，永久状态应改变可通行性；之后即使灵视关闭、死亡或读档，已经打开的路径也仍然存在。
4. **有记忆的捷径**：远端出口通常要求玩家先从主线抵达目标区域。隐藏区可以缩短回程，但不能替玩家完成尚未经历的关键主线首次到达。
5. **少而有意义的回头路**：A1–A4 是边境环路，A3/A5/A6 是中层环路，A4/A8/A9 是王国深层环路。每条环路都应有明确开启侧和视觉地标。

## 3. 门、交互与空间状态

每个门/异常都必须明确区分以下状态，禁止把它们压成一个 bool：

- **未显现**：无可用 E 提示；物理地标可以存在。
- **已显现但未开启**：灵视与条件满足时可见；第一次 E 只记录发现并永久开门，不应立刻传送。
- **已开启**：路径状态持久化；第二次 E 才执行场景切换。
- **远端出口已解锁**：由目标区域已抵达和远端开门记录共同决定，不能只检查隐藏区是否开启。
- **当前不可交互**：交互焦点必须释放；NPC、出口、线索与隐藏门重叠时，不可用目标不能遮挡可用目标。

每个场景切换要显式传递目标出生侧。出生点要离开触发区与敌人碰撞体，进入后应能先看懂空间，再走向出口，而不是落地立即重复交互。

## 4. 进度与存档不变量

1. `current_location` 必须映射到存在的场景；未知或过期 ID 要有安全回退策略。
2. `pending_region_spawn_side` 是一次性传递值：进入目标场景后应消费并重置，不能污染之后的场景切换。
3. 永久开门、隐藏区发现和进入记录是三种不同事实，不应互相推导。
4. 异常来源 ID 是幂等键；旧存档修复只能补最低状态/能力，不得重复发放一次性增量。
5. 临时灵视、暂停、输入锁、交互焦点不应因场景切换而残留；故事事实和永久路径不能因重生而丢失。
6. 结局门只读取故事状态与结局条件，不得要求 H01–H08 全收集。
