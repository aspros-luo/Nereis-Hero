## 1. 本轮确认的 A1 核心定位

A1 是可反复返回的生活、休整与信息枢纽，不是任务大厅或剧情讲解中心。

- 蜜忒是 A1 的情感核心，也是玩家在整个旅程中最希望再次见到的人物。她的关系和生活变化不得被普通 NPC 进度系统稀释。
- 守门人只熟悉村庄及周边道路、地形和自己亲历/听闻的事情；他不是全知者、任务发布者或世界导航员。
- 普通居民各自提供有限视角。传闻可以不完整、错误或尚未证实，不要求每条传闻最终都成真。
- 玩家通过环境、探索、物品和 NPC 有依据的反应拼合信息；不使用任务清单强迫玩家按指定顺序探索。
- NPC 的新对白由玩家真实发生的探索/事件触发，不以“地图上可到达”代替“玩家实际到过”。

## 2. 守门人：已确认的职责与首轮信息

稳定 ID：`village_gatekeeper`。

**职责：** 作为村庄周边的熟悉者，让玩家从普通交谈中自然意识到周边存在三条值得留意的方向。所有初始线索均通过与守门人交谈获得，不需要接受任务、领取标记或触发强制剧情。

| 线索方向 | 守门人可以说的事实 | 信息边界 |
|---|---|---|
| 雾林 / 古老钟墓 | 雾林里有一座古老的钟墓 | 他知道钟墓存在，不代表知道钟墓内部现状或真相 |
| 右侧下水道 | 下水道很早以前因战争被堵塞，年久失修，已经废弃 | 他能描述村庄旧设施和战争记忆，不代表知道通道深处有什么 |
| 后山 / 飞龙 | 小时候曾在后山看见过飞龙 | 这是个人童年记忆；可能看错、记忆失真或确有其事，当前不作裁定 |

### 对话节奏

1. 初次交谈：自然寒暄，不立刻倾倒全部世界观。
2. 继续交谈：以几段短对白讲出三条周边见闻；可在一次交谈中连续听完，也可分次听完，但不得要求玩家完成任务。
3. 阶段耗尽：当前阶段的所有新内容播放完毕后，进入简短、自然的重复对白。
4. 后续反馈：只有玩家实际进入相关区域、发现有意义的证据或改变相关世界状态后，才出现对应反馈。
5. 没有新事实时：重复对白保持短小，不重新播放初见和已经听过的长段内容。

**空间注意：** 当前场景/设计资料曾记录守门人坐标 x≈2740、北门内侧；早期设计文本也出现过 x≈650 等旧坐标。空间坐标以当前场景文件为准，本轮不改站位。守门人与北门 POI 的交互焦点必须继续分离，避免两个对象争夺输入。

## 3. NPC 对话阶段：统一的基础规则

普通 NPC 的建议状态模型：

- `INTRO`：初见阶段；仅在尚未完成该阶段时播放。
- `NEW_CONTENT`：由明确条件解锁的新内容；优先级高于重复对白。
- `EXHAUSTED`：当前阶段的新内容已全部听完。
- `REPEAT`：没有未读新内容时播放的短重复对白。
- `REACTION`：对特定探索事实/事件的反馈；可以作为独立内容队列或高优先级变体，但不能覆盖未读的重要内容。

规则：
- “对话内容已听过”与“事件已完成”是两种不同事实，不能共用一个含糊 flag。
- 新内容必须有稳定 ID；按 NPC ID + dialogue ID 记录已读状态。
- 对话播放完成后才标记为已读；中途退出或切场景不得误记为已读。
- 同一阶段可有多段内容，播放完最后一段才进入重复对白。
- 重复对白短、自然、可再次播放；它不是新剧情，也不重复发放奖励。
- 条件按具体到一般排序；同一时刻冲突的内容须有明确优先级。
- 离开、死亡、Continue 和重新进入场景后，已读记录和事件事实必须保持一致。
- 对话条件只读取可验证的 WorldState 事实；角色不得无缘由获知远方事件。
- 不要求每个 NPC 都有全部状态。宁可只有初见 + 一句重复对白，也不要为填系统制造无意义对白。

## 4. 蜜忒：使用统一基础设施，但保留独立叙事模型

蜜忒使用统一对话播放、存档和输入基础设施，但她不是普通 NPC 配置项。

必须保护的既有内容/合同：
- 初次相遇、共餐、挽留、归来等既有关系事实；
- 按地点/互动节奏限制重复互动的现有设计意图；
- 错过相遇后的空椅子反馈；
- 共鸣后的分阶段对白和表现变化；
- 关系状态不能直接作为结局开关，身体结合不是结局必要条件；
- 她的早期善意、好奇和日常生活必须真实，不提前解释她的核心秘密。

蜜忒需要独立管理关系事实、她自己的生活状态、玩家离开/回访、特殊剧情阶段和不可逆互动。普通 NPC 的“初见—耗尽—重复”机制不能覆盖或压缩这些阶段。

## 5. 当前源码差距（静态阅读，不代表运行时复现）

- `scripts/npc/route_npc.gd` 当前只持有单个 `dialogue` 字符串；交互时发出信号，场景控制器显示同一段对白。没有通用的“新内容耗尽后切换重复对白”状态。
- `scripts/core/world_event_director.gd` 已支持稳定 NPC ID、条件生成、条件对白变体和事件 flag；但对白变体是在生成时解析成一个字符串，尚不是可推进/可耗尽/可重复的对话序列。
- `scripts/levels/village_hub.gd` 目前通过 `_refresh_baseline_npc_dialogue()` 按世界状态替换守门人、老婆婆、铁匠和商人的单段对白；回访反馈基础已存在，但缺少逐段已读状态和重复对白回退。
- `scripts/npc/mite.gd` 使用专属互动 ID 与 `WorldState` 记录关系互动，不应直接迁移到普通 NPC 的通用序列。当前逻辑在每个地点限制互动，并按关系/共鸣阶段选择内容；应先审计现有存档和地点节奏，再决定如何补充日常重复交谈。
- `scripts/core/narrative_manager.gd` 负责显示单段消息和输入锁定，不应承担 NPC 条件判断、事件写入或人物关系决策。

因此，本轮结论是：**现有系统有事件与状态基础，但尚未实现用户描述的完整魂系列对话阶段机制。** 不应误报为已经具备。

## 6. 推荐架构边界（尚未实现）

建议分成三层，避免把人物逻辑塞进 UI：

1. **Dialogue Data**：稳定 dialogue ID、文本、所属 NPC、阶段/优先级、解锁条件、已读后回退对白。
2. **Dialogue Progression**：根据 WorldState 选择下一条可播放内容；记录已读；确保优先级、耗尽和重复回退正确。
3. **Narrative Presentation**：沿用现有 NarrativeManager 显示内容、等待玩家确认/结束并发出完成信号；不负责决定下一条剧情。

事件导演继续负责事件触发与 NPC 出场条件；不要让通用对话系统直接操纵场景节点、奖励、门或人物命运。若事件发生在对白结束后，必须区分“对白已读”与“事件成功触发/完成”。

### 建议的选择优先级

1. 关键剧情反应（有明确事件事实且尚未播放）；
2. 角色相关探索反馈（实际进入、收集、阅读或事件完成）；
3. 当前阶段尚未读过的普通对白；
4. 当前阶段重复对白。

如果同时有多条同级新对白，应采用明确的优先顺序或稳定队列，不能每次刷新随机跳变。

## 7. 下一轮角色梳理顺序

1. 守门人：完成三条线索的自然中文对白、重复对白与三条路线的后续反馈。
2. 蜜忒：核对既有关系阶段和地点互动，整理“已确认 / 已实现 / 待设计”，不改核心命运。
3. 老婆婆：只提供生活经验和她实际听闻的事情。
4. 铁匠：服务、手艺、北门修复等可观察日常；不让他成为万能装备菜单。
5. 旅行商人：保留其身份未必等于金正的既有待确认状态；只谈交易、行路和亲历见闻。
6. 酒馆值夜人：传闻来源与酒馆声音事件分开；不让所有异常汇聚成一个阴谋。
7. 墓地钟守人、朝圣骑士及进度型人物：继续遵守各自出场条件和未定剧情边界。

## 8. 正反方裁定

**采纳统一对话进度基础设施：**
- 收益：避免每个 NPC 各自维护已读 flag；让“新内容—耗尽—重复—事件反馈”一致可测；有利于存档恢复。
- 风险：若系统过度复杂，会产生大量状态和对白矩阵；若把蜜忒也当普通配置，会破坏她独特的关系节奏。
- 裁定：采用轻量、数据驱动的通用基础设施；蜜忒保留专属关系模型；不为每个 NPC 强制增加所有阶段。
- 验收：新游戏初见只播放一次；连续交谈能听完阶段内容；耗尽后回到短重复对白；触发新事实后先播放对应新内容；死亡/Continue/跨场景返回不丢已读状态；重复交谈不重复触发事件或奖励。

## 10. 守门人正式角色卡与对白脚本（设计完成，待系统接入）

### 10.1 角色定位

- **身份：** 村庄北门内侧的守门人，长期看守村庄出入口，熟悉村庄周边道路、旧设施和当地人的生活。
- **性格：** 寡言、务实、略带疲惫；不是冷酷的谜语人，也不热衷讲故事。面对陌生人先观察，再决定说多少。
- **叙事功能：** 让玩家自然听见村庄周边三条路线的存在；在玩家真正回来并带着新见闻时，给出有限、符合他知识边界的反应。
- **不承担：** 发任务、标记地图、解释世界真相、预言路线内容、替玩家总结探索进度。
- **空间：** 当前 `scenes/village_hub.tscn` 中守门人位于 x=2740，北门 POI 位于 x=2840。两者距离近但交互焦点独立；本设计不移动节点、不合并交互对象。

### 10.2 初见与初始线索对白

对白按稳定顺序播放。每段结束后玩家再次按交互键才进入下一段；若玩家中途离开，不应把未播放的段落记为已读。

> “今天没什么新消息。看好脚下的路。”

### 10.3 三条路线的后续反馈

反馈只在相应事实真实发生后解锁。每条路线独立记录；玩家可以任意顺序探索，未探索的路线不会被其他路线的事件顺带解锁。

| 路线 | 可接受的真实触发事实 | 稳定对白 ID | 守门人反馈 |
|---|---|---|---|
| 雾林 / 钟墓 | 玩家实际进入 A2 雾林 R01；若要谈钟墓本身，则必须实际进入钟墓相关房间或发现明确钟墓证据。仅从 A1 出发、地图可见或旧的灰盒介绍 flag 不够。 | `GK_FOREST_ENTERED` / `GK_BELL_TOMB_EVIDENCE` | “你去过北边了？那片林子比我记得的还要静。……钟墓？我只知道它在那儿，里面的事你得自己看。” |
| 右侧旧下水道 | 玩家实际进入 `old_drain_exploration`，而不是仅靠近 A1 的封闭入口或读到守门人的传闻。 | `GK_DRAIN_ENTERED` | “你真进了那条旧排水道？我还以为它早就彻底塌了。里面的路还能走到哪儿，我就不知道了。” |
| 后山 / 飞龙 | 玩家实际进入后山悬崖探索场景；单纯走到 A1.1 后山入口不算看见飞龙。只有实际目击/发现明确证据，才可解锁更具体的反应。 | `GK_BACKHILL_ENTERED` / `GK_DRAGON_EVIDENCE` | “你去了后山？那地方现在还走得通？……飞龙的事，我小时候说过吧。你要是真看见了，那可比我当年的记忆清楚。” |

**关键限制：** `GK_FOREST_ENTERED` 只允许谈“你去过雾林”；不能自动谈钟墓内部。钟墓证据反馈必须单独触发。飞龙传闻在玩家找到证据之前仍然保持不确定，不允许对白把童年记忆提前认证为事实。反馈文本不要求路线中必然存在飞龙，也不预设后续遭遇或结局。

### 10.4 当前地图/状态证据核对

以下结论来自当前分支源码静态阅读：

- `scenes/village_hub.tscn` 中守门人位置为 x=2740，北门 POI 为 x=2840；守门人和北门 POI 是两个独立交互对象。
- `scripts/levels/village_hub.gd` 将北门路线目标指向 `res://scenes/rooms/a2_fog_forest/runtime/a2_r01_room.tscn`；现在由 `guide_defeated` 控制北门，不再启动村庄防卫战。导则事件本身的身份与触发源仍待独立设计。
- 同一脚本将西侧旧排水入口指向 `res://scenes/old_drain_exploration.tscn`，初次进入 A1 即可探索短段并安全返回；深处闸门仍由 A4 侧的 `opened_old_drainage_link_from_A4` 控制。因此守门人不能再把入口描述成因村庄防卫战而封闭。

- 当前 `route_npc.gd` 只有单个 `dialogue` 字符串；`village_hub.gd` 的常驻 NPC 刷新逻辑会覆盖守门人的单段对白。故上述脚本是内容设计，不代表游戏中已能逐段播放。

以上 `a1_gatekeeper_*` 是建议命名，不是现有 WorldState 字段或已存在 achievement flag。实现时应优先评估现有 `explored_room_ids`、`current_location`、`entered_hidden_regions` 与场景进入事件能否直接提供事实，避免重复存储。对白已读状态仍须独立于探索事实，并在对白完整结束后才写入。

### 10.6 正反方裁定与验收

- **正方：** 三条路线一次自然交谈即可建立玩家的方向感；后续反馈能让据点回访有变化。
- **反方：** 若一次对话塞入太多路线，容易像任务列表；若把“进入区域”误当作“发现核心内容”，角色会显得全知。
- **裁定：** 保留四段短对白（初见 + 三条见闻），不出现任务语气；反馈按路线独立解锁，钟墓/飞龙的深层信息需要更具体证据。重复对白只作生活化回应。
- **验收：** 新周目按固定顺序听到四段内容；中途退出不误记未播放段落；全部听完后只出现短重复对白；进入 R01 不会触发钟墓内部反馈；进入旧排水场景前不出现“你进去过”的反馈；进入后山入口但未进入悬崖场景不触发悬崖反馈；飞龙传闻不会被系统自动确认为真；Continue、死亡和切场景后已读状态及探索事实不丢失。
