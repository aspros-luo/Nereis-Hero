# A2-R01 林间遗迹：手绘路线与 2D 纵深施工规格 v0.3

> 分支：`feature/story-map-progression`  
> Godot 目标版本：4.6.1  
> 本版以用户 2026-10-28 手绘草图为主要空间合同。根据实机反馈，已收敛中层树干跳台、明确下层支路入口，并将钟墓出口移入连续平台；这些改动仍需 Godot 本地解析与实机验收，不得标记为通过。

## 1. 设计合同：严格保留草图的四个空间关系

- **左侧 A1 村庄入口**：从左侧进入，接到一条相对宽阔的主路。
- **中部岔路**：主路到达岔点后分成上行主路与下行瀑布支路；分岔必须在视觉上可读，不得用无意义的独立跳台填充。
- **右侧主路出口**：上行主路沿自然斜坡升高，抵达右侧中层出口（R03 钟墓上环）。
- **右上树冠层入口**：从中上部开始逐级攀升，形成明显高于主路的路线，连接 R02 树冠与断桥。
- **下方断水/瀑布区域**：下行支路进入低处水潭/断水区域，作为可选探索。R04 下坠触发只放在明确的下坠井，不把整条低路变成强制通道。

## 2. Godot 场景实现

运行时房间：`scenes/rooms/a2_fog_forest/runtime/a2_r01_room.tscn`

场景直接使用 Godot 可见节点：
- `Polygon2D`：远景山脊、遗迹剪影、地形实体、瀑布、树冠与前景根系。
- `Line2D`：地面轮廓与瀑布高光，强化斜坡方向和边缘。
- `StaticBody2D / CollisionPolygon2D`：主路、上升斜坡、树冠阶台、下层岔路与水潭平台。
- `Marker2D`：入口、出口、下坠点和设计落脚点。
- `Area2D / CollisionShape2D`：R01→R04 下坠转场。
- 主角、HUD、叙事层、调试标识和转场门仍作为场景树中的实例节点存在。

本版没有使用脚本在运行时生成固定地形节点。运行时脚本只负责 Hero 初始化、房间出口交互、存档状态与下坠转场。

## 3. 纵深效果的验证目标

这不是 3D 场景。空间感来自多个可独立调整的 2D 层：
1. 深色远景底色与远山剪影；
2. 中景废墟和低对比雾带；
3. 可实际站立的前中景地形；
4. 高处树冠/根系轮廓；
5. 前景根系遮挡角色下半部或局部路径。

验收时需要确认角色能在地形前后层之间移动时保持合理的可见性。若某个前景多边形永久遮住角色或遮挡关键落脚点，应调整该节点的形状和 `z_index`，而不是删除真实地形碰撞。

## 5. 实机验收标准

1. 从左侧入口可以沿连续主路抵达右侧中层出口，不需要二段跳；出口门不得位于平台尽头导致玩家先坠落。
2. 在中部岔点能从主路直接进入下层斜坡/瀑布支路，不允许出现“只能向前走、无法到下层”的情况。
3. 树冠路由少量有明确用途的树枝台面构成；已删除重复的 `TreeTrunkStep_01–03`，保留 `CanopyBranch_West`、`CanopyBranch_StepA/B` 与 `CanopyBranch_East` 作为连续攀升路线。各平台高度差仍须用 Hero 实测跳跃包络确认。
4. 中央遗迹是远近层次地标，不可误认为可站立平台；只有具备 `StaticBody2D` 碰撞的地形才可承托角色。
5. 下坠井位于瀑布下方，只有角色向下坠落进入指定区域时才转场至 R04；低路上正常行走不能误触发。
6. 远景、雾带、地形和前景根系在游戏画面中形成可辨识的空间层次；前景遮挡不能长期遮住角色。
7. 从 R02/R03 返回时落在对应可站立地形，而不是悬空或嵌入碰撞体。

## 7. 设计方向暂停与 v1 重构入口（2026-10-28）

旧版“多层平台 + 多个独立落脚点”的 R01 已暂停继续叠加修补。下一版改为《胧村正：妖刀传》式横向推进节奏：连续主路、少量有意义的分支、以背景和前景塑造纵深，而不是依靠大量碰撞平台制造层次。新的空间合同见 [R01_MURAMASA_STYLE_REDESIGN_V01_CN.md](R01_MURAMASA_STYLE_REDESIGN_V01_CN.md)。

主角已新增第一版“下 + 跳跃”下穿当前承托平台的逻辑（`↓ + Space` 或 `S + Space`）。下穿平台应为独立的 `StaticBody2D`，否则临时碰撞例外可能影响同一物理节点上的其他平台。此功能及新路线均尚未通过 Godot 本地运行验收。不要把本文旧版地形说明视为新设计合同。
