## 1. 设计合同：严格保留草图的四个空间关系

- **左侧 A1 村庄入口**：从左侧进入，接到一条相对宽阔的主路。
- **中部岔路**：主路到达岔点后分成上行主路与下行瀑布支路；分岔必须在视觉上可读，不得用无意义的独立跳台填充。
- **右侧主路出口**：上行主路沿自然斜坡升高，抵达右侧中层出口（R03 钟墓上环）。
- **右上树冠层入口**：从中上部开始逐级攀升，形成明显高于主路的路线，连接 R02 树冠与断桥。
- **下方断水/瀑布区域**：下行支路进入低处水潭/断水区域，作为可选探索。R04 下坠触发只放在明确的下坠井，不把整条低路变成强制通道。

## 2. Godot 场景实现

运行时房间：`scenes/rooms/a2_fog_forest/runtime/a2_r01_room.tscn`

场景直接使用 Godot 可见节点：
- `Polygon2D`：远景山脊、遗迹剪影、地形实体、瀑布、树冠与前景根系。
- `Line2D`：地面轮廓与瀑布高光，强化斜坡方向和边缘。
- `StaticBody2D / CollisionPolygon2D`：主路、上升斜坡、树冠阶台、下层岔路与水潭平台。
- `Marker2D`：入口、出口、下坠点和设计落脚点。
- `Area2D / CollisionShape2D`：R01→R04 下坠转场。
- 主角、HUD、叙事层、调试标识和转场门仍作为场景树中的实例节点存在。

本版没有使用脚本在运行时生成固定地形节点。运行时脚本只负责 Hero 初始化、房间出口交互、存档状态与下坠转场。

## 3. 纵深效果的验证目标

这不是 3D 场景。空间感来自多个可独立调整的 2D 层：
1. 深色远景底色与远山剪影；
2. 中景废墟和低对比雾带；
3. 可实际站立的前中景地形；
4. 高处树冠/根系轮廓；
5. 前景根系遮挡角色下半部或局部路径。

验收时需要确认角色能在地形前后层之间移动时保持合理的可见性。若某个前景多边形永久遮住角色或遮挡关键落脚点，应调整该节点的形状和 `z_index`，而不是删除真实地形碰撞。

## 5. 实机验收标准

1. 从左侧入口可以沿主路抵达右侧中层出口，不需要二段跳。
2. 在中部能清楚看见上行路线与下行瀑布支路，玩家可以主动选择路线。
3. 树冠路由多级台面构成；各平台高度差须在 Hero 实测跳跃包络内，不可出现视觉相连但实际无法抵达的断点。
4. 中央遗迹是远近层次地标，不可误认为可站立平台；只有具备 `StaticBody2D` 碰撞的地形才可承托角色。
5. 下坠井只在主动落入指定区域时转场至 R04；低路平台不能误触发。
6. 远景、雾带、地形和前景根系在游戏画面中形成可辨识的空间层次；前景遮挡不能长期遮住角色。
7. 从 R02/R03 返回时落在对应可站立地形，而不是悬空或嵌入碰撞体。
