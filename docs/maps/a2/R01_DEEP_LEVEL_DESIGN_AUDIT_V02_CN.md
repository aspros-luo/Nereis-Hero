## 2. Godot 场景现在采用的结构

- `LevelIllustration`：编辑器可见的 `Sprite2D`，引用 1792 × 1200 的分层 SVG 插画；包装场景统一缩放 1.25 倍，最终覆盖 2240 × 1500 的房间范围。
- `Ground_West`：入口主地面。
- `Platform_001..Platform_031`：31 个独立的 `StaticBody2D`，每个有自己的编辑器可见 `CollisionShape2D`，可直接在 Scene 树中选中/移动/调整；薄平台使用单向碰撞，避免跳跃时撞到平台底部。
- `WestBoundary`、`EastBoundary`：房间左右边界。
- `RoomMarkers`：既有入口、出口、跨房间返回点和下坠井触发锚点。
- `FootingDesignMarkers`：5 个编辑器参考点，只用于与概念图对齐，不会显示成游戏 UI。

美术和碰撞解耦：插画负责连续的石壁、树根和背景轮廓；碰撞体规定实际可站立表面。纯装饰断桥没有碰撞节点，不能误把它当作必经地面。

## 4. 已修复的结构性问题

1. 不再以原本“稀疏平台 + 大面积纯色矩形”作为 R01 的主视觉。场景现在引用包含巨树冠层、粗根、远景废墟、中心石拱、非碰撞断桥、瀑布水潭与神殿高台的插画。
2. 真实可站立面单独建模，保留编辑器中的碰撞节点，不通过代码运行时创建地形。
3. 给五个落脚点加了 `Marker2D`，让程序可以在 Godot Scene 树中直接检查它们与参考图的对应关系。
4. 将 `DropToR04` 放在原场景坐标 `(1000, 780)`，与瀑布变细的暗缝对齐；包装场景统一缩放后，运行时触发器中心为 `(1250, 975)`。R01→R04 的触发区域为 32×120，范围窄于普通平台，避免把整段悬崖误当成安全落点。
5. 将西侧根台下层通道的插画净空扩至约 62 px，避免洞口视觉只像装饰裂缝。
6. 在 `scripts/levels/greybox_world_region.gd` 中为独立 A2 房间增加绘制早退。旧版运行时 `_draw()` 会绘制不透明灰盒背景和色雾层，可能盖住编辑器子场景里的远景与地形插画；现在 A2-R01 至 A2-R06 的可视地形由各自编辑器场景负责。
7. 静态校验器检查 23 个平台、碰撞资源、五个设计标记、扩展房间尺寸、瀑布落点坐标，以及 R01→R04 的 32×120 窄触发器合同。

### 当前诚实状态

本轮已提交房间范围、艺术缩放、瀑布暗缝、窄触发器与越界恢复逻辑；这不是“完整地形验收通过”。场景中已追加上层树根回环、中层遗迹支路、下层回程台阶与东侧树根支路；插画仍包含多层树根、遗迹、低层岔路、瀑布水潭与东侧神殿，但新增的 8 个平台目前是编辑器可见碰撞节点，静态结构审计已同步到 31 个平台；但它们与插画轮廓的逐点贴合、平台之间的跳跃可达性、镜头观感、下坠触发精度仍须在 Godot 4.6.1 实机确认。新增平台是拓展地形的第一步，不代表已证明形成完整回环。若实机发现暗缝触发面积偏大，应优先调整触发器宽度/高度和落点，而不是把整片下层区域设为安全落差。

## 7. 本轮验收门槛

最终将以下三种证据分开记录：

1. **静态结构检查**：资源路径、节点、Marker 和合同代码的文本检查。
2. **Godot 4.6.1 导入/解析**：打开和运行场景时无资源或语法错误。
3. **实机玩法验收**：玩家能走主路、下层支路可用，断桥/下坠触发符合设计，跨房间出生点安全。

本仓库当前已写入静态检查逻辑，但没有在用户本地 Godot 中运行过；SVG 实际渲染顺序、场景导入/解析以及第二、第三类验收继续标记为待验证。

## 8. R01 深度重构方向：二维玩法中的三维纵深（2026-10-26）

本节是下一轮实际地形修改的设计合同，不代表这些目标已经实现或验收通过。

### 8.1 美术参照与边界

用户明确要求将《奥丁领域》的二维舞台纵深感与 A1 村庄的既有场景观感作为 R01 的设计参照。采用的是空间表达方法，而非复制其美术资产或角色风格：

- **前景层**：近处枝叶、垂藤、树根、断柱形成局部遮挡；不得遮住致命落差、关键落脚边缘、必要入口或玩家角色的关键动作。
- **可玩中景**：所有真实可站立面仍由独立、编辑器可见的碰撞节点定义。视觉地形的顶边、宽度与碰撞体必须一一对应。
- **远景层**：树冠、雾中遗迹、瀑布岩壁与远处石造轮廓建立尺度和距离感；远景道路可以暗示空间延伸，但不能让玩家误认成可走路线。
- **空气透视**：远景降低对比和边缘锐度，中景保持落脚边缘清晰，前景以剪影或局部高对比塑造遮挡。不能仅靠给背景叠加雾层来冒充纵深。
- **A1 连续性**：沿用项目现有的手绘暗黑气质、轮廓和明暗逻辑；村庄与森林的空间语法要不同。村庄以人工建筑、道路和生活空间组织视线；R01 则让自然结构逐渐包围、切断和吞没人工遗迹。修改前仍须定位并检查仓库中实际的 A1 场景文件，不能仅凭路径猜测或假设 A1 的节点实现。

### 8.2 当前场景的真实问题（基于现有序列化场景的静态审查）

1. 当前房间插画仍以单个 SVG Sprite2D 呈现。即使 SVG 内部绘制了树木、雾和远景，它们也不是 Godot 中可独立调整视差、遮挡顺序或镜头响应的场景层。若继续只扩大这张插画，纵深会停留在“画出来的深度”，缺少可调节的舞台空间。
2. 当前 31 个平台是可编辑节点，但数量不证明路线有趣。部分新增平台的位置与既有平台非常接近，必须逐段核对其职责、落脚净空和回返意义，不能继续按数量堆平台。
3. Platform_012 位于原始场景坐标 x=960、y=672，跨度约 x=960–1096；DropToR04 在 (1000,780)。从静态坐标看，玩家若从该平台边缘离开，可能在触发器高度之前先落到平台或其碰撞范围。必须在 Godot 显示碰撞形状并实测；若阻断安全落差，应改造平台为两侧分离的石沿，而不是扩大触发区。
4. ExitTomb 与 EntryTombReturn 当前同在 (980,672)，ExitCanopy 与 EntryCanopyReturn 当前同在 (1520,480)。它们可能是有意的双向连接锚点，但要核对运行时是否根据进入方向选择正确出生点；不能仅因 Marker 存在就认为连接体验正确。
5. 目前没有可引用的 Godot 4.6.1 实机截图、跳跃轨迹或盲测结果。因此本节只记录可从场景文本确认的问题和待验证假设，不宣称可达性或视觉效果已经通过。

### 8.3 R01 应当让玩家经历的空间节奏

| 阶段 | 空间功能 | 纵深表达 | 玩家应获得的认识 |
|---|---|---|---|
| A. 森林入口 | 从 A1 进入后建立方向感 | 前景枝条短暂框住入口；中景地面清楚；远处出现巨树与断裂石构 | 玩家知道大致向东深入，但不会同时看清三条出口 |
| B. 被树根侵入的遗迹 | 第一次小规模探索与安全回返 | 根系跨越石墙，前景根须遮住部分上层通路 | 树根是可攀爬空间的视觉线索，不是所有根都能站立 |
| C. 中央遗迹庭 | 建立主要地标并形成路线选择 | 断桥、残柱和远景建筑形成前后重叠；断桥本身不作为碰撞地面 | 玩家理解此处曾是人工空间，但当前路线已破损 |
| D. 上层树冠支路 | 可选的高位绕行与观察点 | 从中景逐渐进入高位树根；向回看时能读懂下层空间 | 练习阅读垂直结构，并从高处看到右侧遗迹或瀑布的视觉线索 |
| E. 古墓外围 | 横向推进与建筑阅读 | 远处石造入口先露出轮廓，接近后才看到门框、残碑与真实入口 | 学会从人工结构辨认通道；入口不是一条无遮无挡的直线走廊 |
| F. 瀑布下层 | 风险判断与环境推理 | 水幕、岩壁和前景叶片分层；安全下坠的窄缝与普通危险落差在环境表现上有细微但可读的差异 | 玩家通过水流/雾气/声音变化推断暗缝，不靠 UI 提示或随机试跳 |

这些阶段是空间职责，不要求各自变成独立大房间；应优先利用现有地形重组路径，避免为每个阶段机械增加平台。

### 8.4 三条特殊连接的“可见—可推断—可抵达”链条

- **上方树冠 → R02**：先看见高处树根与枝桥轮廓；随后从可达的高台发现连续根系；最后通过有节奏的上行路线抵达连接点。远景枝桥不可直接冒充可站立平台。
- **右侧古墓 → R03**：先看见远处规则的石造轮廓；沿中景遗迹边缘推进时逐渐揭示墓门；入口前设置空间上的停顿或转折，让玩家确认这是一个地点，而非普通房间边界。
- **瀑布断流 → R04**：从主路或观察点至少能看到/听到一项可信线索；接近后出现水流、雾气或植被方向的异常；安全落差必须由可验证的几何走廊保护。其他落差保持死亡式黑屏恢复，不得因“看起来像瀑布”就全部变成安全通道。

每条连接都要满足：玩家第一次经过可以错过；之后回看能理解线索；找到入口是对观察或路线选择的奖励，而不是必须撞遍地图边缘。

### 8.5 探索乐趣不依赖敌人与收集物的地形机制

在地形验收阶段，使用以下机制而非敌人/NPC填充时间：

- **视线回报**：走到高处后，玩家能把之前看过的地标和下层路径重新拼起来。
- **短环路**：支路回到熟悉的中景地标，减少纯粹折返；每条环路必须改变实际走法，不只是在地图上画一条边。
- **安全观察点与危险落差的对照**：提供可停留观察的台面，也提供明确危险的断崖；死亡边界不能与可玩平台视觉混淆。
- **路线成本差异**：高位绕行应带来更好的视野或更安全的推进；低位路线应更直接但需要观察水系；不能只有一条“正确路线”。
- **空间记忆**：从入口能看到部分远景目标，从目标附近回看又能认出入口方向；使用形状、色块和地标建立记忆，而不是箭头和任务标记。
- **安静的叙事证据**：树根穿过石雕、被水侵蚀的台阶、朝向错误的旧路等，让环境暗示遗迹如何被森林改变；不加旁白解释。

### 8.6 下一轮执行顺序

1. **对照现有场景与插画**：逐个平台记录顶边坐标、宽度、对应视觉边缘、落脚净空、前后路径和是否有回程；先处理职责重复、平台封井和碰撞错位。
2. **审查 A1 的实际场景**：定位仓库里真正的 A1 场景与美术层结构，提取其层级、视差、遮挡和地形边界做法；不把 A1 结构猜测写成事实。
3. **重构 R01 空间草图**：先明确入口、中景庭院、上层树冠、古墓外围、瀑布下层之间的空间关系，再决定平台和前后景层；不以增加房间尺寸或平台数量作为完成标准。
4. **把视觉层拆为编辑器可调节的节点**：根据项目当前 Godot 4.6.1 资产管线，优先评估独立的远景、中景装饰和前景层；只有真正需要平铺/重复的地表才考虑 TileMapLayer，不为使用 TileMap 而使用 TileMap。
5. **逐层做可读性检查**：关闭前景、只看中景碰撞、只看远景时分别检查；恢复完整画面后确认前景不遮挡必要动作、远景不伪装可走平台。
6. **最后验证移动与路线**：先在编辑器显示碰撞体，再测跳跃、下坠、回返与三条跨区连接；任何静态 PASS 都不得代替实机证据。

### 8.7 可复现验收门槛

| 检查 | 通过条件 | 证据 |
|---|---|---|
| 场景结构 | 视觉层与碰撞层可独立选择；所有真实可站立面有明确碰撞节点 | Godot Scene 树与可视碰撞截图 |
| 纵深层次 | 至少能辨认前景、中景、远景；中景落脚边缘仍清晰 | 同一机位完整画面及分层关闭对照截图 |
| 平台对应 | 每个碰撞顶边都对应视觉承托面；无“看着能站却穿落”或“空气墙” | 可视碰撞截图、逐点清单 |
| 主路线 | 不依赖二段跳；无卡住、隐形天花板或不可恢复坠落 | 用户本地 Godot 4.6.1 实机录像/验收结果 |
| 三条特殊连接 | 各自具有视觉线索、合理发现顺序、正确出生点与返回规则 | 三条路线逐项测试记录 |
| 安全下坠 | 只有瀑布断流的窄安全走廊进入 R04；邻近落差触发死亡式恢复 | 正中、左偏、右偏下落测试记录 |
| 探索价值 | 至少一条实际短环路改变路线；高位观察能帮助理解低位空间 | 无设计说明的试玩者路线草图或口述记录 |

**本轮结论：**当前 R01 具备可编辑的碰撞节点与原创插画，但仍不能称为完成的纵深关卡。接下来的有效工作不是继续添加平台，而是先处理平台/瀑布井口的几何冲突风险、核实 A1 的真实场景实现，再把单张插画升级为可独立调节的多层舞台，并用真实移动测试证明探索网络成立。
