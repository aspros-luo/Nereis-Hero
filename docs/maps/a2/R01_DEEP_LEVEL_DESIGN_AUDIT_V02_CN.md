## 2. Godot 场景现在采用的结构

- `LevelIllustration`：编辑器可见的 `Sprite2D`，引用 1792 × 1200 的分层 SVG 插画；包装场景统一缩放 1.25 倍，最终覆盖 2240 × 1500 的房间范围。
- `Ground_West`：入口主地面。
- `Platform_001..Platform_031`：31 个独立的 `StaticBody2D`，每个有自己的编辑器可见 `CollisionShape2D`，可直接在 Scene 树中选中/移动/调整；薄平台使用单向碰撞，避免跳跃时撞到平台底部。
- `WestBoundary`、`EastBoundary`：房间左右边界。
- `RoomMarkers`：既有入口、出口、跨房间返回点和下坠井触发锚点。
- `FootingDesignMarkers`：5 个编辑器参考点，只用于与概念图对齐，不会显示成游戏 UI。

美术和碰撞解耦：插画负责连续的石壁、树根和背景轮廓；碰撞体规定实际可站立表面。纯装饰断桥没有碰撞节点，不能误把它当作必经地面。

## 4. 已修复的结构性问题

1. 不再以原本“稀疏平台 + 大面积纯色矩形”作为 R01 的主视觉。场景现在引用包含巨树冠层、粗根、远景废墟、中心石拱、非碰撞断桥、瀑布水潭与神殿高台的插画。
2. 真实可站立面单独建模，保留编辑器中的碰撞节点，不通过代码运行时创建地形。
3. 给五个落脚点加了 `Marker2D`，让程序可以在 Godot Scene 树中直接检查它们与参考图的对应关系。
4. 将 `DropToR04` 放在原场景坐标 `(1000, 780)`，与瀑布变细的暗缝对齐；包装场景统一缩放后，运行时触发器中心为 `(1250, 975)`。R01→R04 的触发区域为 32×120，范围窄于普通平台，避免把整段悬崖误当成安全落点。
5. 将西侧根台下层通道的插画净空扩至约 62 px，避免洞口视觉只像装饰裂缝。
6. 在 `scripts/levels/greybox_world_region.gd` 中为独立 A2 房间增加绘制早退。旧版运行时 `_draw()` 会绘制不透明灰盒背景和色雾层，可能盖住编辑器子场景里的远景与地形插画；现在 A2-R01 至 A2-R06 的可视地形由各自编辑器场景负责。
7. 静态校验器检查 23 个平台、碰撞资源、五个设计标记、扩展房间尺寸、瀑布落点坐标，以及 R01→R04 的 32×120 窄触发器合同。

## 4.1 本轮落差规则与扩展范围（2026-10-25）

### 空间合同

- R01 运行时范围：宽 2240、高 1500；艺术场景与全部编辑器碰撞统一缩放 1.25，避免只放大背景、却不放大碰撞的错位。
- 只有瀑布暗缝 `(1000, 780)` 对应的 32×120 `Drop_R01_to_R04` 可以进入 R04；运行时触发器必须检测到 Hero 正在下落。
- 其余越过房间底界的坠落，在 `room_height + 96` 之外进入死亡式黑屏恢复，并从 R01 西侧入口重来。
- 水潭边 `Platform_011` 已下移到原场景 y=900，避免横跨瀑布井口；瀑布井口不能再被一整块平台封住。
- 所有薄平台使用单向碰撞，防止从下方跳起时被平台底面挡住。单向碰撞不等于跳距已通过验证，仍需实机检查。

### 必须验证的反例

| 操作 | 预期结果 |
|---|---|
| 从瀑布暗缝正上方垂直下落 | 进入 R04，出生于 `a2_r04_tomb_drop_r01` |
| 从暗缝左侧或右侧相邻位置下落 | 不进入 R04；越界后黑屏并重生 R01 西侧 |
| 从最左/最右边缘掉出 | 不进入其他房间；黑屏后恢复 R01 |
| 在瀑布边普通平台上落地 | 留在 R01，不触发跨房间 |
| 从下方跳过 Platform_004/005 | 不被平台底面卡住，不出现隐形天花板 |
| 触发死亡恢复期间继续输入 | 不应重复触发场景切换或留下输入锁死 |

### 当前诚实状态

本轮已提交房间范围、艺术缩放、瀑布暗缝、窄触发器与越界恢复逻辑；这不是“完整地形验收通过”。场景中已追加上层树根回环、中层遗迹支路、下层回程台阶与东侧树根支路；插画仍包含多层树根、遗迹、低层岔路、瀑布水潭与东侧神殿，但新增的 8 个平台目前是编辑器可见碰撞节点，静态结构审计已同步到 31 个平台；但它们与插画轮廓的逐点贴合、平台之间的跳跃可达性、镜头观感、下坠触发精度仍须在 Godot 4.6.1 实机确认。新增平台是拓展地形的第一步，不代表已证明形成完整回环。若实机发现暗缝触发面积偏大，应优先调整触发器宽度/高度和落点，而不是把整片下层区域设为安全落差。

## 6. 已知范围外问题

A2 的若干旧 runtime wrapper 高度、floor_y 与 `tools/a2_room_connection_contract.json` 中的范围数据此前就不一致。本轮静态校验会把这些不一致标记为 warning，不将它们伪装成 R01 重建引入的问题。本轮不擅自修改 R02–R06 的地图范围，因为这样会改变其他房间相机边界和出生点行为，需要另外单独审计。

## 7. 本轮验收门槛

最终将以下三种证据分开记录：

1. **静态结构检查**：资源路径、节点、Marker 和合同代码的文本检查。
2. **Godot 4.6.1 导入/解析**：打开和运行场景时无资源或语法错误。
3. **实机玩法验收**：玩家能走主路、下层支路可用，断桥/下坠触发符合设计，跨房间出生点安全。

本仓库当前已写入静态检查逻辑，但没有在用户本地 Godot 中运行过；SVG 实际渲染顺序、场景导入/解析以及第二、第三类验收继续标记为待验证。
