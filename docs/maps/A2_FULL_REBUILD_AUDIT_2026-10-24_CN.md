# A2 六房间完整重建与审计记录（2026-10-24）

> 分支：`feature/story-map-progression`
> 状态：源码级检查与修正进行中；**尚未在 Godot 4.6.1 实机运行验收**。此文档不会把静态检查冒充为运行通过。

## 重建标准

- 六个房间分别是一段可以独立理解的横向关卡，而不是把一张总地图的轮廓切成六块。
- 每个房间有可辨识的主路、平台/地面节奏、局部探索支路与回程；各房间主题通过背景、地面材质和结构表现。
- 房间之间的门/坠落连接必须同时满足：源端可抵达、目标出生点落在有效地形上、返回路径可走、摄像机边界覆盖实际地形。
- 视觉背景只负责层次，不承担碰撞；所有可站立地形应在编辑器中以可见的 StaticBody2D / CollisionShape2D 节点维护。
- 地图完成前暂不以敌人数量、掉落物数量或剧情节点填充来掩盖地形问题。

## 本轮实际源码修正

### 1. R03 的坠落口重新打通

此前 R03 的两段底层地面在 x=350 处接成连续地面，覆盖了 `DropToR04` 标记所在的 x≈425；即使生成了坠落触发区，玩家也无法从正常站立地面落入坑底。

已调整为：
- 西侧地面：x=0..350。
- 东侧地面：x=500..1280。
- 中间 x=350..500 保留约 150px 坑口，和 `DropToR04` 触发区对齐。
- 东侧地面碰撞、Polygon2D 和顶边线长度同步为 780px。

提交：`274b2b7d2884dfe517125afca9dc6bdbae803c75`

随后复核发现：东侧地面的碰撞长度已是 780px，但 Polygon2D 与顶边线仍保留 930px，视觉上会把坑口后方画成连续地面。已同步将两者改为 780px，避免视觉地形与碰撞不一致。

提交：`f8fea280ba6876e44048c320528c398960ecbe33`

### 2. R06 的下层裂谷入口不再被整段地板封死

此前 `Ground_East` 从 x=0 延伸到 x=1280，位于 y=485；而 `RavineLowerShelf`、`EntryRavineReturn` 和 `ExitToR04` 位于 y≈610。整段碰撞地板会把下层平台封在地板下面，低入口不能按设计到达。

已把地面拆成两个编辑器可见的静态地形段：
- 西段：x=0..200。
- 裂谷开口：x=200..450。
- 东段：x=450..1280。
- 两段分别维护碰撞形状、地形 Polygon2D 和顶边线，开口上方不再绘制连续地面。

提交：`59f1f3cee747ef91e213fb10456df75926a22652`

### 3. R06 场景资源计数同步

R06 在增加地面段后，`.tscn` 的 `load_steps` 必须与子资源数量同步。现已按 29 个 sub_resource + 场景本身，将 `load_steps` 调整为 30，避免场景资源声明与实际资源数量不一致。

提交：`0b640acbfdc00052919419b83ddd6e373624d710`

## Godot 实机验收顺序

1. 先用 Godot 4.6.1 打开项目，确认六个 authored room 场景在编辑器中可见节点，不是运行时纯代码拼图。
2. 从 A1 的 A2 入口进入，确认初始房间为 R01，角色落在西侧地面。
3. R01→R02→R01，检查树冠入口和返回出生点；再从 R01 进入 R03。
4. 在 R03 从上层路线走到坑口，确认能落入 R04；从 R04 回 R03，再从 R04 进入 R06 低路。
5. 在 R06 从上层走到裂谷开口并落到下层 shelf，确认可回上层并能返回 R04。
6. 从 R02/R03 进入 R05，逐一检查 R05 的返回点和 R06 高入口；最后检查 A3/A5 外部连接。
7. 每次转场观察输出日志：不得出现 `MARKER_MISSING`、`EXIT_ANCHOR_INVALID`、`DROP_ANCHOR_INVALID` 或场景解析错误。
8. 逐房间确认摄像机边界、地面碰撞、出生点高度与安全返回路线；发现问题记录具体房间、入口方向和截图再修。

### 4. R06 房间根偏移与低层相机裁切

R06 authored root 的 `position.y=325`。上层主地面局部 y=485，对应世界 y=810；下层 `RavineLowerShelf` 与 `ExitToR04` 局部 y=610，对应世界 y=935。wrapper 原先 `floor_y=485`，会让环境层和缺失 marker 时的 fallback 高度错误；`room_height=900` 又会把相机下边界设在低层 shelf 上方。现已改为 `floor_y=810`、`room_height=1100`，确保相机范围覆盖下层路线。另发现 `EntryLow` 原先落在上层主地面（局部 y=490），与“低路入口”语义不符；已将其移动至局部 y=610，对齐下层 shelf 顶面及 R06→R04 的回程标记。

提交：`955e3694`（floor_y），`13e57bbd`（room_height），`d53b049c`（EntryLow 落点）。仍需 Godot 实机确认镜头跟随与落地。

### 4. R04 / R05 缩放场景的出生高度偏差

检查根节点变换后发现，R04 与 R05 的房间根节点不仅有缩放，还有 y 偏移：
- R04：scale=(2.2, 1.35)，position.y=73；主地面 y=380，实际世界高度为 73 + 380×1.35 = 586。wrapper 原先 floor_y=513，会让备用出生高度、房间内容与休息点参考高度偏低。
- R05：scale=(1.7, 1.25)，position.y=95；主地面 y=380，实际世界高度为 95 + 380×1.25 = 570。wrapper 原先 floor_y=475，同样漏算了根偏移。

已修正：
- runtime/a2_r04_room.tscn: floor_y=586
- runtime/a2_r05_room.tscn: floor_y=570

提交：R04 500e743627d41cc05915d9b062a60113e0311d90；R05 9781c48c7f50138b068d003d338cca4273852a39。
