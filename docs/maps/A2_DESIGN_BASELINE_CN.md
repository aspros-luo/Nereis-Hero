# A2 当前设计基线：雾林与钟墓

> 状态：当前实施基线（2026-10-24）
> 分支：feature/story-map-progression

## 1. 设计目标

A2 是一个具有森林地表、树冠高路、古代钟墓垂直空间、下层沟壑和回返路线的非线性区域，不是从 A1 到 A3 的短平台走廊。地图必须给玩家多方向探索、可见但暂不可达目标、回环、捷径和有意义的高差。地形阶段不放敌人或 NPC。

## 4. 房间架构决策

- 六个房间是独立 .tscn，地形、StaticBody2D、CollisionShape2D 与可视节点必须能在 Godot 编辑器中直接查看和修改。
- scenes/ash_forest.tscn 当前仍把六个房间装配成同一张 A2 大地图；这只是现状，不是目标架构。
- 目标是 A1 北门进入 R01，R01–R06 之间通过真实出口/入口和明确落点转场；不能以父场景中的六个实例替代独立房间连接。
- 逐项核实 Canva 空间关系与拓扑总账后，建立房间连接表：源房间/出口、目标房间/入口、落点、方向、单向性、条件、返回规则、验收 ID。
- 保留 C03、C04、H02、WorldState、检查点、死亡恢复、Continue/存档和既有跨区连接合同。
- 不改变 A0/A1 设计，不擅自改变世界级拓扑。A1 入口路由修改仅限于让其进入 A2 R01，并需保证返回方向与存档恢复正确。

## 5. 正反方裁定

**正方：** 独立房间让地形可以逐图精细设计、局部验收与迭代；入口/出口和落点能对应具体空间，不再让六个设计职责被一张父场景的连续坐标掩盖。

**反方：** 房间切换会增加边界处的镜头重置、出生点、持久状态、跨区出口、死亡恢复和存档恢复风险。单纯切换场景而不做连接合同会制造软锁、重复触发或状态丢失。

**裁定：** 采用独立房间与真实转场；先建立连接合同和共享转场适配，不把每个房间复制成独立的完整游戏根场景，也不通过降低断言来使检查通过。任何关键连接没有可核实落点时先暂停该连接实现，不猜坐标。
