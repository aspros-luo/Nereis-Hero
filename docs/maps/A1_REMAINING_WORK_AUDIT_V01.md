## 开发约定

1. 固定地形、背景、建筑、平台、门、交互点、出生锚点优先直接写入 `.tscn`，由 Godot 编辑器中的节点树维护。
2. 灰盒优先用 `Polygon2D`、`ColorRect`、`Line2D`、`StaticBody2D`、`CollisionShape2D`、`Area2D`、`Label` 等节点。现有贴图通过 `Sprite2D` 等节点使用，不用 `draw_texture_rect()` 重建场景。
3. 脚本负责交互、剧情状态、保存、条件显隐和转场；不在 `_ready()` 中手工拼整张地图。条件变化用已预置节点的 `visible`、`monitoring` 等属性切换。
4. NPC 和隐藏入口的状态可以由数据/事件管理器驱动；角色造型、地标、标签和交互提示仍应来自可复用场景/节点，而不是 `_draw()`。
5. 保留 C01/C02/C06/H01/C24 及 H09 的既有连接与剧情合同；A1.1 是教堂、酒馆和后山路线，不恢复旧屋顶路线。

## 工作包与顺序

### P0 — 清除 A1 地图的代码绘图

1. 将 A1.0 背景贴图迁为场景节点（如 `Sprite2D`）；背景与前景分层可在编辑器中调整。
2. 将地面断口、下层石沿、接缝迁为可编辑节点；保证可见边界与 `StaticBody2D` / `CollisionShape2D` 完全一致。
3. 把旧排水口、堵塞碎石、炉火、北门、营地帐篷/火堆等固定轮廓做成场景子节点。只用剧情旗标切换 `BlockedState` / `OpenState`、营地显隐，不能从脚本重新绘制。
4. 把 A1.0 / A1.1 的所有地图区域标题迁为 `Label`；目标是两张地图根脚本都不再用 `_draw()` 绘制地图。

### P1 — 将 A1 结构与固定交互锚点放进场景树

1. 统一 A1.0 的 Hero/碰撞体/Camera 与 A1.1 结构；保留各入口安全出生位置。
2. 把检查点、炉火休整点、Mite 房门、墓地/北门/低位排水支路等固定交互锚点改为 `.tscn` 节点或可复用 PackedScene 实例。
3. 将 A1.0 的 Mite、常驻居民、商人、铁匠、守门人等固定位置声明在场景树内；对话仍读 WorldState，允许按剧情状态隐藏或切换实体。
4. 将复国军营地的固定视觉与 POI 预置在场景树中，只在 `restoration_camp_established` 后启用；不可由“村庄防卫战完成”自动推断营地到达。

6. H09 继续使用 `returned_to_village_after_mad_cleric` 旗标与现有 `cliff_cave_experiment.tscn` 目标；补全并验收入口门体视觉和触发区域。
