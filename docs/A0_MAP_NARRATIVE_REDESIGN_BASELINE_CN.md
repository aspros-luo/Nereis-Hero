# A0 地图叙事与序章重构基线（2026-10-30）

> 状态：用户已确认设计方向；本文记录设计目标与源码差异，尚未实施场景/代码重构，也未进行 Godot 实机验收。
> 分支：feature/story-map-progression
> 范围：A0-S01、A0-S02、洞外教会执行者、A0→A1 转场、统一通知控件与全局成就档案。
> 优先级：不得破坏用户已实机确认正常的 A0→A1 基础流程。

## 1. 用户已确认的设计目标

### 1.1 A0 空间与氛围

- A0 整体设定为大型地下研究设施，处于半停摆状态；但 **S01 不扩大现有地图规模**。当前 A0 的空间规模与基本布局已经满足需求，只做必要优化，避免过大的探索空间过早暴露过多信息。
- 洞穴部分拆分为两个独立场景：
  - **A0-S01：现有地下设施探索区**。沿用当前地图规模与主要布局，负责苏醒、拾取其他物品、找回主角自己的长剑，并通往逃生出口；只做必要的叙事、交互和场景衔接优化。
  - **A0-S02：洞穴逃亡与三人埋伏区**。负责逃亡途中遭遇三名埋伏者。战斗空间应比当前版本适度拉宽，给玩家留出横向移动、后撤、拉开距离和调整站位的余地；不因此扩建整个 S01 或增加无意义房间。
- S01 与 S02 必须是独立场景，不能只在同一场景内用门/触发器分隔。

### 1.2 武器获得与切换

- A0 初始没有可切换的第二武器。
- 主角在 S01 找回自己的长剑后，长剑可用。
- 在 A1 完成北门盗贼流程并获得短刃之前，短刃不可用，也不可切换到短刃。
- 完成北门盗贼流程、取得报酬并通过交易获得金正的短刃后，才开放长剑/短刃切换。
- 未解锁第二武器时，切换输入应有简洁、明确的系统反馈，不应表现为输入失灵。

### 1.3 洞外教会执行者

- 执行者必须可以受到真实伤害，Boss HUD 位于屏幕底部，显示血条与名称；首次遭遇名称显示为 ???。
- 玩家可将执行者血量打至 0；血量归零后，教会追兵介入，使用类似圣光/治疗术的效果将执行者生命值恢复至满值。
- 若玩家未能将血量打至 0，追兵也必须在明确的战斗阶段/条件介入，不能用过短倒计时任意打断玩家。
- 执行者恢复后，主角判断继续战斗无胜算，主动跳下右侧悬崖。
- 不论玩家在追兵介入前是否将执行者打至 0，都进入同一段悬崖跳落与黑屏转场，最终抵达 A1。
- 允许用镜头、角色动作、淡出、声音和黑屏完成演出，不要求完整 CG；禁止用解释性旁白讲解撤退原因。

### 1.4 物品与成就通知

- 物品拾取通知显示在屏幕右上角，只显示物品名称与获得数量；物品描述仅在背包查看。
- 成就解锁通知与物品拾取通知共用同一套右上角通知控件/视觉组件和队列。
- 连续触发应排队或合并，不能互相覆盖。
- 成就记录属于全局玩家档案，不属于任何一个存档槽。
- 已获得的成就在新开档、删除/切换存档后仍保留，且不能再次解锁或重复播放通知。
- 同设备本地全局档案与跨设备/重装保留是不同范围；后者需要平台成就或云同步，不能仅凭本地文件承诺。

- 当前 S01 仍承担出口触发后的三人守卫伏击；用户要求将伏击迁移为独立 S02。迁移时应适度增加战斗区域横向空间，重点解决当前战斗过于紧促、体力受限时容易被围攻击败的问题。

### 2.2 执行者与追兵

- scenes/enemies/a0_church_executioner.tscn 当前设置 damage_immune=true、health=900、max_health=900，违背“可真实造成伤害”的新要求。
- scripts/levels/prologue_exterior.gd 当前有 12 秒必败计时；主角接近执行者后计时结束会直接进入转场。Boss 被击败信号与主角死亡也进入同一转场。
- 当前悬崖是限制主角越过的强制败北边界，不是玩家主动跳落的路线。
- 当前追兵通过 prologue_pursuer.gd 作为纯视觉剪影显示，不参与治疗或战斗；需扩展为可读的追兵介入与治疗演出。
- game_hud.tscn 已有 BossPanel/BossBar/BossTitle 节点，优先复用现有 HUD，检查其绑定与布局是否符合底部显示、??? 初始名称及治疗回血动画。

### 2.3 物品拾取与通知

- scripts/world/world_item_pickup.gd 当前拾取后调用拾取面板的 show_pickup(item_name)，未传入数量。
- scripts/ui/item_inspection_panel.gd 的 show_pickup 会打开描述面板、锁定输入并暂停游戏；这与右上角轻量通知不符。
- show_description 可继续用于玩家主动查看物品/背包描述；拾取本身应改为非暂停通知。
- scripts/core/achievement_manager.gd 当前运行时创建独立 AchievementToast，与物品面板不是同一通知控件；需要重构为统一通知组件/队列。
- 通知展示失败不能影响物品入包或成就解锁。

### 2.4 成就持久化

- AchievementManager.unlock() 调用 WorldState.record_achievement()。
- WorldState.achievement_flags 当前被写入 user://nereis_hero_save.json，并随该存档读取；因此成就现在是存档级，不满足跨存档全局唯一要求。
- 后续应迁移为独立全局档案文件，采用独立版本字段、原子写入与备份恢复；迁移时合并现有存档中的 achievement_flags，避免玩家已获得成就丢失。
- 成就检查/解锁必须只以全局档案为权威；普通存档不再决定是否可重复获得。
- 迁移时必须先成功写入全局档案，再移除或忽略旧存档字段；不能直接清空旧数据。

## 3. 设计裁定与风险

### 采纳

- 采纳 S01/S02 场景拆分；S01 保持现有规模，不进行整体扩建。
- S02 伏击战斗区适度拉宽，增加战斗走位空间；调整幅度以改善可操作性为准，不以单纯扩大面积为目标。
- 采纳执行者可受伤、血量归零后由追兵治疗回满、主角主动跳崖、统一黑屏进入 A1 的流程。
- 采纳物品与成就共用右上角通知控件。
- 采纳全局成就档案，独立于存档槽。

### 反方风险与约束

- **Boss 战斗**：玩家不打 Boss、绕过 Boss、将 Boss 打至 0 三种路径都必须稳定汇合；介入触发不能只依赖固定短计时。执行者恢复后必须有治疗保护，避免玩家在治疗动画中再次打空血条导致循环。
- **场景拆分与战斗空间**：迁移三名伏击者时需保留 AI、出生位置、路线约束、死亡重生与检查点语义；S01/S02 的存档恢复映射必须一起更新。S02 拉宽后要重新验证三名敌人的包夹距离、移动速度、攻击覆盖与玩家闪避/后撤空间，不能只扩大地形却保留不合理的敌人压迫参数。体力系统仍按既有设计运行，但玩家应有机会通过走位管理体力，而不是因场地狭窄被迫连续消耗。
- **武器状态**：长剑获得、短刃解锁、当前武器样式和输入反馈必须与旧存档兼容；不能因 A0 重构提前开放 A1 北门流程。
- **成就迁移**：旧成就只在存档内。多个旧存档可能拥有不同成就集合，迁移时应合并所有可发现的旧记录；不能让普通新游戏覆盖全局成就。
- **通知队列**：拾取/成就可能在暂停、场景切换或多个事件同帧发生；通知独立排队，展示失败不回滚游戏状态，也不暂停游戏。
- **演出**：黑屏转场需确保输入锁、摄像机、音效、Boss/追兵释放和 A1 出生侧状态一致；至少保留主动跳落与坠落声音，避免黑屏显得毫无因果。

## 4. 后续实施顺序

1. **A0 场景/空间蓝图**：先核对现有 S01，保持其规模与主要布局，只确定必要优化、长剑位置和出口衔接；再调整 S02 逃亡路径与三人埋伏区的横向宽度，验证玩家在体力限制下有足够的走位和脱离围攻空间。固定地形必须由可见 .tscn 节点构成。
2. **场景与存档合同**：确定旧 escape_prologue、新 S01/S02、prologue_exterior 的场景 ID、进入点、返回点、死亡/继续游戏映射。
3. **战斗与转场**：修复执行者伤害、Boss HUD、追兵治疗、主动跳崖和统一转场；覆盖 Boss HP=0 与 HP>0 两条路径。
4. **武器解锁**：核对长剑拾取与 A1 短刃交易的实际状态入口，封闭提前切换路径。
5. **统一通知控件**：复用右上角布局，接入物品名称/数量和成就解锁通知；保留背包描述查看。
6. **全局成就迁移**：建立独立全局档案，迁移旧存档成就并覆盖多存档回归。
7. **文档与验证**：每次代码/场景变更同步更新本文与相关合同；执行静态检查、Godot headless 检查和用户本地实机验收。未运行的项目不得标为通过。

## 5. 额外场景演出要求

- 当前伏击后 S01 左侧以不可见空气墙阻挡玩家。用户希望改为**伏击触发后，一堵真实的实体墙从上方/侧方落下封住左侧通路**，以场景内可见的物理变化解释封锁。
- 实体墙必须预先作为可见节点存在于 `.tscn` 中，使用 `AnimationPlayer` 等方式驱动其落下；允许代码改变预制节点状态/播放动画，不允许运行时创建墙体或碰撞地形。
- 墙体碰撞应与动画时序一致：落下前不能提前形成看不见的阻挡；落地后再可靠封闭通路，并避免穿透、夹人或玩家被卡在墙体内。
- 墙体最终归属 S01 还是 S02，需在检查当前场景边界与 S01/S02 切分点后决定，不能先验假设。

## 7. 当前场景结构复核（2026-10-30，源码静态审计）

> 本节依据分支 `feature/story-map-progression` 当前提交 `537e63e9b8b6fe3885c8d887f564c196c1a93b99` 的远程源码读取。它是源码结构审计，不是 Godot 运行时验收。

### 7.1 S01 现状与拆分边界

- 当前实际入口仍是 `scenes/regions/escape_prologue.tscn`，场景约 2200×720，包含 62 个场景节点；固定地面、边界、手术台、六个平台、拾取点、检查点、伏击触发器、敌人出生标记和闸门实例均可在场景文件中看到。
- 因此旧文档中“整个 A0 由脚本运行时生成、编辑器里只有根节点”的描述已过时，不应再据此重做地形。
- 当前场景仍把探索、三人伏击和洞外出口串在同一个 S01 场景流程中；尚不存在独立的 A0-S02 场景。
- 现有探索平台最右端约 x=1160；左侧伏击闸门实例中心约 x=1320；伏击触发器中心约 x=1728；敌人出生标记约为 x=1425、x=2075、高处 x=1480；右侧闸门关闭阈值约 x=1960；当前出口交互点约 x=2040。
- **建议的最小风险切分位置**：在现有探索平台结束后、左侧伏击闸门之前切分（约 x=1160–1320 的过渡带）。S01 保留现有手术室/探索布局；S02 接管逃亡通道、三人伏击、战斗闸门与洞外出口衔接。该范围是根据当前节点坐标提出的实现候选，仍需检查背景图、相机边界、地面连续性、检查点和死亡恢复合同后才能定稿。
- S02 的战斗区只需在当前伏击区域基础上适度拉宽。不要将 S01 整张地图扩大，也不要为了凑长度增加无功能房间。

### 7.2 左侧“空气墙”的实际来源

- 当前 `ProgressBarrier_Left` 是预制场景 `scenes/rooms/prologue_progress_barrier.tscn` 的实例。该预制场景已经包含可见的闸门面板、装饰线条和碰撞体；不是必须新建一套墙体资源。
- 但当前流程在伏击触发时直接把它设为 visible，并立即启用碰撞，没有落下动画；玩家因此感受到的是突然出现的阻挡，缺少物理变化过程。
- 应复用/改造该预制实体：预先放置在可见场景树中但处于抬起/隐藏的待机位置；伏击发生后由 AnimationPlayer 驱动它落下；碰撞只在落地阶段启用。不能让碰撞在视觉墙体落下前提前阻挡玩家。
- 需要检查墙体与玩家相交时的安全性，避免落下时夹人、推入地形或把玩家锁在错误一侧。左侧墙的具体归属应随 S01/S02 切分结果决定。

### 7.3 伏击战斗与体力基线

- 当前三名守卫并非同一时间全数压上：前两名先出现，全部击败后第三名从高处进入；敌人脚本还包含攻击前摇、冷却和附近敌人攻击错峰逻辑。这些节奏设计应迁移保留。
- 玩家当前基础数值包括：最大体力 100、普通攻击消耗 12、闪避消耗 28、体力恢复延迟 0.65 秒、恢复速率 42/秒；普通移动速度 260、闪避速度 620、闪避持续 0.18 秒。三名守卫单次攻击伤害为 15。
- 这意味着玩家最多只能连续进行有限次数的闪避；如果战斗空间太窄，玩家即使正确识别前摇，也可能因缺少脱离围攻的距离而被迫连续消耗体力。
- S02 调整应优先给出清晰的左右移动余地和可预测的敌人接近路线；保留敌人错峰进攻，不要通过单纯降低敌人伤害掩盖空间问题。最终宽度与敌人站位必须结合实机测试决定，不能仅凭坐标推断平衡完成。

### 7.4 长剑获得状态的现状差异

- 当前 `escape_prologue.tscn` 只有绷带、手术记录残页与手术痕迹调查点，没有主角长剑的场景拾取节点。
- 当前 `WorldState.current_weapon_style` 默认值为 `long_sword`，旧存档缺省值也回落到 `long_sword`；因此现有系统状态并不能证明玩家在 S01 实际找回了长剑。
- S01/S02 拆分前必须补齐明确的长剑获得状态：玩家在 S01 与自己的长剑发生拾取/装备交互后才记录已获得，并确保旧存档兼容；不能只把默认武器样式当作拾取事实。
- `scripts/player/hero_system.gd::switch_weapon()` 当前直接在长剑与短刃之间切换，并写入 `WorldState.current_weapon_style`，未检查短刃是否已解锁；因此“必须完成 A1 北门盗贼流程并交易后才能切换”的限制目前也未落实。
- `scripts/levels/village_hub.gd` 当前北门 POI 指向 A2 R01，已读取村庄防卫结果改变名称/对白；本轮检索未发现它承担短刃奖励交易或武器解锁。北门盗贼流程、奖励和金正交易的真实入口仍需继续追踪，不能仅凭 POI 名称认定功能已存在。
- 后续必须区分“拥有长剑”“当前装备长剑”“拥有短刃”“允许切换短刃”四种状态。旧存档若已使用短刃，应兼容保留；新开档则不得因默认 `current_weapon_style = long_sword` 被误判为已经拾取长剑。
