# A0 地图叙事与序章重构基线（2026-10-30）

> 状态：S01 横向结构简化已落地；洞外结尾已接入飞龙掠过、山路崩塌与坠落转场的源码原型。当前仅完成远程源码静态核对，尚未进行 Godot 4.6.1 场景解析与实机验收。
> 分支：feature/story-map-progression
> 范围：A0-S01、A0-S02、洞外教会执行者、A0→A1 转场、统一通知控件与全局成就档案。
> 优先级：不得破坏用户已实机确认正常的 A0→A1 基础流程。

## 1. 用户已确认的设计目标

### 1.1 A0 空间与氛围

- A0 整体设定为大型地下研究设施，处于半停摆状态；但序章 S01 只展示其中一个局部，不解释设施全貌和研究目的。
- **A0-S01：单一横向手术所场景**。以一张完整的大型背景图建立空间氛围，地面保持连续平坦；玩家从左侧苏醒，沿横向向前探索，在少数固定地点发现零散物品与线索，最后从出口进入 S02。它不是房间迷宫，也不是平台跳跃关卡。
- S01 不设置六段跳台、垂直路线、复杂支路或为增加时长而堆砌的房间。固定地形只保留必要的连续地面、边界和确有实体意义的物件碰撞；物品与线索通过场景节点放置，不能用代码生成地图。
- **A0-S02：独立的洞穴逃亡与三人埋伏场景**。负责逃亡途中遭遇三名埋伏者；战斗空间应给玩家横向移动、后撤和调整站位的余地，不因此扩建 S01。
- S01 与 S02 必须是独立场景，不能只在同一场景内用门/触发器分隔。

### 1.2 武器获得与切换

- A0 初始没有可切换的第二武器。
- 新游戏开始时主角没有武器；S01 中不要求玩家额外寻找或手动拾取长剑。主角尝试打开手术室出口、准备逃离时，触发场景内长剑发现事件，自动获得并装备这柄属于主角的长剑。
- 在 A1 完成北门盗贼流程并获得短刃之前，短刃不可用，也不可切换到短刃。
- 完成北门盗贼流程、取得报酬并通过交易获得金正的短刃后，才开放长剑/短刃切换。
- 未解锁第二武器时，切换输入应有简洁、明确的系统反馈，不应表现为输入失灵。

### 1.3 洞外教会执行者与飞龙介入

- 洞外山路保留一场教会执行者战斗；首次遭遇名称显示为 `???`，不显示头顶名字，复用现有底部 Boss HUD。
- 执行者可以受到真实伤害。玩家将其 HP 打至 0 时，追兵介入并治疗；若玩家将其压至第二阶段门槛（50% HP）仍未击败，追兵也会介入。若玩家持续回避战斗，则在遭遇正式开始 30 秒后触发同一介入，避免玩家无限等待或绕过流程。
- 追兵治疗期间执行者停止攻击并获得伤害保护，治疗完成后生命值恢复至满值；随后执行者会短暂恢复战斗，飞龙在这段重新交手中介入。复原后若玩家再次击败执行者，也会汇入飞龙坍塌流程，不会出现第二轮无限治疗。
- 飞龙在山谷上空自然掠过，不锁定主角、不攻击执行者、不帮助任何一方；它不与古神、教会实验、主角身份或命运建立特殊因果。
- 飞龙袭击山体/山间道路，先出现岩壁裂缝，再有多块岩石向外崩飞、坠落，尘土扩散；山路失去支撑并整体崩塌。主角因脚下地面消失而坠落；不再保留主角主动跳崖或主动起跳的演出。
- 飞龙只在 A0 展示体型、飞行与环境破坏能力，不进入可战斗状态、不显示 Boss 血条；正式 Boss 战保留给 A7「瞭望深谷」。
- 追兵应从主角身后的洞穴口出现，形成前后夹击的空间关系；其职责是封住退路并参与治疗/结尾演出，不额外开启一场追兵战斗。
- 洞外山路战场应比当前原型更长：主角出生点与洞口分开，执行者向河谷方向后移，保留洞口后方、主战场与悬崖前沿三个清楚的空间段落。
- 主角战败路径保留现有成就提示与 3.2 秒现场停留，然后也进入飞龙袭击/道路崩塌演出，避免战败路径绕过新的序章结尾。
- 坠落镜头必须持续足够时间，让玩家看到主角进入深谷；洞外背景需延伸到坠落镜头范围，避免摄像机追随时露出空白。下坠结束后保留短暂空中停顿，再使用较慢淡出、黑场停留与淡入进入 `res://scenes/mite_house.tscn` 的西侧出生流程；该场景是 A1 的首次落点，之后由住所出口进入村庄主场景。不得将它误写为直接加载 `village_hub.tscn`。
- 禁止解释性旁白；演出只用飞龙掠影、追兵动作、道路破坏、镜头震动与坠落表现事件。

### 1.4 物品与成就通知

- 物品拾取通知显示在屏幕右上角，只显示物品名称与获得数量；物品描述仅在背包查看。
- 成就解锁通知与物品拾取通知共用同一套右上角通知控件/视觉组件和队列。
- 连续触发应排队或合并，不能互相覆盖。
- 成就记录属于全局玩家档案，不属于任何一个存档槽。
- 已获得的成就在新开档、删除/切换存档后仍保留，且不能再次解锁或重复播放通知。
- 同设备本地全局档案与跨设备/重装保留是不同范围；后者需要平台成就或云同步，不能仅凭本地文件承诺。

### 2.3 物品拾取与通知

- scripts/world/world_item_pickup.gd 当前拾取后调用拾取面板的 show_pickup(item_name)，未传入数量。
- scripts/ui/item_inspection_panel.gd 的 show_pickup 会打开描述面板、锁定输入并暂停游戏；这与右上角轻量通知不符。
- show_description 可继续用于玩家主动查看物品/背包描述；拾取本身应改为非暂停通知。
- scripts/core/achievement_manager.gd 当前运行时创建独立 AchievementToast，与物品面板不是同一通知控件；需要重构为统一通知组件/队列。
- 通知展示失败不能影响物品入包或成就解锁。

### 2.4 成就持久化

- AchievementManager.unlock() 调用 WorldState.record_achievement()。
- WorldState.achievement_flags 当前被写入 user://nereis_hero_save.json，并随该存档读取；因此成就现在是存档级，不满足跨存档全局唯一要求。
- 后续应迁移为独立全局档案文件，采用独立版本字段、原子写入与备份恢复；迁移时合并现有存档中的 achievement_flags，避免玩家已获得成就丢失。
- 成就检查/解锁必须只以全局档案为权威；普通存档不再决定是否可重复获得。
- 迁移时必须先成功写入全局档案，再移除或忽略旧存档字段；不能直接清空旧数据。

## 3. 设计裁定与风险

### 采纳

- 采纳 S01/S02 场景拆分；S01 定为单一横向背景场景，连续平地、少量零散物品/线索、单一出口；六个平台与无意义垂直路线废止。
- S02 伏击战斗区适度拉宽，增加战斗走位空间；调整幅度以改善可操作性为准，不以单纯扩大面积为目标。
- 采纳执行者可受伤、追兵治疗复原、飞龙自然掠过并袭击山体、道路崩塌导致主角坠落、统一黑屏进入 A1 的流程；取消主角主动跳崖。
- 采纳物品与成就共用右上角通知控件。
- 采纳全局成就档案，独立于存档槽。

### 反方风险与约束

- **Boss 战斗**：玩家不打 Boss、绕过 Boss、将 Boss 打至 0 三种路径都必须稳定汇合；介入触发不能只依赖固定短计时。执行者恢复后必须有治疗保护，避免玩家在治疗动画中再次打空血条导致循环。
- **场景拆分与战斗空间**：迁移三名伏击者时需保留 AI、出生位置、路线约束、死亡重生与检查点语义；S01/S02 的存档恢复映射必须一起更新。S02 拉宽后要重新验证三名敌人的包夹距离、移动速度、攻击覆盖与玩家闪避/后撤空间，不能只扩大地形却保留不合理的敌人压迫参数。体力系统仍按既有设计运行，但玩家应有机会通过走位管理体力，而不是因场地狭窄被迫连续消耗。
- **武器状态**：长剑获得、短刃解锁、当前武器样式和输入反馈必须与旧存档兼容；不能因 A0 重构提前开放 A1 北门流程。
- **成就迁移**：旧成就只在存档内。多个旧存档可能拥有不同成就集合，迁移时应合并所有可发现的旧记录；不能让普通新游戏覆盖全局成就。
- **通知队列**：拾取/成就可能在暂停、场景切换或多个事件同帧发生；通知独立排队，展示失败不回滚游戏状态，也不暂停游戏。
- **演出**：飞龙不能被塑造成救援者或剧情工具；必须先让玩家看见自然飞越，再呈现山体受击、碎石覆盖道路、地面失去支撑和坠落。黑屏转场需确保输入锁、摄像机、Boss/追兵释放和 A1 西侧出生状态一致。

## 4. 后续实施顺序

1. **A0-S01 简化**：保持单一横向场景和既有大背景，不再设计房间迷宫；移除无意义平台，确保所有保留物品/线索从连续地面可到达；核对背景画布、出口与边界闸门的视觉关系。然后再审计 S02 战斗空间与三人埋伏路线。固定地形必须由可见 .tscn 节点构成。
2. **场景与存档合同**：确定旧 escape_prologue、新 S01/S02、prologue_exterior 的场景 ID、进入点、返回点、死亡/继续游戏映射。
3. **战斗与转场**：复用执行者伤害、Boss HUD 与追兵治疗，验证 HP=0、50% 阶段介入、30 秒未造成伤害和主角战败四条路径；检查飞龙掠过、山路崩塌、坠落镜头与 A1 西侧转场。
4. **武器解锁**：核对长剑拾取与 A1 短刃交易的实际状态入口，封闭提前切换路径。
5. **统一通知控件**：复用右上角布局，接入物品名称/数量和成就解锁通知；保留背包描述查看。
6. **全局成就迁移**：建立独立全局档案，迁移旧存档成就并覆盖多存档回归。
7. **文档与验证**：每次代码/场景变更同步更新本文与相关合同；执行静态检查、Godot headless 检查和用户本地实机验收。未运行的项目不得标为通过。

## 5. 额外场景演出要求

- 当前伏击后 S01 左侧以不可见空气墙阻挡玩家。用户希望改为**伏击触发后，一堵真实的实体墙从上方/侧方落下封住左侧通路**，以场景内可见的物理变化解释封锁。
- 实体墙必须预先作为可见节点存在于 `.tscn` 中，使用 `AnimationPlayer` 等方式驱动其落下；允许代码改变预制节点状态/播放动画，不允许运行时创建墙体或碰撞地形。
- 墙体碰撞应与动画时序一致：落下前不能提前形成看不见的阻挡；落地后再可靠封闭通路，并避免穿透、夹人或玩家被卡在墙体内。
- 墙体最终归属 S01 还是 S02，需在检查当前场景边界与 S01/S02 切分点后决定，不能先验假设。

## 10. 长剑发现、自动获得与装备（2026-10-30，用户最终确认）

### 10.1 设计决定

- **不增加空手战斗系统。** A0 不新增拳击、肘击、踢击、空手连招、空手专属动画/判定或空手伤害平衡分支。
- 新游戏开局时主角尚未获得长剑；但玩家也不需要在战斗前主动寻找并手动拾取武器。
- 在 S01，玩家探索手术室并尝试打开出口、准备逃离时，触发长剑发现事件：主角注意到被随意丢在地上的长剑，随后自动获得并装备。
- 长剑的场景摆放、发现时机和拾取反馈必须有明确场景依据；不得表现为切换场景时凭空发放武器。
- S02 开始时，正常情况下主角已装备长剑，沿用现有武器战斗系统完成三人伏击。S02 不提供空手战斗路线。
- 该自动获得事件必须幂等：重复触发不能重复发放、重复提示或覆盖玩家后续装备状态；场景切换、死亡重生、继续游戏和旧存档迁移均须保留正确的武器拥有权/装备状态。

### 10.2 长剑物品描述（用户确认文案）

> 一柄还算顺手的长剑，剑锋上还有未干涸的血渍，剑柄上有个相当模糊的符号，被随意的扔在地上。

- 这段描述保留玩家最初提供的措辞，不在实现时擅自补充“这是主角的剑”等解释。
- 剑柄上模糊的符号是身份线索：暗示长剑的主人可能就是主角；结合长剑被缴获后随意丢弃在手术室的状态，让玩家自行推断。
- 描述不得直接揭示长剑归属，也不得由自动装备事件附加旁白或主角内心解释。
- 该文案用于物品描述/背包查看；拾取时仍遵守统一通知规则，只显示物品名称与数量，不弹出完整描述、不暂停游戏。

### 10.3 场景与状态实现约束

- 长剑必须在 S01 的场景叙事中有可见/可调查的落点；触发点与手术室出口开门/逃离动作建立明确因果。
- 由一个明确的世界状态/事件接口统一处理“长剑已拥有”和“当前装备为长剑”，不能把默认 current_weapon_style = long_sword 当作获得事实。
- 获得与装备应作为一次有序状态变更：先确认拥有权，再设置当前装备；保存成功后才进入依赖长剑战斗的后续流程。异常或重复调用不得导致状态矛盾。
- 如果旧存档已经处于 S02、洞外或 A1，迁移时不得把玩家回退到手术室，也不得覆盖已有短刃装备/解锁状态；应依据已有剧情进度与装备事实进行保守迁移。
- 本次决定只取消“空手战斗系统”需求，不改变 S02 三人必须击败后才能继续的既定关卡规则，也不改变 A1 短刃通过北门事件奖励与金正交易解锁的设计方向。

### 10.4 验收条件

1. 新档进入 S01 时，长剑尚未拥有，当前装备状态不应伪装成已拾取。
2. 玩家探索并尝试打开手术室出口时，能明确看到/感知长剑发现过程，并自动获得、装备长剑。
3. 继续进入 S02 时，长剑攻击正常工作；没有空手攻击系统或额外空手分支。
4. 重复触发开门/发现事件不会重复获得长剑或重复弹出通知。
5. 死亡重生、场景切换、存档继续和旧档迁移不会丢失长剑拥有权，也不会覆盖已经合法获得的短刃状态。
6. 长剑描述与本节确认文案一致；不出现解释性旁白或主角内心独白。
7. 以上均为待实现验收条件；在代码和场景实际修改、运行验证前，不标记为已完成。
