# 结局条件设计基准（V2，权威规则）

> 项目：Nereis-Hero  
> 适用分支：`feature/story-map-progression`  
> 状态：设计规则已重新确认；现有 `ending_evaluator.gd` 仍是旧原型判定器，尚未完成与本规则的条件映射和运行时验收。  
> **优先级：本文的结局设计规则高于旧版《结局攻略》《Story Foundation》中沿用的原型阈值。旧规则仅作为历史实现记录，不再视为最终设计。**

## 1. 核心规则

结局由玩家在实际游戏过程中留下的可验证事实共同决定：

1. **实际探索路径**：玩家是否真正进入某个隐藏区域、深入某条支线、到达指定地点。地图拓扑上存在连线、看见入口或解锁入口，不等于已经探索。
2. **关键道具状态**：玩家是否取得指定道具、结算时背包中是否仍持有指定道具，以及是否实际使用过该道具。三者必须分别记录，不得用一个模糊的“收集过”标记替代。
3. **特殊剧情 / 事件记录**：例如触发关键特殊剧情、与朝圣骑士共同击败教会怪物、在森林深处与朝圣骑士共同击败邪教仪式头目。需要记录实际完成的事件，而非仅凭抵达地图或击败同名敌人推断。
4. **道具与事件的前置关系**：有些道具只能通过与蜜忒交流、发展关系或完成她相关的互动获得。关系是取得这些内容的途径 / 前置条件，不是直接决定结局的数值或开关。

因此，结局判定的核心是“玩家实际做过什么、获得了什么、使用过什么、触发过什么”，不是一个抽象关系分数，也不是单纯的地图连通性。

## 2. 三个结局的路线意图

### 凡人之墓

代表玩家主要沿正常主线推进，没有细致探索隐藏地图，也没有取得触发宇宙特殊剧情所需的关键道具。

典型因果链：

- 玩家按主线推进，未发现或未进入关键隐藏地图；
- 因未探索隐藏地图，无法取得相应关键道具；
- 因缺少关键道具，特殊剧情无法触发；
- 最终条件落在「凡人之墓」。

这是默认主线结局，不应通过“玩家没有与蜜忒发展关系”直接触发。玩家可以与蜜忒关系良好，但若没有完成必要的探索、道具和事件链，仍可走向凡人之墓。

### 永恒乐园

代表玩家已经深入到足以接触宇宙真相的程度，并触发了部分特殊剧情，但没有完成保留自我、抵抗外神的完整条件链。

示例因果链：

- 玩家细致探索，发现隐藏地图并取得部分关键道具；
- 使用或持有关键道具，触发特殊剧情；
- 但未继续进入更深层的隐藏区域，因而没有取得第三根脐带等更深层关键道具；
- 或未完成后续必要的路径 / 事件条件；
- 因完整抵抗条件不足，落入「永恒乐园」。

第三根脐带在此处是用户提出的设计示例，具体物品 ID、取得位置、是否需要持有或使用，必须在后续道具与剧情台账中确认后才能成为代码契约。

### 烈火天罚

代表玩家不只接触到真相，还完成了更深层的探索、关键道具与协同行动链，保有足够行动能力去抵抗外神的最终降临。

示例必要条件包括：

- 进入指定的深层隐藏地图，而非仅发现入口；
- 取得并满足设计要求的关键道具状态（分别确认取得、持有、使用条件）；
- 与朝圣骑士共同击败教会的指定怪物；
- 在森林深处与朝圣骑士共同击败邪教仪式头目；
- 完成后续与第三根脐带等关键道具关联的特殊剧情 / 事件条件。

这些是结局路线设计的条件类别与已明确示例，不应在未核实现有场景、敌人和任务标识前，臆造事件 ID 或把示例直接当成已经实现的代码条件。

## 3. 关系状态的正确位置

蜜忒关系只在其实际影响游戏内容的地方发挥作用：

- 可以开放交流、互动或特殊剧情；
- 可以作为取得特定关键道具的前置条件；
- 可以改变人物在结局演出中的台词、在场状态或情绪语境；
- **不能仅因关系高 / 低、相识 / 未相识、错过 / 未错过，就直接决定三个结局之一。**
- **身体结合不是任何结局的必要条件。** 不能为了满足结局而伪造 `physical_union_complete`，也不能把亲密场景当成第三根脐带等道具的默认替代品。

如果某个关系分支确实是唯一的关键道具来源，那么结局会间接受到该分支影响：不是因为“关系值决定结局”，而是因为玩家是否取得了该道具并完成后续事件改变了判定结果。后续设计若允许替代获取路径，也必须记录各条路径实际取得的证据。

## 4. 必须拆分的状态

| 状态类别 | 需要回答的问题 | 不可混用的状态 |
|---|---|---|
| 地图探索 | 是否发现、开启、实际进入、深入到指定区域？ | 拓扑可达 ≠ 发现入口 ≠ 开启通路 ≠ 实际进入 |
| 道具取得 | 是否从世界中拾取 / 获得？ | 取得过 ≠ 当前背包持有 |
| 道具持有 | 结局判定时背包是否拥有该道具？ | 当前持有 ≠ 曾经取得 |
| 道具使用 | 玩家是否在指定剧情 / 机关 / 对象上使用过？ | 拾取 ≠ 阅读 ≠ 使用 |
| 特殊事件 | 指定剧情、协同战斗或头目战是否成功完成？ | 到达区域 ≠ 触发剧情 ≠ 完成事件 |
| 关系互动 | 是否发生过指定对话 / 互动，是否由此开放道具来源？ | 关系状态 ≠ 结局结果 |

实现时应优先使用语义明确、可存档、可回归验证的独立事件标记，并明确哪些状态在读档后持续、哪些是消耗型状态。

## 5. 结局求值顺序

最终优先级应为：

1. **烈火天罚**：完整的深层路径 + 关键道具状态 + 指定特殊剧情 / 协同事件条件全部满足。
2. **永恒乐园**：玩家已触及宇宙真相并完成其触发链，但烈火天罚的完整抵抗条件不成立。
3. **凡人之墓**：未形成足以触发上述宇宙结局的完整条件链。

这是路线意图，不是说任意一件关键道具都足以自动触发永恒乐园。具体条件须由逐条剧情链和道具台账确定。求值必须可解释：开发日志 / 调试报告应列出每条必要条件是否满足以及缺失项。

## 6. 旧版逻辑（历史记录，不再作为权威规则）

当前原型 `scripts/core/ending_evaluator.gd` 只按以下阈值判断：

- `hero_resonance >= 68`；
- 烈火天罚：`hidden_artifact_pieces >= 3` 且 `entered_hidden_regions.size() >= 2`；
- 永恒乐园：存在 `anomaly_observer_reaction` 来源且至少进入 1 处隐藏区域（在未满足烈火天罚时）；
- 其余情况为凡人之墓。

它没有显式核查第三根脐带、道具是否使用、结算时是否仍在背包、朝圣骑士协同战斗、森林深处邪教仪式头目战，或特殊剧情是否实际完成。它也没有把蜜忒关系作为道具获取前置链来追踪。

这些阈值曾适用于较早的结局原型 / 演出验证，但不能证明新设计的完整条件已经实现。不得继续把旧阈值描述成最终剧情契约，也不得在缺少事件映射时简单把数值阈值替换成猜测的布尔值。

## 7. 实施与验收顺序

1. 逐一盘点现有关键道具：稳定 ID、取得位置 / 途径、是否可消耗、持有检查、使用记录、与蜜忒互动的前置关系。
2. 逐一盘点关键地图和事件：实际进入标记、指定深层区域、教会怪物、朝圣骑士协战、森林邪教头目战、特殊剧情的真实脚本入口。
3. 建立“结局条件 → 源码状态 → 写入点 → 存档字段 → 验收场景”的映射表。
4. 先为每个结局编写正向与反向回归矩阵，再修改 `ending_evaluator.gd`；不得让导演测试快捷键直接伪造正式条件。
5. 检查旧存档迁移：保留可验证的历史事实；无法从旧数据可靠推断的新条件应保持未满足 / 未知，不得自动补成已完成。
6. 运行静态验证与 Godot 实机全流程：正常主线、部分隐藏探索、完整深层探索、缺少单个必要道具、道具取得但未使用、事件失败 / 成功、旧存档继续。静态检查不能代替实机流程验收。

## 8. 当前结论

本次先确立权威设计规则并记录旧原型的差距。当前旧 evaluator 与本规则存在明确的条件覆盖缺口；在盘点实际道具和事件 ID 之前，不应声称三结局已按新规则完成实现。后续开发应从条件映射表开始，再一次性更新判定器、结局攻略和回归测试。


## 9. 烈火天罚条件链补充实例（用户确认的剧情基准）

本节将后续设计审计的目标流程具体化。它是**需要实现与验证的设计条件链**，不是声称当前代码已经具备这些道具或事件标记。

### 9.1 指定流程

1. **初遇朝圣骑士**：记录首次相遇事件。仅知道这个 NPC 存在或进入其所在区域，不算完成初遇剧情。
2. **禁忌森林再次相遇并合作**：玩家实际进入隐藏地图「禁忌森林」，再次遇到朝圣骑士并完成合作事件。
3. **获得朝圣骑士的回复酒**：这是合作后获得的剧情道具。需要在道具台账中确认正式 ID、获取条件、是否可消耗，以及结局检查要求的是“曾取得”还是“结算时仍持有”。不能只用一个对话标记代替道具状态。
4. **王墓协同战斗**：在王墓与朝圣骑士共同击败指定教会怪物，并因该事件获得朝圣骑士的徽章。需要验证队友参与 / 协同事件成功，不能仅凭怪物死亡或场景已清理推断。
5. **取得其他指定证据**：
   - 金正遗物徽章；
   - 染血笔记；
   - 复仇女神赐福的火种。
   
   这三项必须分别有正式道具 ID、获取来源和状态定义。它们是各自独立的条件，不可仅以“已收集三个线索”替代。
6. **第三根脐带的使用链**：玩家最终需要使用与第三根脐带相关的道具四次，才能满足示例中的最终关键条件。实现前必须确认“四次”指同一道具使用四次、四件脐带类道具各使用一次，还是四个不同目标 / 仪式上的成功使用；在该语义核实前，不得写成猜测的计数器或任意消耗四件道具。
7. **烈火天罚判定**：上述路径、合作事件、指定物品和脐带使用条件全部满足后，才具备走向烈火天罚的资格。若缺少任一必要条件，不得因为共鸣值、隐藏地图数量或线索数量达到旧阈值而越过缺失条件直接触发。

### 9.2 建议的事件事实（待与现有源码映射）

为了使流程可存档、可追溯、可测试，至少需要为以下事实找到现有写入点或新增明确事件标记：

- 首次遇到朝圣骑士；
- 在禁忌森林再次遇到朝圣骑士；
- 禁忌森林合作事件完成；
- 回复酒已获得，以及必要时的当前持有 / 使用状态；
- 王墓指定教会怪物被朝圣骑士协同击败；
- 朝圣骑士徽章已获得；
- 金正遗物徽章已获得；
- 染血笔记已获得；
- 复仇女神赐福的火种已获得；
- 第三根脐带相关使用成功次数 / 对象记录；
- 禁忌森林等必要隐藏区域已实际进入。

上述是语义清单，不是预先指定的变量名或 ID。应优先复用已存在且语义正确的持久化状态；若不存在，再添加字段、事件写入点和存档迁移。

### 9.3 缺项反例

烈火天罚的回归测试必须至少覆盖：

- 所有步骤完成：可进入烈火天罚候选；
- 从未在禁忌森林再次遇到朝圣骑士：不可进入；
- 合作发生但没有获得回复酒：若该道具被确认为必要条件，则不可进入；
- 王墓教会怪物由玩家单独击败、朝圣骑士未参与：不可将其计为协同事件；
- 缺少朝圣骑士徽章、金正遗物徽章、染血笔记或赐福火种任意一项：不可进入；
- 脐带使用次数不足四次：不可进入；
- 仅持有道具但没有完成规定的使用 / 事件：不可将持有视为已使用；
- 旧存档只有旧版锚点计数、没有可验证的新事件记录：不得自动推定完整流程已完成。

## 10. 后续审计优先级

先逐项检索现有场景、道具定义、拾取逻辑、库存、战斗结算、朝圣骑士对话与事件状态，再建立真实 ID 对照表。尤其要确认王墓、禁忌森林、朝圣骑士、金正遗物、染血笔记、赐福火种和脐带使用链在当前分支中分别有哪些实现。完成映射后再改 evaluator；在此之前不应臆造字段或声称条件链已经接入。
