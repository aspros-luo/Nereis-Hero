> 状态：系统接口已接入，进入剧情重设计前的准备阶段；本文不是最终剧情方案。

## 2. 进度系统接口现状

- `scripts/core/world_event_director.gd`：独立 NPC manifest 与事件 manifest。
- `NPC_DEFINITIONS`：支持 NPC 稳定 ID、位置、基础对话、生成条件、可选的互斥 flag，以及按条件排序的 `dialogue_variants`。
- `EVENT_DEFINITIONS`：支持触发类型、上下文匹配、条件列表、一次性标记和安全的持久化 flag 效果。
- `scripts/levels/village_hub.gd`：进入 A1 后分发 `region_entered`；NPC 与 POI 对话结束后分发 `interaction`；`refresh_progression_content()` 用于状态变化后重新评估事件和进度 NPC。
- `WorldState` 已保存 `achievement_flags`、路线、人性状态、隐藏区域进入记录、物品数量、物品收集 ID 与阅读 ID，足以为第一批普通进度条件提供数据源。

## 3. 当前条件类型

| 条件类型 | 含义 |
|---|---|
| `flag` / `flag_absent` | 某个持久化事实已成立 / 尚未成立 |
| `route` | 当前明确选择的路线 |
| `humanity_state` | 当前人性状态 |
| `region_entered` | 指定隐藏区域已实际进入，或当前位置与该 ID 相同 |
| `location` | 当前存档位置 ID 匹配 |
| `item_count_at_least` | 背包中指定物品数量达到要求 |
| `item_collected` | 指定世界物品已收集 |
| `item_read` | 指定记载已阅读 |
| `flag_count_at_least` | 指定前缀的 flag 数量达到要求 |
| `custom_method` | 调用经过审核、返回布尔值的 WorldState 查询方法 |

NPC 的多个对话变体按配置顺序匹配，第一条条件满足且对话非空的变体生效。应将更具体的状态放在更一般的状态之前。

## 4. 事件配置约定

事件 ID 必须稳定且具有语义，不得从显示名称或对话文本临时拼接。一次性事件触发后会持久化 `world_event_fired:<event_id>`。当前事件效果只允许增删 `achievement_flags`；复杂行为通过 `event_triggered` 信号交给专门系统，避免事件表直接操作任意场景对象。

推荐触发点：

- `region_entered`：进入村庄时；
- `interaction`：与指定 NPC / POI 完成交互后，`interaction_id` 使用稳定对象 ID；
- `state_refresh`：物品、区域、任务或战斗状态变化后重新评估。

任何新增进度事实都必须说明：由谁写入、何时写入、是否存档、重复触发是否安全，以及旧存档缺少该字段时如何处理。

## 5. 开始剧情重设计前的必查项

- [ ] 在 Godot 4.6.1 中运行项目，确认新脚本可解析、场景启动无运行错误。
- [ ] 验证 NPC 对话结束后事件能触发，事件写入的 flag 会影响下一次 NPC 刷新。
- [ ] 验证一次性事件在离开村庄、死亡、Continue 后不会重复执行。
- [ ] 验证刷新仅移除事件系统管理的 NPC，不删除常驻 NPC、主角、门或 POI。
- [ ] 验证同一 NPC 的不同对话状态切换正确，空对话不会出现无效交互。
- [ ] 审计常驻 NPC、房门、休整点、POI 的实际焦点半径和站位，避免相邻目标抢提示。
- [ ] 明确哪些普通 NPC 可以增加、离开或改变对话，哪些角色属于作者保留的核心剧情决定。

## 6. 下一阶段的剧情设计输入格式

每个候选 NPC / 事件在定稿前使用同一张设计卡：

1. **身份与局限**：角色是谁；亲历、听说、误解和不知道的内容分别是什么。
2. **空间理由**：为什么在此地、为什么此时出现；离开后是否能再遇到。
3. **出现条件**：精确到稳定 ID 的状态条件，不写“玩家进度足够”这种模糊条件。
4. **对话状态**：初见、重复交谈、事件前、事件后、错过后的表现。
5. **玩家行动**：调查、交谈、交付物品、战斗、选择离开或暂不处理。
6. **事件写入**：具体新增的事实、持久化规则与重复触发行为。
7. **地图反馈**：人物站位、门 / 路线变化、环境变化或实际奖励。
8. **信息差**：玩家能观察到什么，角色认为发生了什么，哪些问题继续保留。
9. **验收案例**：新游戏、条件未满足、条件满足、离开回访、死亡 / Continue 的预期结果。
10. **作者确认点**：涉及核心秘密、角色命运、朝圣骑士事件链或结局条件的内容必须先确认。

## 7. 不可擅自改动的叙事边界

- 不改变三种结局的路线意图与明确的特殊事件链。
- 不将蜜忒关系或身体结合直接当作结局判定开关。
- 不定稿第三脐带物品的“四次使用”语义。
- 不替作者决定蜜忒、朝圣骑士、金正、复仇女神的关键命运。
- 不为填地图增加制作素材、采集、配方或合成系统。
- 不以全知 NPC 对话一次性解释世界观；信息应来自角色有限视角、环境、可重复查看的物品与玩家实际经历。
