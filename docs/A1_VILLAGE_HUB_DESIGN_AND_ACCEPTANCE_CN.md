# A1 边境村庄：区域设计与验收合同

> 状态：基础场景与主线接线已存在；A1 是 A0 完成后的下一项优先工作。本文用于收束现有设计、列出待补齐项，不代表所有内容已通过实机验收。
> 分支：`feature/story-map-progression`
> 范围：A1 村庄空间、探索循环、交互、休整、区域连接与状态变化。核心剧情由作者确认，不在本文擅自定稿。

## 1. 区域职责

A1 是玩家离开序章后第一个自由探索 Hub，不是线性战斗关卡，也不应强迫玩家立即接受任务或进入下一张地图。玩家应能在此：

- 回到安全区域、休整并保存进度；
- 认识蜜忒及村庄中的人物，但可按自己的节奏探索；
- 从环境与物件中发现村庄的异常，而不是由全知旁白解释真相；
- 选择何时前往旧朝圣路；
- 在后续进度解锁后，重新访问旧排水通道、井下隐藏区及其他回访内容。

A1 不承担制作、采集或合成玩法；不为了填满地图而堆叠同质化笔记。

## 3. 核心玩法循环

### 3.1 序章返回与安全 Hub

A0 结束后进入蜜忒的家 / A1 流程，玩家可走出房屋并自由探索。房门、蜜忒、检查点、炉火之间必须有明确的交互优先级；玩家靠近某个对象时只显示当前真正可操作的提示。

### 3.2 休整与死亡恢复

- 检查点负责记录出生位置；炉火休整点负责恢复生命 / 耐力并保存。
- 休整只能在地面承托位置触发，不能将空中或高层平台坐标保存为死亡出生点。
- 从 A2、A3、A4、井下或其他连接回村时，使用各自的 `pending_region_spawn_side` 映射，出生点须避开门触发区和无关交互焦点。
- Continue 必须先读取进入侧，再清除一次性转场变量；存档后的出生点和区域位置应保持一致。

### 3.3 北门防卫与双向区域连接

- 初次调查北门会进入既有村庄防卫场景；这不是可跳过的普通门交互。
- 防卫成功后持久记录 `village_defense_survived`，回村世界状态随之改变。
- 北门开放 A1→A2；旧排水道开放 A1→A3 的替代路线。两条路不应因为接线方便而互相替代，也不得在防卫前提前开放。
- A2 与 A3 的回程门必须把玩家送回可识别且安全的村庄落点。

### 3.4 隐藏井与屋顶探索

- H01 继续使用现有灵视 / 共鸣门机制；两端共享同一个持久化开门状态。
- 屋顶路线是可选的高位探索层，必须有可辨识的起点、连续可达平台和安全回落路径。
- 屋顶内容应优先提供空间发现、实用奖励或通路价值；不以新增一批相似笔记作为默认奖励。
- 新奖励如涉及世界观核心秘密、关键角色命运或结局条件，先提案，待作者确认后再定稿。

## 4. 人物与叙事边界

当前 A1 的人物 / POI 可作为基础接线保留：蜜忒、守门人、失忆的年轻人、旅行商人、墓地、酒馆、复国军营地、教会与北门。

- 普通 NPC 只表达自己知道、相信或误解的内容；不要使用全知旁白解释整个世界。
- 玩家检查物品时可以反复阅读物品描述；拾取、阅读和使用是不同状态。
- 访问教会、酒馆或其他区域不能擅自成为不可逆关系选择。
- 不擅自决定蜜忒、朝圣骑士、金正、复仇女神的命运；不改变三种结局方向、朝圣骑士事件链、第三根脐带“四次使用”语义或最终结局判定。
- 现有对话若涉及路线专属内容，只允许在对应路线 / 状态确实成立时出现；未选择路线时保留中性对话。
- 本文是区域设计合同，不等于核心剧情已获作者确认。

## 8. 进度驱动 NPC / 事件扩展接口

A1 已接入 `scripts/core/world_event_director.gd`。后续进度内容通过配置扩展，不再把所有条件分支继续堆进 `village_hub.gd`。

### NPC 注册

在 `NPC_DEFINITIONS` 中为经过确认的进度 NPC 添加配置：

- `id`：稳定 NPC ID，供交互、测试和后续存档事实引用；
- `position`、`display_name`、`dialogue`：初始站位和基础交互内容；
- `conditions`：全部满足才生成；
- `required_flag_absent`：可选的互斥条件，避免某个状态成立后旧 NPC 仍出现。

现有常驻 NPC 仍由 A1 基础场景负责，进度 NPC 与常驻 NPC 分开管理。后续如果某角色需要离开、替换对话或移动位置，应继续扩展同一套 manifest/refresh 机制，而不是复制第二份常驻 NPC。

### 事件触发点

当前提供以下触发入口：

- `region_entered`：场景完成基础生成后触发，context 包含 A1、进入侧与位置；
- `interaction`：POI 对话结束后触发，context 包含 POI ID；
- `state_refresh`：供后续进度状态变化时主动重新评估；A1 暴露 `refresh_progression_content()`，可在主角仍处于村庄时重新生成进度 NPC 并重新评估事件。\n- 目前 POI 交互结束后会自动调用刷新入口；后续战斗奖励、物品获取或区域事件若在村庄内直接改变状态，也应调用同一入口。

条件类型包括进度 flag、路线、空洞状态、已进入区域、物品持有数量、物品已收集、物品已阅读，以及可选的 WorldState 布尔查询方法。事件效果目前只允许安全地增删持久化 flag；NPC 生成、动画、场景变化等复杂效果应通过 `event_triggered` 信号由对应系统处理。

### 持久化与设计边界

- 一次性事件用 `world_event_fired:<event_id>` 标记持久化，避免读档或重复进入后重复触发。
- 条件与效果必须使用稳定 ID；不要依赖 NPC 名称、对话文本或场景节点顺序。
- 当前 manifest 不含新剧情内容，因此不会擅自决定角色命运或关键事件。
- 静态验证只证明接口接线存在。运行前仍需检查 Godot 语法、事件触发顺序、存档迁移和重复进入行为。
