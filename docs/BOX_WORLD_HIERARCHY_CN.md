# Nereis-Hero 箱式世界地图：大区域—小区域—连接与升降机（v1.0）

> 本文件是开发者设计档案，不向玩家公开。它把宏观区域拓扑继续细分为空间可施工的三级结构。数据位于 `tools/world_map_topology.json`；此文档描述设计规则。静态数据不等于 Godot 场景已实装或实机通过。

> **叙事级区域分组已更新：** 当前剧情地图总纲以 [世界地图总归纳](WORLD_REGION_ATLAS_CN.md) 为准。本文中的旧五区分组仅保留为早期工程组织思路；请勿将其当作当前剧情大区域划分。

## 2. 小区域划分原则

每个宏观区域继续拆成可识别、可导航、可单独放置敌人与奖励的子空间。数据文件中的 `subregions` 为具体清单，每个条目包含 ID、所属区域、名称、高度层与用途。高度层包括 ground、upper、tower、underground、deep、vertical 等语义。

- **地面层**承载首次导航、主要遭遇与可辨认地标。
- **上层/塔层**必须能从视觉上辨认其与地面空间的关系，不能只靠坐标偏移伪造高度。
- **地下层**通过井、楼梯、维护口、水道、牢房或墓道相连；入口应有可读的建筑理由。
- **深层/异象层**承担灵视路线和世界认知变化，不应只是一间独立奖励房。
- 同一小区域可以有多个入口与出口；入口不同应尽量带来不同的落点、视线、敌人压力或信息顺序。

## 3. 区域内连接、捷径与回环

`intra_region_connections` 是小区域之间的连接合同，包含连接 ID、起终点、类型、通行方向、初始状态、解锁条件和设计意图。

连接类型约定：
- `walk`：普通道路、廊桥或街巷。
- `stairs` / `climb` / `ladder`：可读的爬升或上下楼层。
- `drop`：落差路线；若为单向，必须提供后续回返方式或明确这是有意的风险选择。
- `hatch` / `gate` / `winch`：机关、闸门或绞盘开启的通路。
- `lift`：实体升降机，必须引用 `elevators` 中的对应设备合同。
- `resonance`：灵视发现的隐藏路线，玩家需通过声音、轮廓、倒影或环境反馈发现，不直接显示开发者标记。
- `loop`：用于说明额外回环；必须有真实空间路径，不可只在数据里闭环。

捷径要满足至少一项：明显缩短旧路、改变到达高度、让玩家从另一侧进入旧空间、或打开安全回程。若只是把玩家传到同一扇门旁边，不算有意义的捷径。

## 4. 升降机合同

当前设计预留 8 台有明确用途的升降机：

| ID | 设备 | 连接 | 玩法目的 |
|---|---|---|---|
| LFT01 | 雾林绞盘升降台 | A2 地面—树冠 | 让树冠探索可安全回访 |
| LFT02 | 沉积大厅维护笼 | A4 上层—底层 | 地下枢纽纵向交通；供能前保留基础替代路线 |
| LFT03 | 钟塔配重梯 | A6 庭院—塔顶 | 安全垂直回程，与 C10 风险落差分工 |
| LFT04 | 监牢维护吊笼 | A7 走廊—竖井底 | 监牢内部的垂直交通，不取代 C12 |
| LFT05 | 王墓石台 | A8 墓室—中层水道 | 让王墓内部层级形成可回访回路 |
| LFT06 | 外环旧货梯 | A9 下层—屋顶站 | 与跨区 C16 组合为后期高架回路 |
| LFT07 | 内城货运升降机 | A12 服务街—维护层 | 连接内城地面与城墙/维护交通 |
| LFT08 | 王座厅配重梯 | A12 城墙步道—王座厅上层 | 改变终局前的进入高度，不改变结局资格 |

每台升降机都需要：井道和上下停靠点、初始状态、解锁条件、上下站操作反馈、运行音效/动画、可达性检查，以及死亡/读档后的状态持久化策略。损坏或未解锁的升降机不能导致主线软锁；必要时应保留梯子、楼梯或另一条风险更高的路线。

## 5. 施工顺序

1. 先把 A1–A4 做成可验证的多层切片：地面、树冠/屋顶、管线、水道与井底互通。
2. 再完成 A5–A8：战壕/城墙、修道院钟塔、监牢竖井、王墓中层水道。
3. 完成 A9–A12 的屋顶高路、圣堂高廊、排水道、内城服务门与升降机。
4. 最后接入 H01–H08、A11/A13，并检查灵视发现、返回路线和结局条件独立性。
5. 每个连接按“设计合同 → 场景坐标/实体 → 运行时门状态 → 进出落点 → 存档/死亡恢复 → Godot 实机验收”逐项核对。

## 6. 玩家信息边界

完整大地图、子区域清单、敌人位置、奖励/惩罚表、隐藏入口与捷径开关均为开发者信息。正式游戏只通过地标、环境、声音、局部线索和灵视反馈引导玩家，不展示这份设计表或全量开发者地图。

## 7. 验收状态

本次扩展建立了五个大区域、子区域清单、区域内连接和八台升降机的设计合同。它是**地图设计数据扩展**，不是对所有升降机、机关或场景连接已完成实装的声明。后续必须把合同逐项映射到 Godot 场景与运行时逻辑，并记录静态检查与实机验收结果。
