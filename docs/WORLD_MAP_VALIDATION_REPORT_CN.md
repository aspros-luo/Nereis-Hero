# 世界地图静态验证报告（中文）

> 审查版本：World Map Audit 0.1  
> 审查分支：development  
> 审查日期：2026-10-10  
> 审查范围：世界地图总纲、第一阶段拓扑、全游戏区域网络、完整区划图，以及仓库中与灵视 / 隐藏目标相关的现有脚本。  
> **结论性质：静态审查，不是 Godot 实机验收。**

## 1. 审查结论

目前的世界地图在**宏观连通性上成立**：14 个主要区域通过当前规划的 23 条区域连接全部连通，没有孤立区域。A3 废弃城区、A4 下水道与旧水库、A9 王城外环具有较高的连接度，适合承担多入口与回环；A0 作为单入口序章、A13 作为终局分支也合理。

但不能将当前总图称为“已经验证通过的完整游戏地图”。现有区域关系主要存在于设计文档中；项目还没有 A2–A13 的完整可玩区域串联，也没有用 Godot 灰盒实测各条平台路线、捷径、门槛、检查点和返回路径。因此当前状态是：**宏观拓扑静态通过，实际关卡连通与运行时行为待验证。**

## 3. 仓库现状检查

### 3.1 当前场景与完整地图的差距

仓库当前含有开场、村庄 Hub、村庄墓园、古代研究实验室、室内 / 路线场景和若干导演测试场景。它们是现阶段实际存在的场景资产，但不能直接等同于 A0–A13 的完整区域实现。

- A0 开场与 A1 村庄可作为现有基线继续使用。
- 村庄墓园和古代研究实验室可以为 A2 / A11 的部分叙事提供参考，但当前不应把它们直接认定为完整的钟墓或深层研究区。
- 尚需制作和串联 A2–A13 的实际关卡空间。
- A0 到 A1 当前以场景转换承接。设计文档中的“山腹逃生道”可以在未来通过独立场景 / 通道加强连续感，不要求所有地图放进一个巨型场景。

### 3.2 灵视 / 鸣响系统已有基础

仓库中已存在以下机制：

- WorldState.hero_resonance：0–100 的隐藏鸣响值，并参与存档。
- ancient_exposure、outer_exposure：区分古神残留与外神影响的接触度。
- resonance_sight_active：灵视当前是否处于激活状态。
- 主角已有 resonance_sight 能力 ID。
- scripts/systems/resonance_hidden_target.gd：可根据鸣响值、两类接触度，以及灵视是否激活，显现隐藏目标。
- 目前主角灵视一次激活为 4.5 秒，消耗 10 点体力，冷却 6 秒。

这意味着应该扩展既有系统，而不是重新发明一个独立的“隐藏地图管理器”。

#### 3.2.1 正常流程的前置链仍未闭合

核对当前脚本后，还发现两个会直接阻止隐藏地图正常运行的问题：

- `WorldState.mark_ancient_residue_awakened()` 会将 `hero_resonance` 提升到至少 12、`ancient_exposure` 提升到至少 1；旧存档迁移也会保留这个最低值。
- `HeroSystem.add_resonance()` 虽然存在，但在已核查的主线场景、NPC、敌人与世界交互脚本中没有找到正常流程调用。`WorldState.mark_outer_god_resonance()` 目前只设置布尔状态，不会自动增加 `outer_exposure`。
- `hero.gd` 会在 `resonance_sight` 未解锁时拒绝响应 V；主线 / 场景调用链中暂未找到 `WorldState.unlock_ability("resonance_sight", ...)` 的正常解锁调用。
- 当前 `resonance_hidden_target.gd` 的已确认实例化用途以主角的调试测试痕迹为主，没有与 H01–H08 正式地图入口形成可玩闭环。

因此，表中鸣响门槛不能直接视为可达的正式数值。隐藏地图开发前必须打通：**剧情前置 → 解锁灵视 → 鸣响 / 接触成长 → 显现 → E 调查 → 永久开门 → 存档 / 回访**。

为防止把“设计数据通过”误写成“玩法已经实现”，`tools/world_map_topology.json` 现在同时记录 `resonance_progression_contract` 与细化的 `resonance_sources`：R01 使用“至少达到 12”而非盲目增加 12，避免和可选剧情已有的鸣响增量重复；R04 / R06 规划古神接触增量；外神共鸣剧情状态规划将外神接触提升至 12，R08 再提升至 18。校验脚本会检查两张来源表的一致性、累计门槛、隐藏门依赖的异常来源 ID 与接触度可达性。这些仍然是**待接入运行时的来源合同**，不代表相关事件已写入场景脚本。

### 3.3 隐藏地图机制尚未形成完整闭环

当前隐藏目标组件负责显示目标标记与可选的 CanvasItem，但尚未提供完整的地图发现流程：

1. 发现记录不会因为目标显现而自动持久化；
2. 没有专门的隐藏区域 / 隐藏通路开启记录；
3. 目标组件本身不负责 E 键交互、开启门或切换场景；
4. WorldState 当前没有 discovered_hidden_regions / opened_hidden_paths 之类的保存字段；
5. 目前无法仅凭组件存在，就认定任何完整隐藏地图已经可被玩家发现和进入。

后续实现应优先扩展 resonance_hidden_target.gd、既有交互焦点机制与 WorldState 存档，不要增加一套平行的能力 / 状态系统。

## 4. 需要修订的地图规则

### 规则 A：所有连接都要有方向

“区域 X 连接区域 Y”还不够。正式制作前，每条边都需注明：进入方向（单向 / 双向）、初次经过是否开放、需要鸣响 / 剧情 / 机关还是已有能力、从对侧是否能打开、开启状态是否保存、是否可能绕过主线关键事件、死亡后返回是否要重新经过同一遭遇。

### 规则 B：隐藏支路不能破坏进程

隐藏入口可以让玩家提前发现后期区域的轮廓，但从隐藏区通向主线后期地图的出口应从对侧锁住，或需要已经发生的世界状态。早发现可以奖励见识和物品，不能让玩家意外跳过必须发生的关键事件。

### 规则 C：鸣响是感知门槛，不是自动传送

玩家需要激活现有的灵视能力，并靠近地图里的异常点。鸣响达到门槛后，异常空间才显现；玩家随后主动调查并固定开启通路。显现效果结束不应使已永久开启的通道重新关闭。

### 规则 D：可读的空间线索早于隐藏通路

低鸣响时也应存在可供观察的细微不协调，例如影子方向不一致、钟声先于动作、墙面结构重复或水面反射出不存在的楼梯。高鸣响让这些线索变得可辨认，但不必用 UI 直接提示“这里是隐藏地图”。

### 阶段 2 — A0–A4 灰盒

- [ ] 盘点现有 A0 / A1，确认实际入口、复位、存档点和场景转换。
- [ ] 搭建 A2 的主路、钟墓支路与回环。

### 阶段 3 — 灵视隐藏地图试点

先只在现有 A1 或已建立的 A2 放置一个隐藏入口，验证：

- 鸣响低于门槛时没有显眼交互提示，但背景异常可被观察；
- 灵视激活且达到门槛时，在 4.5 秒窗口内显现；
- 玩家未能及时调查时可重复触发，不会永久错过；
- 调查后开启状态写入存档，死亡、切图和重新加载后仍然成立；
- 路线出口不会绕过尚未完成的主线门槛；
- 显现与互动复用现有输入焦点，避免 E 键同时指向 NPC 和隐藏入口。

### 阶段 4 — 扩展到全地图

试点通过后，再把相同模式复制到 A3、A4、A7、A8、A10 和 A11。每次新增入口都要用静态拓扑再次检查全图连通、顺序突破与回程。

## 6. 当前验收结论

**可以作为设计基准继续推进；还不能标记为“地图已实机验证”。**

当前最合理的下一步，不是立即批量创建所有区域，而是先锁定隐藏地图规则和入口合同，再用 A1 / A2 的小型灰盒验证灵视 → 发现 → 开启 → 保存 → 回访整条流程。这样既能保护已冻结的战斗和角色基线，也能避免后期发现隐藏门、地图状态和存档逻辑互相冲突。
