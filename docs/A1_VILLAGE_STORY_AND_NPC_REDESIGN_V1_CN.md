# A1 村庄剧情与 NPC 重设计方案 V1

> 项目：Nereis-Hero  
> 分支：`feature/story-map-progression`  
> 状态：第一版设计提案，普通玩法结构可继续实现；涉及核心秘密、关键人物命运与结局条件的内容明确保留，不在本文定稿。  
> 目标：把 A1 从“静态 POI 展示区”改成可自由探索、能反复回访、会回应玩家行动的边境聚落。

## 0. 设计结论

A1 的核心体验不是告诉玩家“世界发生了什么”，而是让玩家在同一个小村庄里观察到三种互相矛盾的现实：

1. **日常仍在继续**：有人修门、做买卖、照看炉火、守着自己的生活。村庄不是纯粹的废墟或全员等死的舞台。
2. **村庄不愿谈论某些事**：居民对教堂、旧朝圣路、墓地钟声和主角身份的说法彼此不一致，但大多数人只掌握一小块事实。
3. **玩家的行动改变村庄的可用空间**：防卫后北门恢复、旧排水通道开放；探索回来后人物会回应主角真正经历过的事情；部分入口只有在真实事件之后才出现。

A1 不是强制任务大厅。玩家第一次进入后即可自由探索地面路线与屋顶高路；不要求按“守门人→年轻人→商人→教会”的顺序对话，也不因暂时不做某件事而锁死普通探索。

## 0.1 作者确认的空间与出场约束（2026-10-19）

以下约束优先于本文早期草案中尚未确认的空间安排：

- **初次进入 A1 时不出现复国军营地。** 村庄初期先呈现普通居民的生活状态，不提前展示公开驻扎的复国军。复国军可以在后续明确的剧情节点进入村庄，并在该节点之后成为常驻区域；具体触发事件必须绑定已确认的剧情事实，不得简单以“完成村庄防卫”代替。
- **“教会”在 A1 的空间称呼统一为“教堂”。** 教堂初期保持空置，保留建筑、陈设与可调查环境，不以常驻 NPC 或长篇文本填满。
- **朝圣骑士是进度型来访角色，不是 A1 初始常驻 NPC。** 在特定剧情节点，朝圣骑士可以出现在教堂或酒馆；具体出现地点、出场节点、离开条件及其掌握的信息必须与正式剧情一致。没有对应剧情事实时不得提前生成。
- 教堂与酒馆是同一角色可选择的不同出场舞台，而不是同时复制两个朝圣骑士。若后续设计为不同时间分别出现，应使用稳定 NPC ID 和持久事件状态，避免重载、回村或场景刷新导致重复出场。
- 这次确认不授权改写朝圣骑士的核心秘密、关键人物命运或结局条件；普通空间、生成条件与出场状态可先实现，具体剧情内容保留待确认。

### 建议的阶段表现

| 阶段 | 复国军营地 | 教堂 | 朝圣骑士 |
|---|---|---|---|
| 初次进入 A1 | 不出现；不显示明确的驻扎营地 | 空置，可探索 | 不出现 |
| 普通早期探索 | 仅保留可解释为普通村庄空间的环境痕迹，不生成驻军 | 空置 | 不出现 |
| 已确认的后续剧情节点 | 出现驻扎迹象并建立可持续访问的营地 | 仍保持空置，除非该节点指定其到场 | 根据该节点选择教堂或酒馆其一 |
| 后续回访 | 营地保持常驻，除非正式剧情明确改变状态 | 按剧情状态变化，不自动填充 | 按持久事件状态决定是否在场，不重复播放初见演出 |

## 1. 玩家在 A1 的体验节奏

### 阶段 A：醒来后的第一轮自由探索

**目标感受：** 玩家还不认识这个地方，但村庄不是敌对迷宫；玩家可以先恢复、看路、试交互，再决定下一步。

- 炉火与检查点提供明确的安全锚点，但两者功能分开。
- 蜜忒的家是私人空间，房门与蜜忒本人的交互焦点不得冲突。
- 守门人只提示“村庄有几条路，先认路”，不把主线答案直接交给玩家。
- 年轻人表现出似曾相识，但不立即解释主角过去。
- 商人提供观察视角与基本交易氛围；第一版不增加制作、材料采集或配方系统。
- 墓地、酒馆、空置教堂都可调查；初次进入时不出现复国军营地。短交互提供不同性质的可观察事实，不只是同样格式的长文本。
- 北门和旧排水通道都清楚显示当前状态：一个有危险迹象，一个被实体障碍封住。玩家可以调查，但不能用普通交互绕过既有防卫门槛。

**初次离开村庄前，玩家应自然理解：** 村庄有多条路线；北门存在眼前危险；村庄居民对主角有不同反应；屋顶值得探索；某些入口需要更强的共鸣或后续事件。

### 阶段 B：村庄防卫完成后

**目标感受：** 玩家做了一件真实影响空间的事，世界给出持续反馈。

- 北门 POI 改为“旧朝圣路”，门体/守门人状态体现道路已恢复。
- 旧排水通道由封闭状态变为可通行，明确提供另一条进入 A3 的路线。
- 守门人对防卫结果有简短回应，但不重复播放完整战斗说明。
- 村民不应全部同时变成欢庆 NPC；有人松口气，有人担心道路重新打开后会带来什么，也有人只关心日常恢复。
- 该阶段开放的是地图状态与普通对话差异，不自动揭露教会、外神或蜜忒的核心秘密。

### 阶段 C：探索其他区域后回村

**目标感受：** 回访有价值，但不要求每次回村都触发大事件。

- 只有满足明确条件的 NPC 才更换台词、出现或离开。
- 角色的反应必须对应主角实际经历：进入某个区域、完成特定事件、取得/阅读物品，不能因为地图拓扑上“可到达”就当作玩家去过。
- 允许“静默回访”：若没有新事实，角色保持正常对话，不强行播放重复剧情。
- 普通事件的反馈以人物位置、工作状态、路线状态、短对话或真实奖励为主；避免只新增一批同质化笔记。

### 阶段 D：疯狂神职人员事件后，主角实际返回村庄

- 保留现有条件 `returned_to_village_after_mad_cleric` 作为崖下洞窟入口出现的依据。
- 入口出现本身应当是空间反馈；不要强制弹出解释整件事的长文本。
- 村庄 NPC 只谈论他们实际看见或听说的异常，不把这次返回当成所有角色都知道的全局广播。
- 该阶段可以改变环境、部分角色的警觉和可调查对象，但核心洞窟内容与其世界观含义仍按正式剧情设计另行确认。

### 阶段 E：更深层的中后期回访

此阶段只预留扩展口，不预设最终秘密。后续可以根据已确认的区域事件增加进度 NPC、临时来访者、离开的角色或对话变体。不能把结局资格直接绑定到 A1 某位 NPC 的好感值，也不能用 A1 的普通事件替代结局要求的真实探索、关键道具与特殊事件链。

## 3. NPC 阵容：保留职责，重新设计表达

第一版先区分“常驻核心角色”“常驻功能角色”“进度角色”。当前台词多数是原型占位，以下是重设计方向，不等于最终对白。

### 3.1 蜜忒（核心角色，稳定常驻 / 特殊状态例外）

**职责：** 让玩家有一个具体的人可以建立关系；她的日常行为要先可信，再逐步显露与其他事件之间的异常联系。

- 初期：做一些可观察的日常行为，不以神秘台词代替人格；可以谈村庄生活、房子、炉火或主角伤势。
- 回访：只在她实际知情或亲历事件后改变对话；不自动知道主角在远方完成的一切。
- 特殊状态：现有 `mite_connection_missed` 的空椅子表现继续保留，但它应由既有关系剧情状态控制，不作为普通探索失败的惩罚。
- 边界：不在 A1 直接揭示她的真实身份；不把身体结合设置为任何结局的必要条件。

### 3.2 村庄守门人（常驻功能角色，稳定 ID：`village_gatekeeper`）

**职责：** 提供路线安全感与村庄公共态度变化。

- 初见：说明村庄可自由探索、北门危险，但不派发强制清单。
- 防卫前：能指出门外的可见迹象，不直接解释敌人来源。
- 防卫后：承认道路恢复，同时保留对旧朝圣路的戒心。
- 路线变体：保留当前 route-specific 台词作为原型输入，但后续应确认不同路线为何改变其认知；不能只因为全局 route 字段不同就让他无缘由地知道特定秘密。
- 空间：现有 x≈760 与蜜忒 x≈800 距离过近，重设计地图时必须调整两者站位或交互范围，不能只在文字上区分角色。

### 3.3 失忆的年轻人（常驻功能角色，稳定 ID：`amnesiac_youth`）

**职责：** 展现“记忆不可靠”，不是提供答案。

- 初见：他有模糊的熟悉感，但无法确认主角身份。
- 中期：只有在玩家实际取得相关证据或触发明确事件后，才会把零碎记忆与当下事实联系起来。
- 对话结构：至少区分初见、已有新证据、相关事件发生后三种状态；每次变体要给出新信息或不同态度，不要仅重复“我想起了什么”。
- 边界：不能成为讲述主角完整过去的全知角色；具体记忆真相留待核心剧情确认。

### 3.4 旅行商人（常驻功能角色，稳定 ID：`traveling_merchant`）

**职责：** 让世界存在真实的交换、流动和外界消息。

- 初见：先以行商身份出现，交易和路线信息服务于玩家理解地图。
- 中期：对玩家真正带回的物品、区域经历或已发生事件作出有边界的反应。
- 奖励原则：优先考虑直接出售/交换已有功能物品、提供地图提示或开启一个明确的非制作型支线；不添加材料收集、配方、加工台或制作循环。
- 边界：不让商人用一句话解释所有阵营与世界观；其传闻要标注为传闻而非绝对事实。

### 3.5 新增普通 NPC 提案：修门人 / 木匠（暂名，待实现）

**职责：** 让村庄防卫前后变化有可见的人物承载，也为地图闭环提供真实反馈。

- 防卫前在北门附近工作或检查损坏结构，但不挡住出口焦点。
- 防卫后转移到门边修复设施，玩家能看出道路变化不是只有文字变了。
- 交互以观察工作进度、简短对话和一项实际地图反馈为主。
- 他不掌握教会实验、外神或蜜忒身份等核心秘密。
- 如果当前系统不支持可见的门体/结构状态变化，应先做简单的节点显隐或图形状态切换，不必引入复杂建造系统。

**该角色是普通玩法设计建议，可以先实现灰盒版本；姓名、个人背景和最终台词后续再定。**

### 3.6 新增普通 NPC 提案：酒馆经营者 / 值夜人（暂名，待实现）

**职责：** 让酒馆从一段可调查文字变成有生活痕迹的空间，并承接有限、互相矛盾的传闻。

- 初期：以工作或拒绝谈论某件事体现态度，而不是一开始就抛出世界观谜语。
- 防卫后：可以根据村庄安全状态改变酒馆是否有人、门是否打开或对话内容。
- 深层回访：只对玩家真正经历过的事件做反应；可以选择不回答。
- 传闻只提供方向线索，不直接开放隐藏区域，也不替代玩家探索。

**该角色不负责解释摇篮曲的最终来源；酒馆内声音异常的核心含义仍待确认。**

### 3.7 进度型临时角色（系统预留，不在第一版填入核心剧情）

通过 `NPC_DEFINITIONS` 添加，例如未来可用来表达“外区回来的人”“受伤的巡路者”“临时离村者留下的替代反馈”等普通事件。每个进度角色必须具备：

- 稳定 NPC ID；
- 精确出现条件；
- 站位与焦点安全检查；
- 对话前 / 对话后状态；
- 离开或被替换的条件；
- 事件标记与重复触发规则；
- 离开后玩家仍能理解发生了什么的空间 / 对话反馈。

不得为了演示系统而先塞入朝圣骑士、金正或复仇女神的关键剧情版本；这些角色应在相关区域与事件链审计后按正式设定接入。

## 5. 探索奖励与地图闭环

A1 的探索奖励不靠堆叠可读文本。至少要建立以下几种互不重复的收益：

1. **屋顶路线收益**：提供更安全 / 更快的横向移动，观察村庄内部的视觉细节，并能回到地面主路；不能仅仅比地面更高。
2. **防卫后的替代路线**：北门通往 A2，旧排水通道通往 A3。两条路线的前置条件独立清楚，且玩家回访时能记住各自的空间位置。
3. **井口隐藏路线**：发现、满足共鸣门槛、实际进入 H01 是不同事实；井口周围需有视觉引导，不能只靠玩家碰巧走到交互半径。
4. **崖下洞窟**：只有现有规定的事件后实际回村才出现，作为强反馈，不在初期预告其内部真相。
5. **普通奖励**：优先选现有物品、恢复资源、商人交换、捷径或明确的路线信息；不要新增制作材料循环。
6. **回访反馈**：完成 A2 / A3 / 其他已存在区域事件后，只有对应状态真正发生改变时才刷新 NPC 或环境。不要为每次返回都制造强制剧情。

## 6. 交互与状态模型

### 6.1 状态事实来源

- 使用现有 `WorldState.achievement_flags` 记录普通一次性事件完成事实。
- 使用现有实际进入区域记录判断探索，不用“已解锁路线”替代。
- 使用现有物品收集 / 持有 / 阅读数据判断具体证据状态，且不混淆取得、持有和使用。
- 使用 `world_event_director.gd` 的 manifest 管理进度 NPC、对话变体和事件触发。
- 只有当现有状态无法准确表达事实时才新增字段，并为旧存档定义默认行为。

### 6.2 对话变体规则

每个 NPC 最多先设计 3–5 个有实际意义的状态层，避免对话矩阵失控：

1. 初次交谈；
2. 某个可验证事件完成后；
3. 获得 / 阅读相关证据后；
4. 特殊回村或世界状态变化后；
5. 已经谈过但当前没有新变化时的短回访台词。

具体 NPC 不必具备全部层级。条件应从最具体到最一般排列。没有新内容时保留简短的常规回话，不重复播报大段剧情。

### 6.3 事件与 NPC 刷新

- 事件写入持久 flag 后，才刷新进度 NPC。
- 同一个 NPC 刷新不能清理主角、常驻 NPC、门或 POI。
- 对话事件使用 NPC 的稳定 ID；POI 事件使用 POI 稳定 ID。
- 一次性交互不得因为死亡、Continue 或重复进村而再次发放奖励。
- 事件效果目前只支持安全增删 flag；若要改门、播放演出或发放物品，应由对应系统监听信号并执行，不在通用事件表中直接操纵任意节点。

## 7. 需要在实现中修正 / 验证的当前问题

这些是从源码静态阅读发现的设计风险，不代表已在 Godot 运行时复现：

1. **守门人与蜜忒站位冲突**：两者目前约 x=760 与 x=800，间距仅 40px，而交互焦点半径远大于此；必须重新分配空间锚点或采用明确焦点优先级，避免两个角色抢提示。
2. **常驻 NPC 尚未使用进度 manifest**：守门人、年轻人、商人仍由 `village_hub.gd` 内条件分支生成；第一版可以先保留，但正式重构时应迁移到统一 NPC 数据定义或用独立 dialogue provider，避免两套逻辑长期分裂。
3. **POI 事件触发时机**：当前 POI 对话结束后分发事件并刷新，再调用场景切换处理。需要验证进入酒馆等场景前，POI 交互事件不会被目标场景加载或保存覆盖。
4. **一次性事件并发安全**：通用事件导演的 `_dispatching` 必须确保所有路径都恢复为 false；建议用 `try/finally` 不可用的 GDScript 安全模式或避免事件效果内重入。错误 / 提前退出不能永久锁住事件系统。
5. **事件 ID 与完成 ID**：`world_event_fired:<id>` 目前代表一次性触发，不一定等于“事件已成功完成”。设计文档中要分别定义“触发”“完成”“奖励已发放”，避免以后用一次对话代替战斗成功事实。
6. **进度 NPC 刷新**：NPC 条件只在刷新时重新评估。其他区域直接改变 WorldState 后，应在 A1 回访或在村庄内状态变化时主动调用刷新入口。
7. **空间 / 跳跃**：屋顶平台和地面回环需要实机验证跳跃距离、碰撞承托、落地后的可继续移动性和门焦点距离。静态画线不能作为可达证明。
8. **中英文本混用**：当前部分角色在不同 route 分支输出英文、默认分支输出中文。正式剧情实施时应统一中文原型文本，避免一组状态看起来像漏翻译。

## 9. 核心剧情待作者确认项

以下内容不在本版擅自决定：

- 蜜忒真实身份、她与外神痕迹的最终关系、她的关键命运；
- 主角失忆的具体过程与年轻人的完整记忆真相；
- 朝圣骑士、金正、复仇女神的关键事件与命运；
- 酒馆摇篮曲、墓地钟声与旧朝圣路的最终因果；
- 第三根脐带相关物品的正式 ID、“使用四次”的语义和目标；
- 三种结局的实际条件映射、关键道具链和最终演出。

正式剧情设计应先写“角色知道什么 / 不知道什么”和“玩家实际做过什么”的事实表，再写对白；不得先写一句神秘台词，再为了它倒推未经确认的世界观事实。
