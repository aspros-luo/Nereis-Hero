# 叙事呈现审计与去旁白迁移计划（V1）

> 项目：Nereis-Hero  
> 分支：`feature/story-map-progression`  
> 状态：叙事硬规则已写入开发协作条约；已完成 A0→A1 初次抵达和 A1 自动提示的第一批低风险迁移；其余对白仍待台账化审计；未运行 Godot 运行时验收。  
> 核心约束：**剧情通过环境、物品 / 装备、NPC 对话和玩家行动后的世界变化表达，不用旁白替玩家解释。**

## 1. 规则边界

### 必须移除或迁移的内容

- 全知叙述者直接告诉玩家“发生了什么 / 这意味着什么”。
- Hero 的内心旁白替玩家总结记忆、动机、感情或线索结论。
- 进入区域后自动弹出多行叙事文本，只是描述玩家已经能看见的环境。
- 直接告诉玩家某物“证明了某真相”，而不是让玩家检查物品、阅读记录、观察场景或询问知道此事的人。
- NPC 无缘无故知道主线秘密、替设计者解释设定的对白。
- 重复的旁白提示已经在场景、物品描述或 NPC 对话中表达过的信息。

### 可以保留的内容

- 必要的操作提示，例如按键、交互、存档、物品获得 / 丢失确认。
- 不解释剧情的简短反馈，例如受伤、无法使用、门被锁住。
- NPC 实际说出的对白——但必须符合人物身份、亲历范围和当时状态。
- 可被理解为角色现场发出的声音 / 简短台词，而不是无来源的全知叙述。
- 为无障碍需求提供的简洁信息；优先允许设置或可选查看，不强行打断探索。

### 迁移原则

**先保留信息，再改变载体。** 删除一段旁白前，先标记它提供了哪些事实、情绪、线索和状态变化，再逐项决定承载位置：

| 原旁白承担的内容 | 优先迁移到 |
|---|---|
| 地点历史 / 曾经发生的事 | 建筑损坏、尸体与摆放、被覆盖的铭文、场景变化、可检查记录 |
| 人物过去与关系 | NPC 在不同状态下的短对话、共同地点的生活痕迹、赠与或遗留物品 |
| 世界制度 / 政治冲突 | 征兵告示、军需账目、物资分配、阵营标记、士兵之间的不同意见 |
| 教会实验与身体异常 | 手术器具、病例、装备 / 道具描述、实验空间布局、不同证据之间的矛盾 |
| 蜜忒的情感 | 烹饪、食物、习惯、等待 / 缺席、生活空间变化、她本人自然的对话与行动 |
| 线索之间的联系 | 不同区域的重复图案 / 材料 / 记录与玩家自行比较；不要由旁白给出答案 |
| 进入 / 离开 / 操作反馈 | 简短 UI 提示，不添加剧情解释 |

## 2. 第一轮源码抽查发现

本节是已读取文件的具体例子，不宣称已经枚举全仓库所有叙事调用。

### A. `scripts/core/narrative_manager.gd`

目前同一个展示系统同时承载 NPC 对话、物品 / 事件反馈、场景旁白和主角内心总结。这会让剧情文本很容易以“标题 + 多行文字 + 自动暂停”的形式出现，无法从系统层面区分内容来源。

发现的高优先级样例：

- **已迁移第一步**：`play_first_memory()` 不再使用“记忆”标题、老猎人脸色变化的旁白和“村庄之外传来摇篮曲回应”的解释性句子；保留为老猎人本人关于主角旧习惯的一句回忆。仍需确认触发入口是否确实是玩家主动与老猎人交谈，而非自动调用。
- `begin_first_choice()`：把“道路记得你”、印记温度、歌声和对过去的猜测一起放进选择弹窗。应改为玩家先看见印记 / 听见歌声，再通过游戏内可见的选择对象或简短交互决定跟随哪个方向。
- `_select_choice()`：选完后由文字解释“某个人早已料到你会回来”或主角“想起了教会找到他之前的村庄”。这些属于直接给出结论 / 记忆，应该迁移到物品、场景和有来源的 NPC 反应。
- **已迁移**：`play_weapon_upgrade()` 移除了“像记得自己如何死去一样战斗”以及“剑刃更加致命”的解释性总结，改为老猎人直接给出简短架势建议；武器升级效果由装备 / 战斗系统体现。

### B. `scripts/levels/mite_house.gd`

- **已迁移**：删除首次进入自动弹出的 `YOU WAKE IN A SMALL ROOM` 旁白；房间绘制层新增晾着的湿衣、两套餐具和带污迹的绷带等可观察细节，承担“主角受过照料、屋里曾为两人准备食物”的部分信息。源码已提交，仍需 Godot 实机检查摆放与可读性。
- 休息 / 关系推进使用 `NOT YET`、`A QUIET NIGHT`、`AFTER THE LAST SONG` 等标题和描述性文字。可保留必要的 NPC 台词与实际发生的事件，但不应由标题和旁白直接命名 / 总结玩家当前处于哪个关系阶段。
- `_complete_union()` 的“皮肤下的温暖”可转为角色动作、短暂动画、声音、灯光 / 音频变化，以及蜜忒一句符合当下情境的疑问。不能仅靠文本告知玩家发生了何种超自然反应。
- 这类内容可能涉及重要剧情状态；改写时必须保留状态记录与存档行为，且不得让身体亲密成为结局判定的必要条件。

### C. `scripts/levels/village_hub.gd`

- **已迁移**：移除进入村庄后自动播放摇篮曲的计时器；移除首次进入 A1 后自动弹出的“村庄认得他”等介绍性旁白；初始 HUD 指引改为简短的探索 / 交互操作提示。
- **已迁移**：移除击败疯狂神职人员并返回村庄后自动弹出的蜂鸣解释文字。崖下洞窟仍通过世界状态改变后出现的实体入口与交互提示呈现；后续应补充可主动发现的环境声 / 可检查线索，不能把失去的解释文字简单视为全部迁移完成。
- 墓地、酒馆、复国军营地、教会等 POI 目前以固定多行文字复述玩家眼前的门、篝火、钟塔或铭文。应优先做成场景细节与可检查对象；只有真正知道信息的人才补充短对白。
- 守门人、失忆年轻人、旅行商人的对白包含高价值解释性信息。先核查身份、亲历和知识边界，再决定删改；不能单纯将旁白改成 NPC 说话就算解决。
- 蜜忒缺席的“空椅子 / 温热杯子”方向可以保留为环境叙事，但应让玩家主动发现 / 检查；交互文字不必再把可见事实重复讲一遍。

## 3. A0–A13 的统一叙事呈现合同

每个剧情节点进入开发前，必须登记：

1. **玩家可直接观察什么**：地形、动作、声音、物品、人物姿态。
2. **玩家能主动检查什么**：物品 / 装备描述、告示、信件、账本、铭文、尸体或机关。
3. **谁可以说什么**：NPC 的亲历、职业知识、传闻来源与误解。
4. **玩家需要自己推断什么**：线索组合与矛盾，不由文本给出最终解释。
5. **玩家行动会改变什么**：人物位置、环境、道具状态、门、营地、音乐 / 灯光或后续反应。
6. **是否需要 UI 文本**：若需要，解释为何不能用环境、物品或角色行为表达；UI 文本必须短且不承担全知剧情说明。
7. **错过后如何处理**：内容是否永久错过、是否有其他证据路径，以及不能再知道的信息是什么。

## 4. 执行顺序

### N0 — 规则冻结（已完成）

- 将“无解释性旁白、以游戏世界载体呈现剧情”写入 `DEVELOPMENT_WORKING_CHARTER_CN_EN.md`。
- A1 设计基线与本审计文档引用此规则。

### N1 — 叙事文本台账

- 逐一盘点 `show_message`、`show_caption`、自动弹窗、选择文本、区域进入提示、过场对白和叙事音频触发。
- 为每条内容标注来源：旁白 / Hero 内心 / NPC 对话 / 物品描述 / 操作提示 / 系统反馈。
- 标注剧情事实、情绪功能、是否重复、替代载体和所需状态条件。
- 优先处理 A0、A1、A2 与关键结局节点；不得只审计村庄而遗漏全局系统。

### N2 — 载体迁移

- 先改场景与交互呈现，再删去对应旁白。
- 为物品 / 装备描述建立统一可检查入口；若入口尚不存在，先复用既有物品系统设计，不另造制作或材料循环。
- NPC 对话改成短句、分状态、可重访；不得把全知旁白转交给全知 NPC。
- 声音和演出要有世界内来源；不要每次进图自动播放来提示玩家该如何理解。

### N3 — 验收

- 静态审计：剧情事实没有因删除旁白而丢失；每个替代载体都有实际触发入口。
- 游戏内审查：不读旁白仍能通过探索获得关键事实；玩家可忽略可选线索，不会被弹窗强制剧透。
- 状态审查：新档、旧档、回访、错过事件和不同结局记录保持一致。
- Godot 运行时验收单独记录。提交、静态审计和引擎实测不得混称。

## 5. 本轮结论

当前问题不是单纯“旁白太多”，而是叙事系统没有区分**角色说话、玩家检查、环境反馈与全知解释**。第一步是统一规则并建立内容台账；随后逐场景迁移信息，再移除解释性文本。

本轮已移除 A0→A1 的几处自动旁白 / 自动音频提示，并将首批信息转为环境细节；`play_first_memory()` 与 `play_weapon_upgrade()` 也已改为更符合人物身份的短对白。`begin_first_choice()` 仍保留旧的解释性选择面板，因其引用入口和状态依赖尚未确认，暂不盲目删除。全项目文本台账、其余 NPC / POI 文案迁移、物品描述承接，以及 Godot 实机验收仍未完成。

## 6. 首次路线选择：调用入口与状态依赖复核（本轮）

### 已确认

- 当前 A0 主流程脚本 `scripts/levels/escape_prologue.gd` 的初始化、探索、出口伏击与离场逻辑中，没有发现对 `NarrativeManager.begin_first_choice()` 的直接调用。
- `scripts/core/narrative_manager.gd` 仍保留旧选择面板；选择后会调用 `WorldState.make_first_choice(choice)`，并继续显示“有人早已料到你会回来”或主角自行回忆过去的解释性文字。
- `WorldState.make_first_choice()` 会设置 `first_choice_made` 与 `selected_route`，并改变 `church_alignment` 或 `lullaby_resonance`；这些状态被存档 / 读档，并被后续区域 NPC 与路线系统读取。
- 因此，旧选择面板很可能是遗留入口，但仅凭 A0 脚本未发现调用，不足以断定它在整个项目中完全无人调用。GitHub 代码搜索没有返回该符号结果，也不能替代对当前分支完整引用的确认。

### 进一步状态核对

- `scripts/levels/route_scene.gd::_ready()` 会在进入路线场景时直接把 `WorldState.selected_route` 设为场景导出的 `route_id`。因此路线场景本身可建立路线状态，不依赖旧选择面板。
- `WorldState.get_resume_scene_path()` 在 `slice_complete` 且 `selected_route` 非空时才恢复路线场景；否则回到 A0。读档默认值会把缺失的 `first_choice_made` 设为 `false`，把缺失的 `selected_route` 设为空字符串。
- 当前实际 A0 主流程是教会手术所 / 逃离 → 洞外强制败北演出 → 蜜忒的家；该流程没有在上述入口中呈现“印记 / 摇篮曲”分支。因此旧面板文本和现行开场路线之间存在明显的叙事设计脱节。
- `church_alignment` 与 `lullaby_resonance` 不仅是展示字段：旧选择函数会分别修改它们，路线记忆 / 结局评价也可能依赖这些值。若废弃旧选择，不应机械地将旧选择结果补写给所有新档；需要先定义开场到 A1 的正式状态语义，再确认各评价条件。

### 本轮处理决定

暂不删除 `begin_first_choice()`、`_select_choice()` 或 `WorldState.make_first_choice()`。删除展示层却不处理路线状态，可能让新档的路线值为空，或令旧存档 / 路线场景行为不一致。

### 下一步验收项

1. 在当前分支完整检索所有脚本、场景与动态调用，确定是否存在间接入口。
2. 梳理 `first_choice_made`、`selected_route`、`church_alignment`、`lullaby_resonance` 的首次赋值、读档默认值与全部读取点。
3. 若确认选择流程已经废弃，制定兼容方案：保留旧存档状态；为没有选择状态的新档定义符合故事的首次状态来源；不再使用解释性选择弹窗。
4. 若选择仍是现行机制，将其迁移为世界内可主动发现的线索 / 交互，不通过弹窗替玩家解释印记与摇篮曲的含义。
5. 静态核查完成后，再运行 Godot 场景与存档回归；目前尚未执行运行时验收。

## 7. 叙事状态与实际交互入口：全链路静态核查

> 范围：当前分支中已读取的 A0 主流程、A1 村庄、蜜忒家、叙事管理器、物品目录、世界线索交互、WorldState 存档 / 路线恢复与结局评价。此处是源码静态审计，不等于已完成全仓库运行时验证。

### 7.1 状态流向

1. **A0 手术所入口**（scripts/levels/escape_prologue.gd）
   - _spawn_clue() 放置 escape_surgical_mark；玩家主动按 E 检查后，_on_clue_examined() 调用 WorldState.mark_ancient_residue_awakened()，并展示托盘描述。
   - _spawn_item_pickups() 放置 church_bandage 与 surgery_record_fragment。拾取脚本会入包并立即调用 mark_item_read()，随后弹出物品说明。因此“已读”实际等于“拾取时自动展示”，不是玩家主动从物品栏阅读。
   - A0 出口要求击败出口伏击的三名守卫才开启，属于实际战斗门槛，而非叙事状态选择。
2. **A0 洞外 → 蜜忒家**（scripts/levels/prologue_exterior.gd）
   - 强制败北演出直接调用 mark_prologue_complete()，将位置保存为 mite_house 并切换到蜜忒家。
   - 已检查的当前 A0 主流程中，没有调用 NarrativeManager.begin_first_choice()，也没有通过 WorldState.make_first_choice() 选择教会 / 摇篮曲路线。
3. **A1 村庄 NPC**（scripts/levels/village_hub.gd）
   - 守门人、失忆青年、旅行商人的台词由 WorldState.selected_route 与人性状态分支决定。
   - 新档 selected_route 默认空字符串，而守门人 / 青年 / 商人代码对空值走 else 分支，实际上把“未选路线”当成摇篮曲路线口径。这是明确的状态语义缺陷：空值不是玩家作出的摇篮曲选择。
   - 北门前往 A2 依赖 village_defense_survived 成就标记；它与旧路线选择不是同一状态。
4. **旧路线选择与恢复**（scripts/core/narrative_manager.gd、scripts/core/world_state.gd、scripts/levels/route_scene.gd）
   - begin_first_choice() 是旧面板入口；_select_choice() 调用 make_first_choice()，写入 first_choice_made、selected_route，并增加教会倾向或摇篮曲共鸣。
   - 当前已检查的 A0 主流程没有调用该入口；route_scene.gd 进入路线场景时又会按 route_id 直接覆写 selected_route。
   - 存档保存这些状态；读档缺失字段时 first_choice_made 默认为 false、selected_route 默认为空。不能把默认空值冒充路线选择，也不应给所有旧存档强行补写某条路线。
5. **线索与隐藏抵抗**（scripts/world/world_clue.gd、scripts/core/world_state.gd）
   - 世界线索被检查后写入 world_clues_seen、增加记忆并保存；墓地墓碑线索另行登记 graveyard_bell 锚点来源。
   - 隐藏抵抗由四类规范来源去重计数，达到三份后唤醒；这条链路与旧 church_alignment / lullaby_resonance 不是同一套系统。
6. **结局**（scripts/core/ending_evaluator.gd）
   - 结局候选依据隐藏共鸣、真相锚点、隐藏区域探索数与特定观察者反应来源判定；代码注释明确身体结合不是结局门槛。
   - 因此不能把身体结合或旧的首次路线选择直接当作结局必要条件。

### 7.2 发现的问题与风险级别

- **P0：新档路线状态为空，却被 NPC 当成摇篮曲分支。** 当前 A0 流程未建立该选择，但 A1 多个 NPC 直接使用 selected_route == church，否则进入另一套台词。建议采用显式三态语义（未定 / 教会 / 摇篮曲）；未定状态使用中性且符合 NPC 认知的台词。不得静默映射为摇篮曲。
- **P0：A1 教会入口会提前判定蜜忒关系错过。** _enter_village_location("church") 在玩家尚未记录 mite_stay_a_while 时直接调用 mark_mite_connection_missed()。这是不可逆的关系状态写入，与自由探索村庄的设计冲突，也可能让玩家因探索顺序永久失去关系线。改动前应先审计该标记所有写入点与关系线依赖，再定义明确、可理解且有补救窗口的错过条件。
- **P1：A0 物品说明在拾取时自动标记已读。** 这混淆“获得”和“主动阅读”；若后续提示依赖 read_item_ids，会造成玩家未实际查看背包仍被视为读过。应先盘点所有读状态消费者，再分开 collected 与 read 状态。
- **P1：叙事管理器把 NPC 台词、物品检查与场景旁白放在同一个消息面板。** 现有调用可运行，但接口没有表达信息来源类型，增加误写旁白、直接把线索结论告诉玩家的风险。后续应按 NPC 对话 / 物品检查 / 短促系统反馈分层，并保留现有输入锁和暂停行为。
