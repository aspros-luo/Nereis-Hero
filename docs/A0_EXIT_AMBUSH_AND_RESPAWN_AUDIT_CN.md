# A0 出口伏击与重生安全审计

## 本轮目标

- A0 开场只呈现探索、环境叙事与物品，不预先实例化敌人。
- 主角靠近出口区域（世界坐标 X >= 1710）时触发伏击。
- 伏击由左右两侧的守卫与一名从上方坠落的守卫组成。
- 只有清除全部伏击敌人后才打开出口与战斗场地闸门。
- 死亡重生点必须位于手术台碰撞体之外；战斗中死亡后允许玩家重新进入尚未完成的遭遇。

## 已实施的代码调整

### 重生与休整点

- 初始检查点改为 `Vector2(420, 540)`。
- 主角开场出生点与休整点均移动到 X=420 的空旷地面。
- 手术台碰撞体仍位于 X=280 附近，不再与主角出生/检查点重叠。

### 出口伏击

- 移除 A0 `_ready()` 中的敌人和闸门即时生成。
- 主角推进到出口区域后调用 `_start_exit_ambush()`，生成三名守卫。
- 两端闸门只在伏击开始时创建，全部敌人被击败后统一移除。
- 如果伏击过程中死亡，重新打开场地入口闸门，避免重生后被锁在场地外。

### 敌人 AI

- 为守卫补充重力与地面判定，支持上方坠落入场。
- 攻击前摇期间锁定朝向；只有在水平与垂直距离均合理时才释放攻击。
- 进入攻击距离后主动减速停止，不再在冷却期间持续推挤玩家。
- 错开右侧与坠落守卫的首轮攻击，并抑制附近同类守卫同时进入攻击前摇。

## 待本地 Godot 4.6.1 验收

1. 新开 A0：场景开场没有敌人；可自由探索并拾取物品。
2. 在 X<1710 区域活动时不会提前触发伏击。
3. 接近出口后左右守卫出现，上方守卫落地后能正常追击与攻击。
4. 三名敌人全部击败前，出口不可交互；清场后闸门打开。
5. 伏击前死亡重生后可正常左右移动、跳跃；身体不与手术台重叠。
6. 伏击中死亡后能从检查点返回战斗，不会被入口闸门永久封锁。
7. 观察敌人是否出现悬空、地面抖动、连续同帧攻击、隔空攻击或穿过场景碰撞体。

## 翻滚穿敌人建议（本轮暂不改）

建议后续作为独立战斗手感选项实施：翻滚期间临时忽略普通敌人的身体碰撞，但继续保留墙壁、地面和场景障碍碰撞；攻击伤害规避仍由闪避无敌帧单独控制。先验收基础闪避与本轮 AI，避免同时改变太多战斗变量。

- S02 伏击敌人场景及其脚本/碰撞组件引用均存在。

### 伏击 AI 根因与修复

- 根因：伏击守卫由 `a0_s02_escape.gd` 加入 `Wardens` 子节点，因此守卫脚本中的 `get_node_or_null("../Hero")` 实际查找的是 `Wardens/Hero`，并非场景根节点下的 Hero。目标节点为空时，守卫持续执行无目标分支，只受重力影响，不会追击或攻击。
- 修复：Hero 场景根节点加入 `player` 组；`experiment_warden.gd` 改为通过 `get_first_node_in_group("player")` 获取目标，不再依赖敌人嵌套层级。
- 保留原有伏击设计：左右两名先出现、第三名从上方坠落；保留重力、攻击前摇、攻击冷却、同伴错峰攻击与清场后开放出口的流程。

### 验证边界

- 已完成 GitHub 远程源码与资源路径静态复核，并提交 AI 目标引用修复及 A0 场景颜色规范化。
- 尚未在本地 Godot 4.6.1 执行项目导入、场景解析、碰撞和逐帧战斗验收；不能将静态复核描述为运行时 PASS。
- 本地验收重点：新游戏进入 S01；S01 进入 S02；触发线触发伏击；左右守卫主动接近并攻击；第三名落地后能追击攻击；死亡重生后伏击可重试；清除三名守卫后出口开放。

### 2026-10-30 追加：S02 伏击生成期间物理查询错误修正

- 用户实机日志显示，`body_entered` 触发伏击时，敌人 `Area2D` 在物理服务器刷新查询期间初始化，导致 `area_set_shape_disabled()` 报错。

- 该修正只调整执行时机，不改变伏击触发条件、敌人数量、波次顺序或战斗数值。
