# A2《空洞骑士式》探索空间重构方案

> **权威性说明（2026-10-24）：** 本文是历史方案/审计资料；若与当前 A2 房间架构或入口规则冲突，以 docs/maps/A2_DESIGN_BASELINE_CN.md 为准。本文中的旧实现描述不代表当前代码状态或实机验收通过。

> 目标：解决“地图变大了但仍然空洞”的问题。这里借鉴《空洞骑士》的探索设计方法，不复制其具体地图、美术、角色或叙事内容。
>
> 当前状态：设计合同。需要据此重做 A2 的空间组织与灰盒表现；不能把现有 3600px 横向平台链视为最终方案。Godot 实机可玩性尚未验证。

## 1. 诊断：为什么现有扩建仍然像空平台

当前方案主要增加了地图宽度、平台数量和一条远端出口，但仍有四个根本问题：

1. **横向优先**：空间主要沿 X 轴展开，玩家看到的是连续的平台串，而不是有边界、有高度差、有遮挡的地点。
2. **平台没有空间语义**：平台只负责站立，没有明显说明它属于钟墓、树冠、断桥、朝圣建筑或地下回廊。
3. **路线缺少发现过程**：出口靠坐标延长，而不是让玩家先看见远处目标、暂时无法抵达，再通过另一条路径绕到目标。
4. **探索回报太单薄**：玩家主要是在跳平台和经过敌人；缺少捷径、空间重识别、危险下探、环境互动、隐藏入口与可选战斗的组合。

因此，下一版不应继续无差别增加平台。必须先把 A2 划分成可辨认的“房间／区域”，再设计这些空间之间的路线关系。

## 2. A2 的新空间骨架

把 A2 做成一个横向连通、纵向叠层的探索区域。建议仍然保留一个主场景，但在场景内部形成 8 个有明确身份的空间单元。

| ID | 空间名 | 层级 | 玩家体验 | 主要连接 |
|---|---|---|---|---|
| A2-R01 | 雾林入口 | 地表 | 安全起步；远处可看见钟墓轮廓和高处残桥 | R02、R04 |
| A2-R02 | 倒塌钟墓外圈 | 中层 | 环绕巨大钟墓，能从不同高度看到内部 | R01、R03、R05 |
| A2-R03 | 钟墓坑底 | 深层 | 可选择下落；有可回跳路线、危险落点与 H02 的视觉暗示 | R02、R07、H02 |
| A2-R04 | 枯树冠层 | 高层 | 有缺口、枝干、树洞与被遮挡的上层路线；不是等距平台链 | R01、R05、R06 |
| A2-R05 | 旧朝圣者断桥 | 高层／中层交界 | 远处能看到通向 A5 的封锁结构；从另一侧开启后成为捷径 | R02、R04、A5/C04 |
| A2-R06 | 钟楼外壁 | 垂直中继 | 通过外壁、梁柱、塌陷窗洞上下穿行，建立垂直空间感 | R04、R07、R08 |
| A2-R07 | 林下排水廊 | 低层 | 低矮、有遮挡、局部单向落差；与坑底形成第二条穿越路线 | R03、R06、R08 |
| A2-R08 | 东侧残桥与树根洞 | 东端 | 主线出口 C03 不再只是平地尽头；先绕过树根洞/残桥，再登上可读的出口平台 | R06、R07、A3/C03 |

### 重要原则

- **空间单元不是新地图场景**：先在现有 A2 场景内通过地形、背景层、实体结构和路线标识建立空间感，不急于拆分成多个 scene。
- **每个区域至少有一个独特轮廓**：例如巨钟、倒悬的石棺、断桥、粗树根、外露钟楼梁柱。不能仅靠文字标题区分。
- **每个区域至少提供两种信息**：视觉地标 + 路线选择、视觉地标 + 可调查物、或视觉地标 + 危险机制。
- **不是所有路都要走通**：先允许玩家看见暂时到不了的门、平台和洞口；后续再通过回环、捷径或能力解锁重新抵达。
- **保留 Soulslike 节奏**：探索空间里放置有目的的敌人、风险落差和休整点，而不是把每个平台都变成跳跃挑战。

## 3. 需要形成的 3 个回环

### 回环 L-A：雾林入口 → 树冠 → 钟墓外圈 → 雾林入口

初次探索可沿地面进入钟墓外圈，也能尝试攀上树冠。树冠路线绕过钟墓上方，并在中层找到一处落下后可从另一侧打开的短路。玩家第一次走过时感到绕路，之后回到入口时则能认出这是同一地点。

### 回环 L-B：钟墓外圈 → 坑底 → 林下排水廊 → 钟楼外壁 → 钟墓外圈

坑底不是“掉下去再原路跳回来”的孤立坑。坑底应有两种选择：从承托平台回到外圈，或继续进入低矮廊道，再沿外壁结构爬回中层。H02 位于这一回环旁边，仍是可选内容，不得成为前往 A3 或 A5 的门槛。

### 回环 L-C：树冠 → 旧朝圣断桥 → 东侧残桥 → 林下廊道

该回环让玩家从高处看见 C03 出口、从低处经过其下方，再通过外壁或断桥爬到出口平台。C03 不应被普通地面路线直接绕过。C04/A5 保留原有解锁语义，不能因为新增路线而绕开锁门。

## 4. 关卡节奏：按“看见—尝试—绕行—发现—捷径”组织

1. **看见**：入口处就能辨认巨钟、上层残桥和远处的树冠出口，但不是全部都能直接抵达。
2. **尝试**：玩家可以攀上枯树冠层，也可以沿地面环绕钟墓；两条路的风险和视野不同。
3. **受阻**：旧朝圣断桥或某段门路暂时无法打开；用实体障碍表达，不依赖 UI 文字说明。
4. **绕行**：玩家从坑底或林下廊道进入建筑内部，再由钟楼外壁回到此前见过的高处。
5. **发现**：找到 H02 的环境线索、可选奖励或独立叙事证据；具体故事含义继续留给剧情设计，不在本文件定稿。
6. **捷径**：从另一侧打开短路后，回到已熟悉的空间明显变快；捷径必须改变真实路线，而不只是出现一条提示。
7. **离开**：最终通过东侧残桥抵达 C03/A3；在离开前仍可以回头探索未完成的分支。

## 5. 灰盒不再只是矩形平台：空间表现合同

当前可先继续使用矩形碰撞，但视觉上必须用可复用的结构层将其组织起来。

- **背景远景层**：低对比雾林轮廓、远处钟墓与树冠；远景不参与碰撞。
- **中景地标层**：大树干、巨钟、断桥、外露梁柱、钟墓立面。轮廓要跨越多个屏幕，让玩家能用它们判断位置。
- **实体地形层**：地面、平台、墙体、可落下的坑口边缘；碰撞形状必须与可见边缘一致。
- **遮挡层**：树根、断墙、钟墓外壁可遮挡一部分角色或路径，制造“前景／后景”层次；遮挡不得隐藏致命落点或必要交互。
- **交互地标层**：休整点、调查物、门和可打开的捷径必须与建筑语义绑定，不能像散落在平台上的浮标。
- **路线可读性**：安全主路可辨认但不必平直；危险支路要有可见的落差提示；远处可见的路线要能在稍后通过空间连接抵达。

不要用大量装饰物来伪装空洞。优先做出少量但有体量的地标，并让路线围绕地标组织。

## 6. 探索内容密度规则

每个空间单元至少满足下列 3 项中的 2 项，才算具备可探索价值：

- 一个可识别的环境地标；
- 一个有意义的路线决策（上层／下层、风险／安全、捷径／绕行）；
- 一个互动或探索回报（调查、物品、隐藏入口、敌人、捷径开关、环境谜面）。

每个大区域避免连续出现超过两个“只有跳跃、没有发现”的平台段。敌人不应均匀撒点，而应放在狭窄通路、落差边缘、重要地标前后或回环交汇处。

## 7. 连接和既有设定约束

- C03：仍为 A2 ↔ A3 的东侧出口；保留高位到达平台和双向出生点合同。
- C04：仍为 A2 ↔ A5 的旧朝圣高路连接；保留既有解锁与回程语义，不允许普通地面绕过。
- H02：仍为可选隐藏区域；不变成主线门槛。
- SC011：应有明确的空间职责（例如连接树冠与钟墓外圈的共鸣桥），而不是孤立的一段平台。
- 不改 A0–A13 全局拓扑、不擅自确定钟声或朝圣者历史真相。
- 新增所有落差都必须有回跳承托或明确的单向意图；不得让玩家出生在门触发区、悬空处或无法返回的坑底。
- 所有新路径需要同步更新拓扑与静态验证器；不使用 GitHub Actions。

## 8. 推荐实施顺序

### P0：先做出空间骨架

1. 重画 A2 的地形剖面，先明确地面、中层、高层、坑底四种高度带。
2. 把连续、等距的平台链改成由树干、断桥、墙沿和洞口连接的路线；删除不服务路线决策的冗余平台。
3. 为巨钟、钟墓外壁、断桥和东侧树根洞建立可复用的灰盒地标轮廓。
4. 让三个回环在坐标上真实连通，保留 C03/C04/H02 的既有连接语义。

### P1：空间可玩性审计

1. 检查每次跳跃的水平距离和高度差，标出普通跳跃、风险跳跃与不可达路线。
2. 逐条检查坑底回跳、低位通道、捷径开关和转场出生点。
3. 运行现有拓扑、灰盒场景连线和空间路线验证器。
4. 在 Godot 中实际走完整个 A2，记录失败跳跃、死路、视线误导和不合理回程。

### P2：再填入探索内容

1. 为每个区域选择少量高辨识度的敌人／调查点／物品，而不是均匀铺设。
2. 设计一次“看到但暂时到不了”的路径和一次“绕一圈后打开捷径”的发现。
3. 根据实际路线决定 SC011 的用途及 H02 的入口线索。
4. 最后调整氛围、远景、前景遮挡和声音反馈。

## 9. 验收标准

A2 只有在以下条件都成立时，才算从“扩大的灰盒走廊”转为探索地图：

- 玩家能用地标而非坐标记住至少 4 个不同空间。
- 至少有 3 个真实回环，且至少 1 个回环能显著缩短回程。
- 玩家能从一个区域看到另一个区域的目标，但不能直接走直线抵达。
- 坑底既有安全回返方案，也有继续探索的可选路线。
- C03、C04、H02 的角色清晰，且没有被新路线意外绕过。
- 每个主要空间至少有 2 种探索价值来源。
- 完成一轮全路线 Godot 实机验收后，才开始大规模添加敌人与剧情内容。
