# Nereis-Hero 正式地图设计基线 / Official Map Design Baseline

> Branch: `development`  
> Source of truth: `tools/world_map_topology.json`  
> Status: design alignment in progress; Godot runtime acceptance is still required.  
> 本文只把拓扑数据转译为可读的地图布局与验收约束；不代表所有路线已通过引擎实测。

## 1. Map reading rules / 地图阅读规则

- 14 个主区域：A0–A13。宏观地图可采用“北部边境高地—中部城区与修道院—南部王墓/王城—终局深层”的箱庭式分布，但具体坐标只用于布局表达，不改变连接数据。
- 24 条连接：C01–C24。线型必须区分：常规双向主路、初始封锁后双向开启的捷径、单向流程出口、灵视条件门、终局单向入口。
- 8 个隐藏区域：H01–H08。用独立图标表示隐藏入口；虚线仅表达“隐藏/条件连接”，不能单凭线条暗示可以立即通行。
- 图上的每条线都必须标注连接 ID。视觉稿不允许创建拓扑文件中不存在的连接。

## 2. Macro layout / 宏观区域布局建议

| Map band | Regions | Visual role | Navigation intent |
|---|---|---|---|
| 北部边境 | A0、A1、A2 | 手术所、村庄、雾林与钟墓 | 序章单向逃脱后建立可回访的地面/树冠路线 |
| 中西部边缘 | A3、A5、A6 | 废弃城区、旧战场、修道院 | 以高架残墙、城墙和钟塔落差形成中层环路 |
| 中央地下层 | A4、A7、A8 | 下水道、监牢、旧王墓 | 通过竖井、供给隧道、王墓水道连接地面与王国深层 |
| 东部王城 | A9、A10、A12 | 外环、大圣堂、内城 | 主线向王座推进，屋顶步道与服务门提供后期开启的回访捷径 |
| 深层终局 | A11、A13 | 古神研究区、深层梦境 | A11 是可选深层探索；进入 A13 必须遵循各终局连接条件，不得被普通双向门表现 |

## 3. Three macro loops / 三条宏观回环

1. **L01 边境环路**：A1 → A2 → A3 → A4 → A1。依赖 `opened_sewer_inspection_hatch_from_A4` 与 `opened_watergate_and_village_well_exit`。C05/C06 的方向和解锁必须与实际闸门状态一致。
2. **L02 中层环路**：A3 → A5 → A6 → A3。依赖 `opened_bell_tower_drop`；C10 初始封锁、从 A6 开启后形成双向回访。
3. **L03 王国深层环路**：A4 → A8 → A9 → A4。依赖先经 A7 抵达 A8 并开启王墓门，以及抵达 A9 后开启王室排水道。C07/C23 不应在首次经过时被误画成已开放主路。

回环是条件满足后的宏观可达性，不表示所有边在新游戏开始时均已通行。

## 4. Direction and gate semantics / 方向与门槛语义

| Connection | Topology contract | Map notation |
|---|---|---|
| C01 A0→A1 | 单向序章出口 | 单箭头；不画普通回程门 |
| C02 A1↔A2、C03 A2↔A3 | 双向主路；C03 为高位树冠/屋顶路线 | 双向实线；标高位平台 |
| C04 A2↔A5、C10 A6↔A3、C16 A3↔A9、C18 A9↔A12、C23 A9↔A4、C24 A1↔A3 | 远端开启的双向捷径 | 锁闭图标 + 开启方向标记；不可画成初始开放 |
| C05 A3↔A4、C06 A4→A1、C07 A4↔A8、C12 A7↔A4 | 地下/回村捷径，初始访问状态与最终方向不同 | 分别标注“上层检查廊”“老井单向出口”“王墓侧门”“供给隧道” |
| C11 A6↔A7、C13 A7↔A8、C14 A8↔A9、C17 A9↔A10、C20 A10↔A12 | 双向主路 | 双向实线 |
| C15 A8↔A11 | 灵视条件隐藏门；共振≥55、古神暴露≥2，并需两个指定异常来源 | 紫色隐藏线；标出条件，不表现为常开门 |
| C19 A10↔A11 | 灵视条件隐藏门；共振≥68、外神暴露≥12、外神共鸣与镜街异常来源 | 紫色隐藏线；独立条件，不与 C15 合并 |
| C21 A11→A13 | 完成实体结合后的终局单向入口 | 终局色单箭头；不可绘制成普通回环 |
| C22 A12→A13 | 由 A10 抵达 A12 后进入终局层，单向 | 终局色单箭头；结局由现有 evaluator 决定 |
| C08 A3↔A5、C09 A5↔A6 | 双向高架/城墙主路 | 双向实线，必须显示承托平台和落点 |

**Important:** `initial_access` and `final_direction` are separate fields. A map must not infer initial accessibility from final direction alone.

## 5. Hidden areas / 隐藏区域布局

| Hidden ID | Parent / anchor | Gate presentation | Return / secondary route |
|---|---|---|---|
| H01 | A1 / 村庄老井 | 灵视，共振≥12 | 返回 A1；满足条件后可连接 A4 |
| H02 | A2 / 钟墓 | 灵视，共振≥18 | 返回 A2；抵达 A5 并开启旧钟塔连接后可连 A5 |
| H03 | A3 / 旧市场、旧礼拜堂 | 灵视，共振≥28 | 返回 A3；抵达 A9 并开启旧服务门后可连 A9 |
| H04 | A4 / 旧水库 | 灵视，共振≥36、古神暴露≥1 | 返回 A4；抵达 A8 并开启王墓侧门后可连 A8 |
| H05 | A6 / 钟塔无声窗口 | 灵视，共振≥42、古神暴露≥1 | 返回 A6；钟塔落差开启后可回 A3 指定街道层 |
| H06 | A8 / 旧王墓铭文 | 灵视，共振≥55、古神暴露≥2、两个指定异常来源 | 返回 A8；抵达 A9 后可连王室交通侧门 |
| H07 | A9 / 外环积水倒影 | 灵视，共振≥68、外神暴露≥12、外神共鸣、镜街异常来源 | 返回 A9；抵达 A12 后可连内城侧门 |
| H08 | A11 / 深层研究区观测壁 | 灵视，共振≥78、古神暴露≥2、外神暴露≥18、外神共鸣、三个指定异常来源 | 返回 A11；完成实体结合后可汇入 A13 终局层，不能绕过终局评估 |

隐藏区的入口、回程出口和二级出口应分别绘制；二级出口需要额外进程条件，不代表进入隐藏区后自动开放。

## 6. A8 Royal Tomb: vertical layout / A8 王墓多层布局

A8 应以“中心墓室 + 环形侧廊 + 竖向维护井”为空间骨架。下表是**空间设计契约**，落地时必须与场景中的平台、门和出生点逐项对照。

| Layer | Intended content | Connections / landmarks |
|---|---|---|
| L0 入口平台 | 来自 A7 的高位到达点；安全落脚与路线识读 | C13 双向入口；返程出生点必须落在可承托平台 |
| L1 外环墓道 | 可回访的左右环廊、短落差、基础敌人和宝箱 | 中心墓室可见但暂不直接抵达；通往 C14 的外环出口 |
| L2 中层仪式环廊 | 围绕中央王像的战斗空间；至少两条高低不同的可走平台 | 与 L1/L3 通过明确楼梯、竖井或单向落差连接；不允许靠背景装饰充当碰撞平台 |
| L3 王室维护井 | 视觉上隐蔽的维护管线与可交互异常铭文 | C15 通往 A11 的隐藏条件门；H06 的入口/触发点与 C15 必须分别标识，不能混为一个门 |
| L4 中心王墓 / Boss 场 | 王的残影 Boss 区域；进场与退场路径明确，战斗空间有完整承托 | Boss 区不得封死所有回程；战斗结束后通过已定义门/平台回接环廊 |
| L5 上层排水/外环出口 | 从墓室上方或侧向维护通道回到外环高位 | C14 → A9 的出口与返回 A8 的出生点成对标注；高度必须与相邻场景锚点一致 |

### A8 traversal acceptance / A8 游玩验收

- **Spawn & support**：从 A7 经 C13 进入 A8，角色落在入口平台；从 A9 经 C14 返回 A8，角色落在外环出口对应的平台。不能生成在空中、墙内或地面绕行层。
- **Jump reachability**：逐段验证 L0↔L1↔L2↔L3；每条必要路线必须有可见承托面。装饰性平台不能被路线图误标为可站立平台。
- **Boss arena**：入口、战斗空间、离场路径三者清晰；战斗触发不应覆盖出口交互区；死亡/重生后不应把玩家困在 Boss 门内侧。
- **C15/H06 separation**：C15 是 A8↔A11 连接；H06 是 A8 内部隐藏区域。两者可共享线索但不可共享未经设计的触发状态。
- **Gate persistence**：分别测试首次锁闭、满足条件、交互开启、切图后状态保持、从两侧返回、存档读档、死亡恢复。
- **Ground bypass**：检查连续地面碰撞是否让玩家绕过高位门/锁门；若门是交互触发器，需以真实碰撞或地形落差阻止未经设计的绕行。
- **C14**：从 A8 到 A9 与从 A9 返回 A8 都要验证门的触发范围、目标场景、出生侧和高度。
- **Runtime status**：以上条目只有在 Godot 4.6.1 实机走通后才能标记通过；静态拓扑检查不能替代引擎验收。

## 7. Acceptance matrix / 验收矩阵

| Layer | Static checks | In-engine checks |
|---|---|---|
| Topology | 14 区、24 连接、8 隐藏区 ID 完整；所有端点存在；方向与解锁字段不冲突 | 不适用 |
| Macro loops | L01–L03 路径边存在，条件依赖可追踪 | 开启各门后实际走完闭环，再反向走回 |
| Transitions | 场景路径、目标区域、spawn side 与连接端点一致 | 双向转场、连续转场、切图后状态、死亡/读档 |
| Platforms | 空间锚点与目标层命名齐全 | 跳跃、落地、碰撞承托、单向落差与地面绕行 |
| Hidden gates | 条件、来源、持久化与返回路线齐全 | 逐个验证未满足/满足/打开/回程/重载状态 |
| Endgame | C21/C22 均为单向且条件独立 | 两条终局入口都到达 A13；结局由 evaluator 决定 |

## 8. Source-of-truth policy / 数据权威约定

- 区域、连接 ID、初始访问、最终方向、解锁条件、隐藏区域条件：以 `tools/world_map_topology.json` 为准。
- 实际场景出口、门交互、碰撞平台、出生点：以 Godot 场景与运行时控制器为准。
- 若文档/图稿与拓扑不一致，先修正图稿；若拓扑与场景实现不一致，记录为实现缺陷并修复实现或明确更新设计数据，禁止默默用插图覆盖事实。
- 本文是可执行设计/验收基线，不声明场景运行时已验收通过。
