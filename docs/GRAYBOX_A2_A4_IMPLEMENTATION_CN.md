## 2. 进入 A2 的流程

首次在村庄使用北门，会沿用现有村庄防守章节。完成防守后写入 `village_defense_survived`。回到村庄后，北门 POI 改为“旧朝圣路”；再次互动即可进入 A2。

这样保留当前村庄防守内容，同时让 A2 进入方式有剧情因果，而不是另加一个与现有 POI 抢 E 键的传送点。

村庄防卫完成后，A1 还可选择西侧的旧排水通路直接进入 A3。该通路使用独立的 POI 与出生侧映射；A3 能返回 A1，也保留通往 A2、A4 与 A5 的既有出口。这样玩家可以先探索城市，再回头进入森林，而不是被强制锁在 A1 → A2 → A3 的唯一顺序。

## 3. R01–R04 异常调查流程

异常来源通过固定 ID 记录；同一来源只能奖励一次。每个来源把鸣响提升至其规划目标下限，而不是直接累加固定数值，因此玩家先探索后段区域、之后再回来补前置线索时，不会发生鸣响倒退或重复奖励。

| 区域 / 来源 ID | 调查内容 | 鸣响目标 | 额外效果 |
|---|---|---:|---|
| A2 / `anomaly_bell_retiming` | 钟锤不动，但钟声已经响起 | 12 | 解锁已有的 `resonance_sight`，用 V 激活 |
| A2 / `anomaly_old_pilgrim_echo` | 旧朝圣石阶上的第二处回声 | 18 | 无 |
| A3 / `anomaly_erased_street_sign` | 标牌写着不存在的第三街 | 28 | 记录后期隐藏区可引用的异常来源 |
| A4 / `anomaly_old_stone_layer` | 新管线覆盖在明显更古老的石构上 | 36 | 确保古神接触度至少为 1；若序章已经记录过，则不重复累加 |

注意：A2–A4 的来源当前已接入新灰盒脚本，但仍需在 Godot 里核实交互焦点、鸣响增长时机以及读档恢复。

A2 另有一条可选树冠平台路线；A3 具有屋顶支路和一段地图内鸣响桥（共鸣达到 28 且启动灵视时显现，按 E 固定后永久保留）；A4 有可选抬高管线栈道。它们都保留地面安全路线，不是强制跳跃门槛。

## 4. H01：显现、开启、进入、返回

H01 入口位于村庄旧井。它复用已有的 `hero_resonance`、古神 / 外神接触值、`resonance_sight_active` 和共享 E 键焦点：

1. 普通观察时只能看到一口异常石井；没有可用的隐藏入口提示。
2. 先在 A2 调查 R01，解锁 V 灵视；鸣响满足门槛后，主动激活灵视。
3. 靠近旧井按 E，将 H01 记为已发现并把隐藏通路写入 `opened_hidden_paths`。
4. 开启后再次按 E，进入 `scenes/hidden_well.tscn`；这时才记录 `entered_hidden_regions`。
5. 从隐藏井底可以返回村庄。只有已通过 A3 抵达 A4 后，A4 才会生成井底入口；它仍然要求灵视激活并达到相同鸣响门槛。两侧使用同一个 H01 ID，因此从任一侧永久开启后，另一侧也会同步保持开启；在 H01 场景里返回 A4 的门也随之可用。
6. 开启记录不依赖灵视持续状态。切图、鸣响下降、死亡或重新读档不应该重新封闭入口。

村庄旧井与 A4 的另一侧入口使用同一个 `H01` 通路 ID，避免两扇门的开门状态不同步。A4 侧入口只有在玩家通过 A3 抵达 A4 后才生成，但第一次开启仍检查灵视和鸣响门槛；不能靠走到 A4 就直接进入 H01。

## 5. 场景连接

~~~text
村庄 A1
  ├─ 首次北门：村庄防守（现有章节）
  ├─ 防守完成后：旧朝圣路 A2
  ├─ 防守完成后：旧排水通路 → A3（A3 可返回 A1）
  │    └─ R01 / R02：钟声与旧朝圣石阶
  │         └─ 废弃城区 A3
  │              └─ R03：被抹去的第三街
  │                   └─ 下水道 / 沉积大厅 A4
  │                        ├─ R04：古老石构
  │                        └─ 已开启的 H01 井门
  └─ 学会灵视后回访旧井：H01 井底回声层
       ├─ 返回村庄 A1
       └─ 达到“已从 A3 抵达 A4”条件后：返回 A4
~~~

A2–A4 的出口使用现有 `interaction_door.gd` 和共享交互焦点，不创建平行 E 键系统。出入每个区域会更新存档中的 `current_location`；`WorldState.get_resume_scene_path()` 已增加这四个场景的恢复映射。

## 6. 本地静态检查

在仓库根目录运行：

```bash
python3 tools/validate_world_map_topology.py
python3 tools/validate_graybox_scene_wiring.py
```

第一个脚本验证 14 个主区域、24 条宏观连接、8 个隐藏子区、三条大环路与鸣响门槛数据；第二个脚本检查新场景文件、脚本引用、存档字段、灵视入口接口、场景恢复映射，以及 A1–A4 新增路线的静态契约。

这两个脚本都只验证静态数据 / 接线。它们不会模拟真实跳跃、碰撞体、镜头、动态输入焦点或 Godot 的场景切换。

## 7. Godot 实机验收表

- [ ] 从游戏菜单开始新游戏，完成序章并进入村庄。
- [ ] 首次使用北门进入村庄防守；胜利后返回村庄，北门变为旧朝圣路。
- [ ] 进入 A2，与 R01 交互，确认只奖励一次并解锁 V 灵视。
- [ ] 完成村庄防卫后分别尝试 A2 林路和 A3 旧排水通路；从 A3 返回 A1 不会出生在门体或重复交互范围内。
- [ ] 在 A2 验证树冠路线，在 A3 验证屋顶路线与鸣响桥，在 A4 验证管线栈道；每区的地面路线仍然可走。
- [ ] 重新进入 A2 后，R01 不再显示交互提示；R02 可正常记录至目标鸣响。
- [ ] 从 A2 进入 A3，再从 A3 进入 A4；从 A4 返回 A3，再返回 A2，不出现软锁。
- [ ] 回村庄，在灵视关闭 / 未激活时，旧井不显示可用 E 提示。
- [ ] 灵视激活且条件满足时，旧井显现；第一次 E 永久开启，第二次 E 进入 H01。
- [ ] 开启 H01 后关闭灵视、离开场景，再回来，旧井仍然开启。
- [ ] 从 H01 返回村庄；经 A2 / A3 到达 A4 后，A4 侧井门在灵视关闭时不显示交互提示，激活灵视并达标后可调查开启；开启状态与村庄旧井同步。
- [ ] 退出游戏再点继续；`current_location` 对应场景可以恢复，已开启的 H01 不会重锁。
- [ ] 确认 NPC、门和异常源附近任意时刻只出现一个 E 交互提示。
- [ ] 检查主角死亡后回到当前灰盒检查点，不会卡在平台或门体里。

**验收结论目前为：代码 / 静态接线待进一步本地验证，Godot 实机验收尚未执行。** 当前环境没有 Godot 可执行程序，不能将本文件或静态检查结果描述成“已经跑通”。
