## 1. 审计结论

**当前代码尚未实现已确认的烈火天罚条件链。** 现有结局求值器仍使用旧原型阈值；物品目录只有两个正式物品；通用地图场景 A2 与 A8 使用灰盒区域脚本；未发现朝圣骑士、禁忌森林协作、王墓协同击败教会怪物等条件链已接入结局求值器的证据。

本次不直接重写 evaluator：在永恒乐园的正式触发条件、具体剧情事件 ID、道具获取/消耗规则尚未完成映射前，直接替换为猜测条件会把未确认的设计写成代码契约。应先补齐真实的物品与事件台账，再一并改写求值器和回归测试。

## 4. 当前 evaluator 的具体风险

`get_candidate()` 当前逻辑：

- 当 `hero_resonance >= 68`、`hidden_artifact_pieces >= 3`、已进入隐藏区域数不少于 2 时，返回「烈火天罚」；
- 否则若共鸣达标、存在 `anomaly_observer_reaction` 且进入至少一个隐藏区域，则返回「永恒乐园」；
- 其他情况返回「凡人之墓」。

该实现可能在没有回复酒、徽章、笔记、火种、朝圣骑士协战、脐带使用或指定剧情事件的情况下直接返回烈火天罚；也可能因为旧来源/区域数量而返回永恒乐园。因此，**静态上可以确认这是与新规则不一致的旧原型逻辑**。不过本次不以猜测的替代条件直接覆盖它，避免在完整路线设计前把临时设计固化。

## 5. 实施顺序与验收契约

1. 在地图与剧情内容设计阶段，确定朝圣骑士在首次相遇、禁忌森林、王墓三个节点的场景位置、对话/合作触发与失败/重入行为。
2. 建立正式剧情物品清单：稳定 ID、显示名称、获取来源、堆叠/消耗规则、当前持有条件、曾取得事实、使用对象与成功事件。
3. 建立事件事实清单：事件发生时的唯一写入点、存档字段、重复触发保护、读档后恢复行为。
4. 再实现求值器：烈火天罚逐项 AND 检查全部必要事实；永恒乐园使用另行确认的明确条件；凡人之墓作为不满足其他结局时的默认项。关系状态仅能作为获取路径的前置，不直接决定结局；身体结合不得成为门槛。
5. 回归矩阵至少覆盖：全条件完成、逐项缺失每个必要物品、合作事件未完成、未参与协战、物品已取得但不再持有（若规则要求当前持有）、只阅读未使用、使用事件失败、旧存档无新事件证据，以及三种结局互斥优先级。
6. 对正式流程做完整地图运行验收。拓扑连通、静态字符串检查、导演演出场景均不能替代从实际地图进入、拾取、战斗、触发事件到结局求值的实机链路。

## 6. 本次范围边界

- 已确认：当前正式物品目录不含目标剧情道具；目标区域仍是通用灰盒场景；现有 evaluator 使用旧阈值；导演测试场景会主动设置测试状态。
- 未确认：目标教会怪物的正式 ID、朝圣骑士场景/身份 ID、四次使用的计数语义、永恒乐园的最终完整条件、各道具要求“曾取得”还是“结算时持有”。
- 本次没有修改 evaluator、没有添加虚构道具/事件 ID、没有声称 Godot 实机通过。
