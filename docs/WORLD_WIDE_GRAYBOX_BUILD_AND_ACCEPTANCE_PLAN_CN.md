## 1. 目标范围

目标是**全世界的地图**，不是只完成 A2。A2 作为首个空间拓扑样板，提炼可复用的方法；其具体形状、平台密度或路线风格不应该复制到每个区域。每个区域都要拥有符合其叙事与地理职责的探索网络。

覆盖范围：
- 14 个主区域：A0–A13；
- 8 个隐藏区域：H01–H08；
- 78 个登记子区域；
- 73 条区域内 SC 连接；
- 24 条跨区域 C 连接；
- 升降机与宏观回环仍以拓扑合同为准，必须单独核实真实通行。

**硬规则：** 设计合同、地图示意图、静态图连通都不等于游戏可玩。只有在 Godot 中使用主角走过并验证入口、落点、回程和条件状态，才能把相应项目标为实机通过。

## 3. 统一的空间施工方法

每个区域依次完成以下步骤：

1. **读拓扑合同：** 列出本区全部子区域、SC 连接、C 连接、升降机、隐藏入口和解锁条件。
2. **确定空间身份：** 先定地理原型和标志性地标，不先复制平台布局。城市、森林、塔楼、监牢、水库、王墓和梦境应有不同的空间语法。
3. **画出内部路线网络：** 先规划分叉、短死路、回返、上下层、环路、单向落差、远端捷径和暂时不可达的可见地点。
4. **划定场景边界：** 连续攀爬/坠落尽量保持空间连续；有明确入口或独立空间体验时才切场景。场景切换不能抹掉玩家对地标的认知。
5. **搭实体灰盒：** 地面、墙、平台、竖井、楼梯、门、落脚点和返回路线必须有实际碰撞/通道。禁止只在图上连线。
6. **静态检查：** 检查引用、连接 ID、出生侧、坐标和平台承托；静态通过只算预检。
7. **主角实机走图：** 逐个走过分支、死路、回程、捷径、落差、隐藏入口、场景边界、死亡恢复和 Continue。
8. **记录问题并修复：** 记录复现步骤、所在区域、入口 ID、出生侧与坐标。没有实测的项保持未验收。
9. **后置内容：** 区域灰盒通过阶段验收后，再恢复敌人、Boss、NPC、收集品和剧情遭遇。

## 5. 各区域设计重点

### A0 · 边境手术所与逃脱通道

- **空间身份：** 序章逃脱 / 受控单向空间
- **结构方向：** 紧凑室内、观察廊、明确向下的排污井；以视线引导代替自由分叉
- **必须实现并检查：**
  - 出生点与第一条可读移动路线
  - 观察廊让玩家看见危险区域或出口
  - 单向下落后进入出口链，不能误做成普通回环
- **回环策略：** 不强求区域内回环；确保 C01 staged route 的分段方向与返回语义清楚
- **场景：** scenes/escape_prologue.tscn、scenes/prologue_exterior.tscn
- **验收状态：** 灰盒未完成审计；Godot 实机未运行。

- **结构方向：** 主街作为认知骨架，墓地、村庄边缘、旧排水与防卫事件形成支路
- **必须实现并检查：**
  - 主街可重复识别且安全返回
  - 墓地或边缘支路有回归主街的路径
  - 防卫章节是事件场景，不误认成连续地理
  - 旧排水入口按 C24 条件开放
- **回环策略：** 至少形成一条可记忆的村内小环或回返链；事件场景可单独切换
- **场景：** scenes/mite_house.tscn、scenes/village_hub.tscn、scenes/village_graveyard.tscn、scenes/village_defense_demo.tscn、scenes/old_drain_exploration.tscn

## 6. 通用验收门槛

每个区域的验收台账都应独立记录：

- [ ] 子区域与实体场景的映射完整；
- [ ] 每条 SC 连接都能对应到实际地形或通道；
- [ ] 本区应有的分叉、死路、回返和环路可实际走通；
- [ ] 高低层之间有真实可通行的连接；
- [ ] 每条 C 连接的入口和返回出生点都有安全承托；
- [ ] 出生点不与门触发区重叠，不会切场景后立刻再次触发；
- [ ] 锁定门、远端解锁捷径、灵视入口和隐藏区域条件正确；
- [ ] 地标足以帮助玩家认路，不依赖调试线或地图外说明；
- [ ] 主角已在 Godot 实机走过路线，回程也已验证；
- [ ] 实机结果、复现步骤与未解决问题已记录。
