# 箱式世界地图开发者圣经（中文）

> 状态：地图生产规范 / 持续补全中  
> 适用分支：`development`  
> 本文件是开发者内部设计资料，不是面向玩家的地图说明。区域、路线、敌人、奖励、惩罚与触发条件必须以可追溯的数据和场景实现为准；仅存在于文档中的内容不得标记为“已实现”。

## 1. 核心原则：开发者全知，玩家有限知情

开发团队必须能够回答每个区域的全部问题：从哪里进入、有哪些出口、出口如何开启、玩家落在哪里、有哪些敌人与战斗组合、奖励是什么、失败代价是什么、灵视能揭露什么、如何返回，以及它如何影响世界状态和结局。

正式版默认不向玩家展示完整世界地图、全出口列表、隐藏区域坐标、敌人配置表、奖励清单或结局条件。玩家通过地标、视线、环境叙事、声音、敌人活动、物品描述、能力解锁和灵视变化建立自己的心智地图。禁止用无意义迷宫、随机封路或无法辨认的同质走廊制造纯粹困惑。

## 2. 信息分层

| 层级 | 内容 | 玩家是否可见 |
|---|---|---|
| D0 开发者权威档案 | 全拓扑、坐标、门状态、生成点、敌人、奖励、惩罚、条件依赖、结局门槛 | 否 |
| D1 运行时状态 | 已开门、已拾取、Boss 状态、灵视阈值、任务旗标、捷径状态 | 只通过游戏反馈间接体现 |
| P1 玩家感知 | 当前可见地形、已走过的空间、可辨识地标、可听到的威胁 | 是 |
| P2 玩家推断 | 对未探索路径、危险、历史与势力的猜测 | 由玩家自行形成 |
| P3 隐藏真相 | 灵视揭露的通道、被删去的空间、世界与结局真相 | 满足条件后分层揭露 |

地图菜单若未来加入，只能默认呈现玩家已经亲自探索、且角色有理由记住的区域；不得自动显示所有门、隐藏出口、敌人、奖励或未发现区域。是否加入局部草图属于后续实现决策，不影响“完整地图不直接泄露”的原则。

## 3. 现有宏观拓扑基线

- 主区域 A0–A13：14 个，其中 A13 是终局层；主要探索区域 A0–A12 共 13 个。
- 正式隐藏区域 H01–H08：8 个。H09“崖下实验窟”仅为候选，不属于正式地图 canon。
- 当前登记 24 条宏观连接，包含主线、捷径、地下路线、秘密入口和结局入口。
- 当前登记三条宏观环路：L01 边境环路 A1–A2–A3–A4–A1；L02 中层环路 A3–A5–A6–A3；L03 王国深层环路 A4–A8–A9–A4。
- 这些数字只是设计基线，不等于场景实现完成，也不等于游戏已通过实机验收。必须逐条核对拓扑记录、实际场景锚点、交互条件、传送落点与回程可行性。

权威连接表以 `tools/world_map_topology.json` 为准；若文档与 JSON 或场景不一致，先记录差异，不得静默假定其中一方正确。

## 4. 每个区域的强制档案字段

每个 A/H 区域必须逐项建立记录。未知项应标为 `TBD`，不允许编造后伪装成实现事实。

### 4.1 空间与路径
- 区域 ID、名称、叙事职责、解锁阶段、建议玩家能力。
- 入口/出口 ID、所属场景、交互对象、世界坐标、触发半径、门状态。
- 出口目标区域、目标出生点、朝向、垂直偏移、安全落脚空间。
- 单向/双向、是否可返回、是否是捷径、首次开启条件、永久/临时状态。
- 主路、支路、回环、死路、隐藏路、能力门、灵视门和可选绕路。
- 地标、视线走廊、背景轮廓、环境色彩/光源/声音提示。
- 软锁检查、坠落检查、门口重叠、出生点与交互区重叠检查。

### 4.2 敌人与遭遇
- 敌人实例 ID、敌种、数量、坐标/区域、巡逻范围、朝向、警戒距离。
- 遭遇类型：单体教学、混合编队、伏击、追击、远程压制、精英、Boss。
- 激活条件、刷新规则、死亡后状态、跨场景持久化、玩家可绕过方式。
- 敌人组合意图、空间优势/劣势、可利用地形、预期消耗与难度评级。
- 与灵视、任务、世界状态和结局有关的变体。
- 每个战斗必须有可说明的设计目的；不得仅为填充时长堆叠血量或重复敌人。

### 4.3 奖励与信息
- 奖励 ID、类别、精确位置、获取条件、是否可错过、是否可重复领取。
- 类别至少区分：武器/能力、升级材料、治疗/消耗品、货币、关键道具、支线证据、环境叙事、捷径、隐藏区域、结局条件物品。
- 奖励为何放在此处；它是否教会玩家机制、回报风险、改变路线或重解释世界。
- 错过后的替代来源；是否会影响任务/结局；是否会导致不可逆后果。
- 线索的可信度、来源角色/势力、与其他线索的矛盾关系。

### 4.4 惩罚与风险
- 伤害/陷阱/坠落/状态异常/资源消耗/警报/敌人增援/路线关闭。
- 触发条件、预警方式、可反制方式、伤害或损失区间。
- 死亡后的重生点、资源回收规则、敌人重置规则、已开捷径是否保留。
- 惩罚是否可预期、是否可学习、是否与奖励形成公平交换。
- 禁止无预警的一击必杀陷阱，除非存在明确且可读的特殊设计理由。

### 4.5 灵视与隐藏内容
- 灵视数值/状态门槛、触发位置、可见性变化、音画反馈。
- 显现的是实体路径、可交互对象、敌人、物品、文本，还是世界观异象。
- 低灵视时是否仍有公平的环境暗示；高灵视是否改变玩家对旧区域的理解。
- 是否存在绕过阈值的替代线索；是否会误导但不作弊。
- 灵视改变必须有可观察的游戏反馈，不可只在文档里存在。

### 4.6 验收状态
每一条内容只能使用以下状态：
- `DESIGNED`：已设计，尚未实现。
- `IMPLEMENTED_STATIC`：源码/场景中存在，未实机运行。
- `RUNTIME_CHECKED`：已在 Godot 运行时验证。
- `PLAYTESTED`：通过实际游玩检查。
- `ACCEPTED`：完成设计、实现与体验验收。
- `BLOCKED`：存在明确阻塞。
记录证据、测试步骤、版本/提交和已知缺陷。静态检查不得冒充实机验证。

## 5. 玩家信息揭露规范

1. 先让玩家看见地标或路径的迹象，再让其抵达入口，最后才确认连接关系。
2. 捷径要让玩家在打开时重新理解先前走过的空间；开启后必须有明确的声音、动画或场景反馈。
3. 隐藏区域应改变认知、路线、资源或叙事，不应只是多一个空房间。
4. 灵视优先揭露“本来就在这里但无法感知”的空间，而不是像凭空生成普通门。
5. 失败惩罚应提供可学习的信息：敌人布置、地形、音效或视觉预兆都可以成为玩家知识。
6. 不把全部敌人、奖励和路径显示在 HUD 或地图上；用可读的环境线索保持公平。
7. 玩家可以迷失一时，但不能长期因为同质布局、不可读出口或无反馈触发而失去方向感。
8. 可选区域与结局真相应允许玩家错过；错过必须是有意义的取舍，而不是 UI 隐瞒关键操作规则。

## 6. 地图时长与内容密度

目标时长是设计估算，不是实测承诺：单结局首通约 18–24 小时；首轮较完整探索约 22–28 小时；多结局与高完成度约 30–40 小时。需要通过路线重用价值、真实捷径、能力回访、差异化隐藏区域、Boss/精英与叙事线索密度实现，而非单纯增加跑图距离或敌人耐久。

每个区域应记录：
- 盲玩主路径预估、支路探索预估、回访预估、战斗预估、叙事阅读预估。
- 首次通过和后续回访各自新增的内容。
- 预计战斗次数、精英/Boss、补给点、检查点、关键奖励与可错过内容。
- 是否有足够的空间变化与认知变化，避免无意义重复。

时长必须在真实游玩测试后更新，并注明测试者、路线、完成度与死亡次数；没有实测数据时保留“估算”标签。

## 7. 优先核验顺序

1. A2–A4：第一组核心箱式连接，验证边境环路、地下出口、回程出生点和门口交互范围。
2. A5–A8：验证中层环路、钟塔落差、监牢低位补给道与王墓水道是否形成可理解的网络。
3. A9–A12：验证后期枢纽、王室排水道、内城侧门与秘密入口。
4. H01–H08：逐一核验阈值、显现反馈、进入/离开路线和内容回报。
5. A11/H08/A13：专项核验结局条件与共享世界观，尤其不得让单一亲密事件未经论证就成为所有关键结局的硬门槛。

## 8. 完成定义

只有在以下条件全部满足后，地图才可宣称达到开发验收：
- 每个区域均有空间、敌人、奖励、惩罚、灵视与验收档案。
- 所有连接均与实际场景锚点、门逻辑和落点一致。
- 主要区域至少形成可辨认的多路径、回环与捷径网络。
- 所有隐藏区域均有明确的发现逻辑、独特回报和返回方式。
- 无已知软锁、无法返回的意外单向路、门口交互冲突或出生点危险重叠。
- 关键遭遇、奖励与惩罚通过游戏运行和盲玩检查。
- 中文/英文文档同步；未实现与未验证项明确标记。
- 正式玩家界面不会直接泄露开发者档案。

## 9. 当前缺口登记

当前拓扑仅提供宏观连接基线，不能据此宣称所有敌人、奖励、惩罚和触发条件已完成。后续工作必须把每个区域的实际场景内容逐项映射到上述字段，并以场景/源码证据更新状态。实机运行条件不可用时，报告必须明确区分静态审查与运行时验收。
