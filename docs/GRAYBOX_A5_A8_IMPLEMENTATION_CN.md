# A5–A8 主线路径灰盒扩展（中文）

> 分支：development  
> 版本：Graybox Extension 0.1  
> 状态：代码与场景接线已提交；尚未在 Godot 4.6.x 中实机验收。  
> 目的：把 A3 城区东侧主路接到 A5–A8，让玩家能够在同一程序化灰盒框架内走过旧战场、修道院钟塔、监牢与旧王墓，同时保留 A4 下水道支路和 H01 灵视隐藏入口。

## 1. 新增场景

| 区域 | 场景文件 | 位置 ID | 当前承担的职责 |
|---|---|---|---|
| A5 旧战场与边境堡垒 | `scenes/old_battlefield.tscn` | `old_battlefield` | A3 的主线出口；通向修道院 |
| A6 修道院与钟塔 | `scenes/monastery_tower.tscn` | `monastery_tower` | 垂直平台灰盒、R05 无声窗口 |
| A7 监牢与忏悔井 | `scenes/prison_depths.tscn` | `prison_depths` | 下行路线与通向王墓的主路 |

四个场景都复用 `scripts/levels/greybox_world_region.gd`，不为每个区域复制一份控制器。共用 Hero、Camera2D、HUD、NarrativeManager、平台碰撞和 E 键出口交互。

## 1.1 本轮已写入的区域内部路线

- **A5 战场城墙高路：** 在地面战壕平台上方加入断裂城墙路线；可以从地面路线跳上高路，再下降回主路。
- **A6 钟塔侧回廊：** 保留原有逐层上升的主阶梯，新增绕钟塔外墙的侧阳台，形成不同的垂直路径。
- **A7 监牢维护栈道：** 在牢房铁栏上方增加之字形平台路线；地面通路仍然可用。
- **A8 王墓上层墓廊：** 在石棺列上方增加断续的上层路线，能从高处观察被抹除的王名地标。

以上均为真实的 `StaticBody2D` 平台碰撞，不是纯装饰；但跳跃手感、落地容错和交互距离仍待 Godot 实机验证。

## 2. 当前连续路线

~~~text
A1 村庄
  → A2 雾林与旧朝圣路
  → A3 废弃城区
       └─ 中段支路：A4 下水道 / 沉积大厅
            ├─ 调查 R04：古老石构（鸣响目标 36，古神接触至少 1）
            ├─ H01：只有抵达 A4 后才出现的另一侧井门；首次开启仍需灵视
            └─ 从 A4 侧第一次按 E 打开检修闸，第二次按 E 返回 A3 市场
  → A5 旧战场
  → A6 修道院钟塔
       └─ R05：无声窗口（鸣响目标 42）
  → A7 监牢
  → A8 旧王墓
       └─ R06：王名抹除（鸣响目标 55，古神接触至少 2）
~~~

A3 的下水道入口位于中段，城区东侧则继续通往 A5，避免把主线错误地终止在 A4。A4 的回程检修闸由 `opened_sewer_inspection_hatch_from_A4` 保存；旧城区的返回出口使用 `sewer` 出生侧，将玩家放回市场支路附近。

## 3. 新增的叙事 / 异常锚点

### R05 — 无声窗口（A6）

修道院钟塔有一扇无法解释的窗口：它没有远景，窗口阴影却落在一面并不存在的墙上。首次调查会把鸣响提高到至少 42，来源 ID 为 `anomaly_silent_bell_window`。

该调查点位于 A6 的灰盒主路线，不会要求玩家先找到 H05 隐藏区。H05 的正式入口和钟塔回落捷径仍待下一轮制作。

### R06 — 王名抹除（A8）

王墓铭文被主动刮除，刀痕产生在石棺封闭之后。首次调查把鸣响提高到至少 55，并确保古神接触度至少为 2（如果玩家此前已达该值，不重复累加），来源 ID 为 `anomaly_erased_royal_name`。

这条“确保到下限”的规则很重要：玩家即使错过序章可选手术台线索，也不会因此永远无法满足 H06 的接触条件。

## 4. A4 一次性检修闸规则

`scripts/world/interaction_door.gd` 新增了可选字段 `unlock_once_flag_id` 与 `opened_prompt_text`：

1. 其他普通门默认字段为空，行为不变。
2. A4 检修闸第一次互动时，只记录开启标志并更新提示，不触发场景切换。
3. 第二次互动才沿原有出口离开 A4。
4. 开启标志写入已有 `achievement_flags` 并保存；重新进入 A4 时会显示已开启后的提示。
5. A4 仍没有开启 H01 的直接传送捷径：H01 使用同一个持久 `secret_id`，且首次开启仍要求灵视激活和鸣响达标。

## 5. 静态结构 / 场景接线检查

拓扑校验和灰盒接线检查：

~~~bash
python3 tools/validate_world_map_topology.py
python3 tools/validate_graybox_scene_wiring.py
~~~

当前远程源码的独立静态复核确认了：

- A2–A8 / H01 的场景文件均存在，使用共享灰盒控制器；
- A5–A8 的 location ID 已添加到继续游戏恢复映射；
- A3 的主线出口连接 A5；A4 回城区出口有独立的一次性开启状态；
- R01–R06 来源 ID 与设计门槛保持一致；
- H01 两侧入口共享相同的 `H01` 开启状态。

**注意：以上是远程文件与数据的静态接线审查。本环境不能启动 Godot，因此还没有验证 GDScript 在引擎中实际解析、碰撞、跳跃距离、镜头边界、E 键焦点或读档回程。**

## 6. 本阶段验收清单

- [ ] 从 A2 进入 A3；确认 A3 中段的下水道入口与东侧主线出口不会互相遮挡。
- [ ] 进入 A4，第一次按 E 打开检修闸；确认没有直接切图。
- [ ] 再次按 E 返回 A3；确认出生位置在市场中段附近。
- [ ] 通过 A3 东侧进入 A5，再依次走到 A6、A7、A8，并逐一返回前一区。
- [ ] 分别测试 A5 城墙高路、A6 侧回廊、A7 维护栈道和 A8 上层墓廊；确认地面主路线没有被平台封死，失败后仍能回到安全地面。
- [ ] 调查 R05，确认鸣响只记录一次，目标值达到至少 42。
- [ ] 调查 R06，确认鸣响只记录一次，目标值达到至少 55、古神接触度达到至少 2。
- [ ] 退出游戏并继续，恢复位置和 R05/R06 来源状态正确。
- [ ] 在 A4 测试 H01 门：未激活灵视时没有可用提示；激活且达标后可以调查，开门状态保持永久。
- [ ] 确认死亡后回到当前区域入口检查点，不能复活在前一个场景的旧坐标。
