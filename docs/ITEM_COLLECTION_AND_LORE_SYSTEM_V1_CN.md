# 物品收集、查看与碎片化叙事规范 V1.0

> 状态：范围与架构原则已确认；具体 UI、物品列表与徽章效果分阶段实现。
> 适用项目：Nereis-Hero。
> 设计确认：不引入制作素材、采集循环、配方、合成台或独立制作系统。

## 1. 目标

建立一套贯穿探索、战斗成长、存档与碎片化叙事的轻量物品系统。物品既可以有玩法功能，也可以是玩家反复查阅的叙事证据。

物品系统不应扩展为生存或制作玩法；新增物品必须至少服务于探索、战斗、角色成长、任务推进或叙事发现之一。

## 2. 物品类别

| 类别 | 用途 | 当前范围 |
|---|---|---|
| 消耗品 | 恢复生命、临时效果等 | 允许 |
| 关键道具 / 任务物品 | 开启路径、推进事件、交付 NPC | 允许 |
| 记载与线索 | 笔记、信件、铭文、实验记录等，可重复阅读 | 允许 |
| 徽章与纹章 | 后续战斗构筑与角色成长 | 设计纳入，效果分阶段实现 |
| 装备 / 武器相关物品 | 武器、特殊装备或装备解锁凭据 | 按现有战斗系统需要接入 |
| 制作素材 | 采集、合成与配方循环 | **明确不做** |

现有升级逻辑中可能已经存在的 upgrade_materials 是既有代码状态，不代表本设计批准新增制作素材玩法。后续不得因此扩展成采集与合成循环；若它服务于现有武器成长，需在后续审计时单独确认是否保留。

## 3. 物品数据字段

建议所有可收集物品共享稳定 ID 和统一数据契约：

- item_id：稳定且不可随显示名称改变的唯一 ID。
- display_name：本地化显示名。
- category：消耗品、关键道具、记载、徽章 / 纹章等。
- description：物品本身可以合理承载的描述；不承担全知旁白职责。
- effect / effect_data：仅对具有玩法效果的物品填写。
- stackable / max_stack：是否堆叠及数量上限。
- icon：物品图标资源。
- source_id：可选，获取来源或场景对象。
- lore_links：开发侧关联数据，可用于后续事件与证据关联，不直接展示为剧情结论。

玩家获得后应能在物品界面重新查看描述。拾取、阅读、使用、装备应是可区分的状态，避免一次性拾取文本导致线索无法重读。

## 4. 叙事表现规范

- 物品描述只写该物品能支持的事实、痕迹、记载或有限推测。
- 不使用全知视角告诉玩家“你刚刚经历了什么”或直接总结真相。
- 绷带、器械、尸体、磨损、血迹等可以通过外观与短描述叙事，不要求每件物品都配一篇文件。
- 书信和笔记只在世界里确实存在书写载体时使用。
- NPC 对话只表达角色自身知道、相信或误解的内容。
- 系统提示只负责操作反馈；必要的过场演出可以表现关键动作，但不取代环境证据。
- 底部描述面板可以显示玩家主动检查的物品说明；它不是旁白框。

## 5. A0 首批落地范围

第一轮先建立可复用的物品描述展示方式，并清理 A0 中承担旁白职责的底部弹框。

- 手术托盘：描述托盘、血迹、器械或异常残留；避免“主角伸手触碰后某物回应”等全知内心叙述，除非它确实是玩家可见的演出。
- 周边道具：优先考虑绷带、药瓶、手术记录等少量物件，数量以信息差异和探索节奏为准。
- 守卫全部被击败后：通过出口状态、环境变化与 HUD 操作目标反馈出口开放，不弹出总结式旁白。
- 初次进入房间：通过场景构图、主角起身的可玩动作、物品痕迹和 HUD 的必要操作提示建立情境，不使用全知旁白介绍房间。

A0 的 Boss 强制败北与坠崖属于关键动作，可用演出呈现；它不是物品描述应承担的内容。

## 6. 背包 / 图鉴的交互原则

- 玩家可查看已获得物品、数量与描述。
- 记载类物品可反复阅读；已阅读状态只用于整理和后续条件，不替玩家标记“真相”。
- 不强制把每条线索自动拼成答案，不用“剧情完成百分比”代替推理。
- 不把所有检查过的场景线索都自动塞入背包；世界线索与可携带物品可共用数据契约，但保留不同交互语义。
- 徽章 / 纹章未来接入同一物品数据体系，但槽位、搭配限制与效果不在第一轮臆定。
- 存档保存玩家真正持有的物品与阅读状态；场景拾取物是否重生由各自世界状态 / 事件契约控制。

## 7. 排除范围

明确不实现：
- 独立制作素材分类。
- 采集与刷材料循环。
- 合成配方、制作台、材料消耗制作。
- 为填充背包而增加无实际作用的垃圾物品。
- 仅为了显得内容丰富而堆叠大量同质化笔记。

## 8. 当前已提交的第一轮实现（运行时待验收）

- 已新增统一物品目录，当前首批物品为染血的绷带与手术记录残页。
- 已新增世界物品拾取对象、持有数量、拾取点唯一记录与阅读状态，并纳入存档读写及旧存档默认值兼容。
- 游戏 HUD 可通过 I 打开物品界面；玩家可以选择已获得物品并反复查看描述。
- A0 手术所已放置两件可拾取物品；调查手术托盘使用独立描述面板。
- A0 守卫全灭后只更新出口操作目标，不再弹出总结式旁白；A0 室内自动开场旁白与洞外山路自动介绍均已移除。坠崖时的短字幕保留为关键动作演出。
- 目前尚未实现物品使用效果、徽章 / 纹章装备槽与实际战斗效果；这些不属于本轮已完成内容。
- 尚未在 Godot 运行时验证解析、暂停 / 恢复、拾取、读档与 UI 输入焦点；必须由本地运行验收确认。

## 9. 分阶段执行

1. **P0 规范与现状审计：** 对齐既有 world_clue、存档、HUD、交互焦点与已有升级材料逻辑。
2. **P1 描述与收集基础：** 物品数据契约、拾取 / 持有状态、重复查看描述、存档兼容。
3. **P2 A0 叙事改造：** 移除旁白式开场与开门提示，增加少量物品 / 环境证据，确认出口 Boss 与坠崖演出仍独立处理。
4. **P3 徽章 / 纹章：** 依据现有战斗节奏定义槽位和效果，不提前批量制作道具。
5. **P4 验收：** 检查新旧存档、拾取 / 阅读状态、输入焦点、暂停 / 恢复，以及完整 A0 流程。

本规范不表示上述系统已经完成运行时测试。Godot 实际运行验收只能在可运行项目环境中执行后报告。
