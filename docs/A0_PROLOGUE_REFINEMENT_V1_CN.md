# A0 序章体验优化 V1.0

> 状态：第一轮结构改动已提交；Godot 实机验收待执行。
> 范围：A0 教会手术所 + 洞外山路，不改动 A1 村庄及后续地图拓扑。

## 1. 体验目标

A0 不应只是“向右走、击败三名守卫、进入下一张地图”。它要完成四件事：

1. 让玩家通过场景物件而非全知旁白，察觉主角刚经历过手术与拘束。
2. 以可选检查和少量可携带物品鼓励观察，不强迫玩家读完所有线索。
3. 将普通敌人战斗拆成有节奏的教学遭遇，先让玩家学会攻击与识别起手，再逐步施加压力。
4. 让洞外执行者构成明确的剧情必败节点，玩家不能通过跑酷或跳跃跳过该事件；坠崖与失去意识仍然是关键动作演出，而非解释性旁白。

## 2. 已确认的叙事约束

- 主角在 A0 开始时已经接受教会改造。
- A0 保留可玩逃脱序章：室内普通敌人战斗 → 洞外出口执行者 → 强制败北 / 坠崖落水 → 蜜忒救起。
- 中期需通过钩爪或爬墙能力回访悬崖战场，并进入初次无法抵达的隐藏路线。隐藏地图 ID 与空间拓扑仍需单独审计，不在本次擅自锁定 H09。
- 不使用自动开场旁白、击败敌人后的总结旁白或“这是一件剧情线索”一类物品标签。
- 底部描述面板只用于玩家主动检查物品；物品界面只展示名称、数量和描述。
- 不引入制作素材、合成、配方或采集循环。

## 3. 第一轮已提交的改动

### 3.1 室内节奏

- 主角起始位置调整到有实体碰撞的手术台上，台面留有断开的束缚带；初始 HUD 目标调整为观察手术托盘及周边物件、寻找离开路线，不再一开始就把完整通关条件全盘告知。
- 玩家接近第一名守卫时，HUD 才显示一次操作提示，说明攻击与观察起手动作。
- 增加两道实体安全闸门，将三名守卫的长走廊遭遇拆成三个阶段。
- 第一名守卫被击败后打开第一道闸门；第二名守卫被击败后打开第二道闸门；三名守卫全部被击败后才开放出口。
- 闸门开合通过场景变化表达，HUD 只反馈下一步操作目标，不弹出剧情总结。
- 保留手术托盘、绷带和手术记录残页三类不同的观察 / 收集入口；它们分别承载环境痕迹、实物状态与有限的书面记录。

### 3.2 洞外执行者

- 仍然使用对玩家伤害免疫的序章执行者，普通攻击不会将其击败。
- 玩家接近执行者后进入必败遭遇计时；即使玩家持续闪避或不主动进攻，也不会永久卡在该节点。
- 执行者仍在场时，玩家不能通过直接跑向悬崖来跳过必败事件。
- 计时结束或玩家先被击败，都会进入同一条失去意识 / 救援流程。
- 悬崖边加入崩塌石块的视觉提示；必败时通过短暂位移动画将主角带至崖边并落下，字幕表现关键动作，不承担世界观讲解。

## 4. 当前仍未完成的工作

- 主角从手术台起身的开场动作仍需专门设计；当前主要依靠环境与物品建立情境。
- 需要检查主角从手术台离开时的碰撞与站位，以及三名守卫在闸门前后的 AI 行为，确认不会隔门攻击、卡住或在开门后无法寻路。
- 需要实机检查闸门碰撞、跳跃与维护高路是否产生绕过遭遇的路径。
- 洞外的必败计时、悬崖阻挡与转场需要实机调校，避免玩家感到是“突然被系统判负”。
- 当前坠崖已加入短时位移动画，但还没有完整的落水、入水反馈和蜜忒救援演出。
- 悬崖战场与中期隐藏地图之间的连通、回访能力条件和回程路径尚未在本轮实现。
- 手术托盘调查目前仍会调用既有的 `mark_ancient_residue_awakened()`，影响隐藏共鸣 / 区域进度；该旧机制与新版“教会改造”叙事的关系尚未最终确认，本轮保留以免破坏现有隐藏区域条件，后续需单独审议。

## 5. 本地验收清单

### 室内

- [ ] 新游戏进入 A0 时没有自动旁白。
- [ ] 手术托盘可调查，描述只写物件上可见的痕迹。
- [ ] 绷带和手术记录残页可拾取，并可通过物品界面反复查看。
- [ ] 玩家接近第一名守卫时才显示一次操作提示。
- [ ] 第一名守卫死亡后第一道闸门打开，第二道仍保持关闭。
- [ ] 第二名守卫死亡后第二道闸门打开。
- [ ] 玩家无法从维护高路跳过仍关闭的闸门。
- [ ] 三名守卫全部击败后出口开放；没有总结式旁白。
- [ ] 死亡恢复、休息点和交互焦点没有把玩家送入闸门或物件的错误触发区。

### 洞外

- [ ] 洞外没有自动介绍场景的旁白。
- [ ] 执行者免疫伤害，战斗反馈清晰。
- [ ] 试图跑过执行者时，不能直接跳过必败事件。
- [ ] 主动战斗、持续闪避和被执行者击败三种情况最终都进入坠崖 / 救援流程。
- [ ] 救援转场只触发一次，输入锁与交互焦点不会遗留到 A1。
- [ ] A1 村庄正常加载，存档状态和序章完成状态正确。
