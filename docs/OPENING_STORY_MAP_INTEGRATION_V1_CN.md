## 1. 当前地图基准已确认的事实

- **A0：边境手术所与逃脱通道。** 当前地图总账与项目 README 将其定义为可玩的教会外科病房 / 逃脱序章。
- **A1：边境村庄。** 是可反复返回的情感枢纽，承担休息、人物关系与路线分流，不应只作为一次性新手村。
- **A2：雾林、钟墓与旧朝圣路。** 是第一个野外探索区，含雾林地面、钟墓外圈 / 坑底、树冠栈道和旧朝圣高路。
- **A3：废弃城区。** 是第一个大型互通区，并非与 A2 无关的线性关卡。
- **C01：A0 → A1。** 将逃脱路线与村庄连接。
- **C02：A1 → A2。** 当前拓扑将其解锁条件写为 `village_defense_survived`。
- **C24：A1 → A3。** 当前拓扑也将其解锁条件写为 `village_defense_survived`。
- 当前地图设计已经有村庄防卫事件和防卫后开放的周边路线。新版故事可以利用这条因果，但需要检查触发顺序，避免同一事件承担过多互不相关的解锁职责。

以上内容来自当前文档与拓扑数据。本文没有据此断言每个场景都已经通过 Godot 实测。

## 3. 当前最重要的设计冲突

### 3.1 玩家是否亲自游玩教会逃脱？

旧地图与 README 明确记录了 A0 教会手术所 / 逃脱通道的可玩流程；新版叙事强调玩家以失忆状态进入村庄生活。

两者不一定互斥：A0 可以表现主角失忆前后断裂的逃脱经历，并以坠崖落水结束；也可以将 A0 改为非玩家可玩的过去事件，游戏直接从村庄开始。但这属于开局体验的重大决定，不能仅凭文档自动选择。

**当前处理：保留 A0 既有实现，不修改代码；将“玩家首次进入游戏时所在的位置”列为待决定事项。**

### 3.2 村庄防卫与“为村民做事”的关系

新叙事不应让主角只因为剧情要求而接受一个任务。村庄防卫可以是他帮助居民的自然结果，也可以是独立于森林 Boss 的村庄事件。

**当前处理：不把村庄防卫与森林 Boss 合并为同一事件；先检查现有触发逻辑，再决定两者的时间顺序。**

### 3.3 老婆婆对话与地图解锁的关系

新版设计希望休息后，老婆婆告诉主角不同方向可能存在答案；当前地图拓扑则将 C02 和 C24 绑定在村庄防卫事件上。

这并不要求删除旧门锁。老婆婆的对话可以只负责提供方向感和目的，而实际门状态仍由村庄事件决定；也可以在设计确认后增加更细的探索解锁。需要避免的是同一句话既承担世界观解释，又成为多个区域的硬性开锁开关。

**当前处理：老婆婆的线索先作为叙事引导，不新增门锁逻辑，等待完整触发契约。**

## 4. 叙事证据职责：避免重复解释

| 载体 | 建议承担的主要信息 | 不应直接揭示 |
|---|---|---|
| Boss 材料 | 森林危险、当地生态或异常现象的局部证据 | 教会与外神的完整关系 |
| 主角短刃 | 与主角过去有关的工艺、磨损或修复痕迹 | 主角完整身份和全部过去 |
| 高烧 / 梦境片段 | 感官、动作或空间的碎片，形成疑问 | 一段完整的回忆过场或可靠的时间线 |
| 老婆婆的说法 | 有限的地方知识、传闻、个人判断与探索方向 | 全知地图说明、所有区域的完整答案 |
| 朝圣骑士的装备与行为 | 他自己的旅途、信仰和承诺 | 仅为主角服务的剧情解释 |
| 村庄日常物件 | 人物之间真实的生活关系 | 把每个日常细节都变成外神伏笔 |

## 5. 第一轮结论

### 可直接保留

- A1 继续作为可返回的情感枢纽。
- A2 继续作为第一个野外探索区；森林 Boss 放在 A2 是合理候选，但尚未锁定到具体子区域。
- 朝圣骑士的首次帮助应与他的独立旅程相连。
- Boss 材料、短刃、梦境和老婆婆线索承担不同叙事职责。
- 物品与环境提供证据，NPC 提供有限解释；主角不通过台词解释自己。

### 需要先核实，暂不改代码

1. 当前 A0 逃脱序章的真实触发与结尾状态。
2. A1 村庄防卫事件与 C02 / C24 的实际门锁逻辑。
3. A2 当前可玩场景、现有 Boss / 精英遭遇、休息点与返回 A1 的路径。
4. 金正、老婆婆与朝圣骑士当前在场景中的真实挂接点及交互状态。
5. 新版的休养期、Boss 伤病、短刃交易和老婆婆对话应插入哪个已存在的流程节点。

### 下一步执行顺序

- 先检查实际场景与脚本，确认上述五项现状；静态地图文档不能代替代码核验。
- 在不改变地图拓扑的前提下，提出一版事件顺序与状态条件表。
- 将事件顺序与用户确认的开局方向对齐后，再决定是否修改场景流程、NPC 触发或地图门锁。
- 运行可用的静态验证；只有实际启动 Godot 并游玩 / 自动化执行后，才报告运行时验收结果。

**本文件是对照与审计计划，不代表 Boss、交易、梦境或 NPC 触发已经实现。**

## 6. 源码级核对结果（development，2026-10-17）

> 本节是对当前源码的静态阅读结果，不等于 Godot 运行时验收。

### 6.1 实际新游戏入口

- `scripts/core/boot.gd` 的新游戏流程进入 `res://scenes/escape_prologue.tscn`。
- `scenes/escape_prologue.tscn` 使用 `scripts/levels/escape_prologue.gd`。
- A0 当前生成主角、三名实验守卫、手术托盘线索、破损凳子休息点和逃脱出口。
- 调查手术托盘会记录 `escape_surgical_mark` 并调用古神残留相关状态更新。
- 击败三名守卫后出口开放；离开时直接进入村庄场景。当前脚本没有表现“坠崖落水”的明确事件或独立场景。
- 当前开局文案说明主角不记得自己如何来到这里，但玩家先实际游玩的是教会手术所逃脱，而不是先从村庄醒来。

### 6.2 当前村庄流程

- `scenes/village_hub.tscn` 使用 `scripts/levels/village_hub.gd`。
- 村庄进入时生成蜜忒、守门人、共享世界 NPC、若干 POI、休息点与地图出口。
- 当前守门人和共享世界 NPC 的部分条件对白，明确暗示其认识主角、记得主角过去或曾见过主角。这与“村民救起失忆者，但不必认识他的过去”的新版叙事需要逐项核对。
- 当前商人节点 ID 为 `traveling_merchant`，位置约为村庄地图 x=1380。其条件对白包含“七年前来过村庄”“主角的脸已画在教会门上”等信息。它尚未以本文所说的“金正通过 Boss 材料交易交出短刃”方式实现。
- 村庄北门通往 `scenes/ash_forest.tscn`（A2）。首次交互且尚未记录 `village_defense_survived` 时，会进入 `scenes/village_defense_demo.tscn`；防卫完成后记录该状态并返回村庄。此后北门才进入 A2。
- 旧排水路线通往 A3，同样受 `village_defense_survived` 状态控制。

### 6.3 当前森林与 Boss

- `scenes/ash_forest.tscn` 绑定通用 `scripts/levels/greybox_world_region.gd`，区域 ID 为 A2。
- A2 当前的通用遭遇生成包含一只苍白猎犬与一名邪教徒；在已检查的 A2 遭遇分支中，没有发现专门的首个 Boss 配置。
- 当前地图拓扑的 `optional_encounters` 仅列出 A8 王墓守墓者作为显式 Boss 契约，没有列出新版设想中的 A2 森林首 Boss。
- 因此，“森林首 Boss + 朝圣骑士援助 + Boss 材料交易”目前应视为新的叙事 / 玩法设计，不应在文档中宣称已实现。

### 6.4 对新版设计的实际影响

当前代码与新版方向并非全部冲突，但有三个必须先处理的衔接点：

1. **A0 与坠崖：** 可以保留 A0 作为可玩逃脱序章，并把坠崖落水补在逃脱到村庄之间；也可以调整开场入口。当前没有实现坠崖事件。
2. **村民是否认识主角：** 当前部分对白假定村民或商人对主角的过去有所记忆。新版可以保留“有人知道一些东西”的悬疑，但需要逐条审视，不能默认所有旧对白仍符合新版失忆设定。
3. **森林 Boss 与村庄防卫的先后：** 当前是先完成村庄防卫，再开放 A2；新版需要森林 Boss 发生在主角已为村民做事之后。二者可以按“村庄遭遇威胁 → 主角参与防卫 → A2 开放 → 森林 Boss”衔接，但这只是候选顺序，需确认防卫事件是否仍是所需的主要开场事件。

### 6.5 本轮处理范围

本轮只完成源码核对和文档记录，没有修改游戏流程、场景或 NPC 对白。原因是“玩家是否先游玩 A0、坠崖事件放在哪里、哪些村民知道主角过去”会改变开场信息结构，应该先确认叙事方向，再做最小风险实现。


## 7. 新确认：A0 出口 Boss 与中期悬崖回访

用户已明确确认：A0 保留可玩序章，且主角在序章开始时已经接受教会改造。A0 拆为两个战斗区：
- 前段小怪战：帮助玩家熟悉手感与基本战斗。
- 出口 Boss 战：叙事规定主角会被击败，随后坠入悬崖并落入河水，由蜜忒救起。

出口 Boss 的战场还必须在中期通过钩爪或爬墙能力重新到达，连接先前无法探索的悬崖隐藏地图。因此它既是开场失败节点，也是后期地图回访节点。

### 地图数据发现：候选 H09

当前 `tools/world_map_topology.json` 已有一个标为临时候选的 H09「崖下实验窟」，其父区域暂写为 A1，锚点为“村庄山崖（候选位置，待整体地图与剧情复核）”。拓扑审计注释明确指出：H09 是代码中存在的临时候选，不属于已冻结的正式 H01–H08 隐藏地图网络。

所以当前只能得出：**项目里存在一个可能与悬崖有关的 H09 候选，但还不能断定它就是 A0 出口 Boss 战场下方的隐藏地图。** A0 出口战场、坠落河道、村庄所在山崖与 H09 之间的空间关系必须通过场景、地图层级和返回路线一起复核。

### 下一步必须核实

1. A0 现有出口的坐标、地形边界、Boss 战场与可能的坠落路径。
2. A0 → 河流 / 悬崖 → A1 的空间与叙事衔接是否能在现有场景结构中表达。
3. H09 的真实场景与返回出口是否已经存在，是否与 A0 悬崖战场处于同一地理结构。
4. 中期钩爪 / 爬墙能力当前是否已存在于能力契约；若尚未实现，先只记录设计依赖，不虚报已实现。
5. 若 H09 不适配，应重新规划隐藏地图连接，而不是为了复用候选 ID 强行改变用户已确认的悬崖设计。

本节是新的设计基准与静态数据发现，不代表 Boss、坠落或隐藏地图回访已经实现或通过运行时测试。
