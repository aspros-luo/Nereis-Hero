# A5 独立房间与正式区域的集成审计

> 日期：2026-10-22
> 分支：`feature/story-map-progression`
> 范围：只审计 A5；不修改世界级拓扑或 C04/C08/C09 条件。
> 运行时基线：用户报告 `A5 ROOM RUNTIME ACCEPTANCE: PASS | PASS=444 FAIL=0`。

## 1. 关键区别：房间 smoke test 不等于完整区域已组装

当前 A5 有两层实现：

1. **独立测试房间**：`scenes/a5_rooms/a5_r01.tscn` 至 `a5_r22.tscn`。每个场景把 `region_id` 设为 A5，并通过 `room_id` 触发 `_ready_a5_room_test()`，只生成该房间的测试地形、地面、残骸、主角和 UI。
2. **正式 A5 区域**：共享脚本在 `region_id == "A5"` 且 `room_id` 为空时，走正式区域初始化；其地形由 `_configure_platforms()` 中的 A5 分支定义，地面由 `_create_floor()` 中的 A5 分支定义，并由正式出口/共鸣路线逻辑布置跨区连接。

因此，22 个房间通过 `a5_room_runtime_acceptance.gd` 的实例化与碰撞检查，**不能证明这些房间已拼成正式 A5 的可探索空间**。当前正式区域仍是独立的一张长地图；房间 contract 的 `room_binding` 是设计绑定信息，不代表场景自动拼接或出口已经引用这些独立场景。

## 2. 集成风险清单

| 风险 | 证据 / 现状 | 下一步处理 |
|---|---|---|
| 两套地形可能漂移 | 独立房间几何在 `_configure_a5_room_platforms()`；正式区域几何在 `_configure_platforms()` 的 A5 分支 | 明确正式区域的宏观地形与房间职责对应，避免同一房间两份坐标各自演变 |
| 连接绑定尚未被 smoke test 证明 | contract 将 C08 绑定 R01、C04 绑定 R16、C09 绑定 R20；独立测试场景不生成正式跨区出口 | 对正式 A5 的入口/出口位置、出生点、触发区域、承托平台做专项核对 |
| 22 个房间没有自动组成连续地图 | 测试场景是单独加载的，房间尺寸有 1×1、2×1、1×2、2×2、1×3 等 | 先创建房间邻接表和空间装配图，再考虑把它们实例化成连续地图 |
| 共鸣桥属于特殊的垂直/地下路线 | 正式 A5 仍有 x=880..1220 的埋旗共鸣桥相关地形；该合同要求特定共鸣视野和持久开启 | 不可用通用房间拼接覆盖其地面缺口、桥段坐标或持久状态 |
| smoke test 覆盖与玩法覆盖不同 | 用户报告 444 PASS / 0 FAIL；手动清单仍未回填 | 继续保留人工移动、镜头、回环、软锁检查，不把测试数当作玩法质量分 |

## 3. 正式 A5 的宏观路线职责（不改变跨区连接）

- **西侧进入区（R01 职责）**：C08 从 A3 高位进入；先有稳定落脚点，再让玩家读懂战壕与堡垒轮廓。
- **中西段战壕与战线（R02–R04、R07–R09）**：观察、分叉、战斗、休整、藏物各有明确用途；地面主线必须保持可读，支路不得成为无回程的陷阱。
- **高位地标与垂直空间（R05、R10、R13、R15）**：负责观察、路线选择和高墙俯瞰；不是把所有平台串成一条必经蛇形阶梯。
- **地下与低位路线（R06、R17–R19）**：提供下降、维护空间、低位绕行及回接；至少一处应改变实际回程成本，而不只是视觉上的另一条线。
- **绞盘与旧朝圣高路（R16 职责）**：C04 从 A5 侧解锁并双向回连；开门后应明显缩短回程，但不能成为离开 A5 的强制条件。
- **东侧出口（R20 职责）**：C09 进入 A6 上层廊桥；出生点和出口门触发区需避开彼此，不应切图后立刻重复触发。
- **可选探索（R14、R21、R22 职责）**：叙事记录、后期能力软门槛和隐藏观察点。主线可完成而不强迫探索全部隐藏内容。

以上是职责映射，不是已实现的物理邻接关系。真实邻接关系需要在集成实施前依据正式区域坐标逐项确认。

## 4. 下一轮开发方案

### P0 — 先把正式 A5 画成可审计的房间邻接图

新增一个以房间 ID 为节点的集成合同，至少记录：
- 房间尺寸和放置坐标（屏幕单位或世界坐标，二选一并固定）；
- 每个入口/出口所在的墙面、地面高度与承托平台；
- 邻接房间、连接方向、是否单向落差、返回方式；
- C08/C04/C09 的实体出口绑定；
- 共鸣桥、低位路线、能力软门槛和回程捷径的节点关系；
- 每条主线和支路至少一条实际连续的房间路径。

### P1 — 让静态验证器检查集成合同

在不要求先完成美术或敌人的情况下，验证：
- 22 个房间 ID 唯一，坐标不重叠（允许合同明确标记的垂直重叠）；
- 房间边界出口能与相邻房间对应出口对齐；
- C08/C04/C09 绑定指向存在的房间与出口 ID；
- 主线从 R01 职责可到达 R20 职责，且 C04 是可选捷径；
- 隐藏支路可选，不能切断主线；
- 共鸣桥条件与坐标保持既有值。

### P2 — 再决定正式区域的实施方式

优先把正式 A5 拆成可复用的房间场景，或让正式区域和独立测试场景共用同一份几何数据。不要长期维护两份独立坐标；但在完成邻接合同和出口对齐审计之前，不直接替换当前正式区域，以免破坏 C04/C08/C09、死亡恢复或存档流程。

## 5. 明确不做的事

- 不复制《空洞骑士》的具体地图形状或房间。
- 不在本轮加入敌人数量来填满空间。
- 不更改世界级 A0–A13、C01–C24 拓扑。
- 不降低埋旗共鸣桥的条件，不把可选捷径改成强制主线。
- 不声称正式 A5 已通过人工试玩；当前确认的是用户提供的独立房间运行时 smoke test 结果。
