# Nereis-Hero 关卡设计规则（空洞骑士式探索原则）

> 本文只提炼关卡设计原则，不复制《空洞骑士》的具体房间、区域布局、敌人或美术设计。
> 适用范围：全局地图规划与 A5「旧战场与边境堡垒」房间审计。灰盒阶段也必须满足空间职责和路线逻辑；美术、敌人与机关可以暂用占位定义。

## 1. 世界结构与多路径可达

- 世界应由枢纽、主路线、可选支线、回连与少量有明确目的的单入口支线构成，而非线性关卡串。
- “任意两个区域至少有两条路径可达”按**重要区域之间的网络冗余**验收：重要区域对之间应存在至少两条边不重复的可行路线；不要求每一对区域直接相连，也不强制每条可选支线都有第二出口。
- 枢纽需连接多个区域，且在推进过程中会反复成为分流、汇流或返回节点。
- 每条地图连线都必须映射到实际可走通的场景路线；拓扑数据中的边不能代替实机连通。
- 单入口支线仅在承担奖励、观察、挑战、伏笔或有意设置的单向推进时允许；必须记录其目的和退出/恢复方式。
- 验收：列出区域图的枢纽、关键区域对、替代路径、回环、单向边和死路；分别检查解锁前后可达性。

## 2. 区域身份：三项缺一不可

每个区域都必须明确且可辨识地定义以下三项：

1. **配色/视觉语言**：主色、明暗、轮廓、材质或环境视觉符号。
2. **敌人构成**：敌人类别组合及其与空间的互动方式；灰盒阶段可以记录计划，不要求先实现敌人。
3. **环境或移动机制**：至少一种影响路线选择、战斗、跳跃、停留或探索的机制。

- 三项必须共同形成区域身份，不能只通过换背景色区分区域。
- 机制不能只是装饰；它必须实际影响玩家决策。
- 验收：每个区域有一张身份卡，列出三项和可观察证据；相邻区域至少在轮廓、机制或敌人空间行为上有清楚差异。

## 3. 房间职责与初始占比

按房间的**主要功能**归入一个类别，兼具其他用途的功能写在备注中，避免重复计数。

| 主要类型 | 初始目标占比 |
|---|---:|
| 通道 / 过渡 | 40% |
| 战斗 | 20% |
| 平台挑战 | 15% |
| 隐藏 / 奖励 | 10% |
| 安全 / 休息 | 5% |
| 地标 / 叙事 | 10% |

- 以上为规划起点，可根据区域身份和实际试玩结果调整，不是硬性配额。
- 允许存在不放敌人、不放奖励的“空房间”，但每个空房间必须明确标注至少一个目的：**氛围、伏笔、节奏缓冲、远景**。
- 不允许仅以“连接两个门”为理由保留大量重复房间；通道也应通过转向、分层、视线、路线选择或节奏承担明确职责。
- 验收：统计区域内各主要类型占比；偏离目标时说明设计理由；没有明确目的的空房间应合并或重做。

## 4. 房间尺寸与节奏

- 大空间与窄通道应交替出现；连续空间不能长期保持相同宽高比例和同一种路线决策。
- 大空间至少承担多路线选择、战斗机动、远景观察或地标定位中的一项；否则应考虑缩小。
- 窄通道应承担压迫、转向、遮蔽、节奏收束或连接功能，不应只是把普通房间压窄。
- 竖井必须承担垂直连接、上下层探索、风险选择或捷径中的至少一项；需要有可辨认的落脚点和路线信息，避免重复的无信息平台。
- 每个房间登记尺寸、入口/出口方向、高差、主要功能、可见目标和回程方式。
- 验收：连续三间以上若主要功能、空间轮廓和路线决策都相同，列为重复候选并重新审查。

## 5. 门槛与可见不可达目标

- **软门槛优先**：先让玩家看到暂时够不到的目标、通路或奖励；随后在另一条路线获得能力，再返回解锁。
- 每个软门槛至少记录：首次可见位置、视觉线索、暂时无法通过的原因、能力来源、返回路线、解锁后的反馈。
- 同一关键能力应在多个地点产生用途，避免能力只对应一个孤立门。
- **硬门槛**（钥匙、Boss、强制进程条件）仅用于关键节点；必须有清晰条件、合理提示与通过后的反馈。
- 障碍外观应帮助玩家推断行动方式；不同能力对应的障碍不能全部长得一样。
- 验收：玩家在第一次遇到门槛时，至少能理解“这里有东西/这条路尚未开放”，并能在获得能力后辨认和找回入口；不要求提前知道完整答案。

## 6. 捷径、回连与安全点

- 捷径应从远端开启，例如拉杆、破墙或单向门；开启后必须改变实际行进路径或显著降低回程成本。
- 捷径优先接回休息点、枢纽、主路线或玩家已熟悉的区域。
- 长距离或高风险探索之后，应提供合理的回连机会；单向落差必须明确其推进意图、后续出口与恢复方式。
- 休息点优先放在难段之后或 Boss 之前；不能让连续高风险挑战之间的安全点间隔过长。
- 验收：比较捷径解锁前后的实际路线、回程房间数、危险遭遇和玩家操作；若没有实质变化，捷径设计不合格。

## 7. 无任务指示的玩家引导

- 主路线通过地标、视线、光源、建筑轮廓、环境叙事或 NPC 暗示进行引导，不依赖任务箭头。
- 交叉口的出口应有可感知差异，例如不同地形轮廓、远景目标、声音/光照或环境线索。
- “看得见但暂时不可达”的目标应留下可记忆的视觉特征，返回时可以辨认。
- 环境暗示必须与真实可走路线一致；若引导玩家走向死路，必须提供有意义的发现、奖励或信息。
- 新机制首次出现时，先提供可观察或低风险试用机会，再组合进高风险挑战。
- 验收：在不打开地图、不读任务说明的情况下，从入口、交叉口和主要高点检查玩家是否能推断一个合理的下一步方向；不要求每次只有唯一正确方向。

## 8. 房间重复与验收标准

逐房间检查以下项目：

- 房间职责能否用一句话清晰说明。
- 它与相邻房间是否至少在路线结构、空间轮廓、机制、观察目标或节奏中的一项上明显不同。
- 空房间是否明确标记氛围、伏笔、节奏缓冲或远景目的。
- 入口、出口、主要路线、可选支路和返回方式是否明确。
- 隐藏内容是否有可推断线索；软门槛是否有可回访路径。
- 连接、跳跃与落差是否经实际操作验证；静态几何或图论可达性不等于实机可玩。
- 如果两个房间的尺寸、平台布局、路线决策和主要功能均相近，必须重新设计其中至少一个，不能只改平台坐标或数量。

## 9. A5 当前执行边界

- 本规则先用于审查 A5 的全部 22 个房间，不代表只审查之前重点调整过的 R05、R06、R13、R16、R17。
- 不扩展到其他区域，直至 A5 的空间差异与路线职责完成审计并获得确认。
- 保留现有世界级连接契约，尤其 C04、C08、C09 及 A5 埋藏旗帜共鸣路线；如需变更，必须先记录影响并获得明确确认。
- 当前灰盒阶段不要求立刻制作正式美术或填入敌人，但区域身份中的敌人构成必须先作为设计约束登记。
- 验收顺序：房间职责审计 → 重复房间判定 → 房间空间与连接修订 → 静态检查 → Godot 运行时检查 → 人工跳跃、摄像机、回连和软锁验收。
