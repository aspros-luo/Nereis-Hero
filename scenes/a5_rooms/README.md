## 集成边界审计

独立房间的运行时 smoke test 通过，不代表这些场景已自动拼成正式 A5 地图。正式区域仍由共享脚本中独立的 A5 地形分支生成；C04/C08/C09 的实体出口也需单独核对。集成风险与下一步合同设计见 [A5 独立房间与正式区域的集成审计](../../tools/A5_ROOM_INTEGRATION_AUDIT_CN.md)。在完成房间邻接图与出口对齐验证前，不要把独立测试房间视为正式地图已装配完成。

## 当前灰盒地形实现

- **地面不是统一模板**：不同房间分别定义实际碰撞地面的分段与缺口；缺口处不生成地面碰撞，并由对应平台跨越。
- **平台按房间独立设计**：横向战壕、交叉火力区、信号塔、绞盘竖井、地下维护层和隐秘观察室采用不同的平台数量与高差。
- **残骸是实体障碍**：每间房间都有单独布置的矩形残骸，视觉形状与 `StaticBody2D / CollisionShape2D` 碰撞一致，主要高度控制在可跳越范围。
- **R06 从高位开始验收**：出生点放在塌陷坡道上端，方便检查下降路线；其余房间默认从地面入口开始检查。
- **当前限制**：这是无美术资源阶段的灰盒，尚未添加敌人、机关动画、拾取物与正式区域出口。脚本静态验收通过不等于 Godot 实机跳跃验收通过。

## Godot 运行时验收

在仓库根目录执行静态检查后，再用 Godot 4.6.x 运行全部 22 个独立房间：

```bash
python3 tools/validate_a5_room_scenes.py
"$HOME/Downloads/Godot.app/Contents/MacOS/Godot" --headless --path . --script tools/a5_room_runtime_acceptance.gd
```

运行时脚本会逐一加载、实例化并释放房间，检查实际生成的平台碰撞体、残骸碰撞体、地面分段与缺口、Hero 碰撞形状、摄像机边界和出生位置。完整报告写入 Godot 的用户数据目录下的 `a5_room_runtime_acceptance_report.json`。如果 Godot 不在上述路径，请将命令替换为实际可执行文件路径。

这属于运行时 smoke test；它不会代替人工试玩，也不会自动证明所有跳跃路线都有良好手感。

## 静态检查

在仓库根目录运行：

```bash
python3 tools/validate_a5_room_scenes.py
```

该检查验证 22 个场景文件、房间 ID 与尺寸，并检查每间房的平台范围、路线相邻步幅、实体残骸边界和真实地面缺口。它是静态几何检查，不代替 Godot 解析、碰撞物理和人工游玩验收。

## 建议验收顺序

1. R01：出生位置、地面与基础跳跃。
2. R05、R06、R13、R16、R17：高差、垂直镜头、上升/下降路线。
3. R02、R03、R04、R08、R10、R11、R12、R15、R18、R20、R21：长横向路线、平台间距与分支。
4. R07、R09、R14、R19、R22：小房间落脚空间与探索支路。
